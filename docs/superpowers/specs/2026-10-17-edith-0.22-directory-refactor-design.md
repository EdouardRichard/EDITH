## 1. 背景与现状证据

### 1.1 模块与目录

`settings.gradle.kts` 收录 **24 个模块**，全部平铺在仓库根目录，只有 4 个工具模块在 `tools/` 下：

- 交付链路 15 个：`core-contracts`、`plugin-api`、`host-runtime`、`agent-runtime`、`device-control`（0.25 新增）、`model-runtime`、`storage-runtime`、`audio-runtime`、`audio-android`、`transport-rokid`、`output-runtime`、`plugins-smart`、`plugins-diagnostic`、`phone-app`、`glasses-app`。
- 非交付 9 个：`test-support`、`plugins-interview`、`glasses-audio-probe`、`glasses-sdk-coexistence-probe`、`phone-accessibility-probe`、`tools:p2-text-probe`、`tools:p3-toolcall-probe`、`tools:p3-agent-probe`、`tools:p3-eval-trigger`。

另有两处不是模块、但参与构建或作为仪器的目录：

- `probes/p0/vendor`：CXR AAR，被 `settings.gradle.kts` 的 ivy 仓库直接引用；整个 `probes/p0/vendor/` 已 gitignored。`probes/` 下唯一入库文件是 `probes/p0/README.md`。
- `tools/shizuku-shell-probe/`：未入库、未加入 `settings.gradle.kts` 的本地 WIP 模块。

源码规模：交付模块 **613** 个 `.kt/.java` 文件，探针/工具 **60** 个，合计 **673**；其中 `phone-app` **205** 个。

### 1.2 包名

- 交付代码的根包是 `edith.*`，但分布不一致：`edith.contracts`、`edith.plugin`、`edith.host`、`edith.agent`、`edith.model`、`edith.storage`、`edith.audio`、`edith.audio.android`、`edith.output`、`edith.rokid`、`edith.plugins.smart.*`、`edith.phone.*`、`edith.glasses`、`edith.testsupport`。
- `phone-app` 的根包 `edith.phone` 下**平铺 42 个文件**（含 Cxr*、Smart*、Session*、Audio*、Plugin*、Debug 之外的仪器等），是“看不出属于哪一块”的主要来源。
- `phone-app` 同时混入 **vendored `com.laya`（7 个文件）**，与 `edith.phone.laya` 并列。
- `edith.rokid` 被用作传输层包名，与品牌/产品名重复。
- `core-contracts` 的测试文件 `ModuleSmokeTest.kt` 声明在根包 `edith`，没有任何子域。

### 1.3 会被改名牵连的硬引用

以下都是**代码事实**，不是推断；重构时必须同步修改，否则编译或运行会断：

| 位置 | 现状 | 影响 |
|---|---|---|
| `phone-app/.../CxrGlassesTarget.kt` | `GLASSES_PACKAGE_NAME = "edith.glasses"`、`GLASSES_ACTIVITY_NAME = "edith.glasses.GlassesActivity"` | 眼镜端改名后必须同步；两端必须同一次构建（D63） |
| `phone-app/build.gradle.kts` | `namespace`、`applicationId` 均为 `edith.phone`；`testInstrumentationRunner = "edith.phone.PhoneTestRunner"` | 应用身份与测试入口 |
| `glasses-app/build.gradle.kts` | `namespace`、`applicationId` 均为 `edith.glasses` | 同上 |
| `phone-app/proguard-rules.pro` | `-keep class edith.phone.**`、`-keep class edith.phone.laya.**` | R8 反射/保留规则 |
| `phone-app/src/main/aidl/edith/phone/actions/IRemoteShell.aidl` | `package edith.phone.actions;` | Shizuku UserService 的 binder 契约 |
| `phone-app/src/main/AndroidManifest.xml` | `.EdithApplication`、`.MainActivity`、`.SessionService`、`.ConfirmationActionReceiver`、`.a11y.EdithAccessibilityService`、`.NotificationCategoryService` | 组件名变化，设备需重新授权无障碍/通知/Shizuku |

| `phone-app/src/main/res/xml/edith_accessibility_config.xml` | 无障碍服务配置 | 组件名变化后设备端设置需重建 |
| `.gitignore` | 为 `Audio/` 规则写的 `!audio-runtime/.../edith/audio/` 例外 | 包改名后必须改为新路径，否则 Windows 大小写不敏感会再次吞掉 `audio` 包（D45 已踩过） |
| `tools/`、`docs/`、`AGENTS.md` | 大量 `edith.*` 包名、模块路径、adb 命令 | 文档与脚本同步 |

另有一批字符串**不是包名**、重构中必须逐字节保留：`edith.START`/`edith.STOP`/`edith.PAUSE`/`edith.RESUME`、`edith.CONFIRM_*`、`edith.DEBUG_*`、`edith.phone.SHOW_CONFIRMATION`、通知 channel `edith.session`、系统属性键 `edith.cxr.*`、唤醒词 `edith`、`/sdcard/EDITH/skills`。

### 1.4 工作树基线

- 当前分支 `main` 比 `origin/main` 多 523 个提交；未 push、未打 tag。
- 工作树有 **10 处先于本任务的 `phone-accessibility-probe` 改动**（2 处修改、8 处未跟踪），以及未跟踪的 `gradlew`/`gradle/wrapper/`。它们不属于本次重构，**不得纳入本次提交**；移动探针目录时随目录走，但保持原有的已修改/未跟踪状态。

## 2. 已确认的决策（业主 2026-10-17）

| 编号 | 决策 | 备选与理由 |
|---|---|---|
| R1 | **交付代码统一 `com.sheen.rokid.*`；探针/工具保留 `edith.*`** | 产品代码统一品牌根；探针是测量仪器，被 D95、脚本、证据写死，改名对产品零收益 |
| R2 | **两端 `applicationId` 同步改为 `com.sheen.rokid.phone` / `com.sheen.rokid.glasses`** | 应用身份与包名一致；接受一次性卸载重装与重新授权 |
| R3 | **不改 Gradle 模块边界** | 不拆分 `phone-app`、不合并模块；只做目录、模块名、包结构。构建图不变，功能等价性可证明 |
| R4 | **顶层目录采用“两端 + 一个公共依赖目录”** | `phone-app/`、`glasses-app/`、`common/`、`tools/`、`third_party/`、`docs/` |
| R5 | **手机侧运行时归属 `phone-app/`，两端共用归属 `common/`** | 判断标准：两端 `build.gradle.kts` 都直接依赖才进 `common/` |
| R6 | **插件核心与宿主胶水用 `.host` 分包** | 避免同一个包横跨两个 Gradle 模块（split package） |

> 实施时这 6 条登记进 `docs/project/DECISIONS.md`，编号按写入时的最新 D 号顺延。

## 3. 目标与非目标

### 3.1 目标

1. 目录能回答“这是手机端、眼镜端、公共依赖，还是仪器”。
2. 包名能回答“这是哪个领域”，根包下不再有平铺文件。
3. 规则写进 `AGENTS.md`，后续新增代码不会再退化成平铺。
4. 重构只动路径与名字，**功能行为逐字节不变**。

### 3.2 非目标（明确不做）

- 不修依赖倒置：`host-runtime` 反向依赖 `plugins-*` 的现状保留，只记录。
- 不修 source set 问题：`ScriptedModelWire` 仍在 main source set。
- 不做 D121 的工具面收敛；不重跑 F4、M2、AC-13/16；不改变任何验收判词。
- 不改 Intent action、通知 channel、系统属性键、唤醒词、`/sdcard/EDITH` 路径。
- 不重命名探针包名、不改 `com.laya` vendored 代码。
- 不重写 `docs/project/evidence/` 里的证据文件（只在别处补映射）。
- 不 push、不打 tag。

## 7. 固化到 `AGENTS.md` 的规则

在 `AGENTS.md` 新增一节“目录、模块与包命名（0.22 起）”，正文如下：

1. **顶层只允许六个目录**：`phone-app/`、`glasses-app/`、`common/`、`tools/`、`third_party/`、`docs/`。新增顶层目录必须先改本节并获业主批准。
2. **可部署物在根、以 `-app` 结尾**：模块名与 Gradle 路径同名（`:phone-app:app`、`:glasses-app:app`），`applicationId = com.sheen.rokid.<end>`。
3. **库模块只能放在四个位置**：`phone-app/`（手机专属）、`glasses-app/`（眼镜专属）、`common/`（两端共用）、`tools/`（仪器）。判断“共用”的标准是两端 `build.gradle.kts` 都直接依赖；只有一端使用就不得进 `common/`。
4. **包名规则**：`com.sheen.rokid.<domain>[.<subdomain>]`，全小写、无下划线/连字符；根包不得直接放文件，每个文件必须落在领域包；模块与包不要求同名，但必须在模块清单里登记。
5. **依赖方向**：`apps → 本端模块 → common`；`common/contracts` 不依赖任何实现；`tools → 产品模块` 单向，产品模块不得依赖工具与 `test-support` 的生产代码。
6. **插件边界**：`plugin-smart-helper` 不得 import `com.sheen.rokid.phone.*`（只允许 `phone-app` 的 `plugin.smarthelper.host` 包跨边界）；眼镜端不得依赖 `phone-app/`。
7. **测试包镜像主包**；新增文件必须进已有领域包，或先更新本节再加包。
8. **例外登记**：`com.laya`（vendored）、探针保留 `edith.*`、`third_party/cxr`（原 `probes/p0/vendor`，gitignored）。
9. **移动纪律**：只允许 `git mv`；每次移动后全量构建 + 全量测试；不改 Intent action、资源 id、通知 channel id、系统属性键、唤醒词等运行期协议。
10. **文档同步**：代码路径变化必须在同一提交更新 `README.md`、`AGENTS.md`、基线规格与验收链接；`docs/project/evidence/` 不可改写，旧路径只在迁移映射里出现。

## 10. 风险与回滚

| `.gitignore` audio 例外 | Windows 下 `audio` 包被忽略，模块变 NO-SOURCE | 改为新包路径并验证 `git check-ignore` |
