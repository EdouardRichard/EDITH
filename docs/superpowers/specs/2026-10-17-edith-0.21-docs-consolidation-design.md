# EDITH 0.21 文档基线重构规格

- **日期**：2026-10-17
- **锚点**：EDITH 0.21（代码/工具基线 `f0eab5f`；0.21 结项 `edith-0.21-closed-20261017-01`）
- **状态**：已执行（过程记录，不是当前架构；当前架构见 `2026-10-17-edith-0.21-baseline-architecture-design.md`）
- **范围**：仅文档与临时文件；**零代码改动**
- **上游裁决**：本文 §2 的五条业主裁决（2026-10-17 本会话）

---

## 1. 问题

EDITH 经过 P0–P5、0.2、0.21 多个版本迭代，文档采用"只追加、不退役"的写法，已经影响 Agent 正确取用：

1. **同一主题有多份"当前"**：`PROJECT_STATE.md`（454 KB）、`HANDOFF.md`（455 KB）、`ACCEPTANCE.md`（380 KB）、`CONTRACTS.md`（102 KB）都由大量 `Current Increment` / `History Entry` 段落堆叠而成，新会话必须读完整份才能确定哪段有效。
2. **决策登记不完整且新旧混排**：`DECISIONS.md`（149 KB）只有 D01–D59 在表格中，D60–D121 是追加章节；`D02`、`D60 §1`、旧上传同意模型等已被取代，但仍与生效决策并列。
3. **实施前的设计仍被当作当前架构**：`2026-10-05-edith-blueprint.md` 与 `2026-10-13-edith-0.2-design.md` 描述的是旧范围/旧接口；0.21 的 71 KB 设计规格也早于 D105、D110、D116、D120 等收口裁决。
4. **文档数量失控**：216 份已跟踪文档、157 份证据、38 份 spec/plan；另有 1,727 份 SDD 账本文件（71 MB）。
5. **临时数据失控**：`.local/` 7.8 GB、`probes/` 1.5 GB、根目录堆转储 4.0 GB、`.model-cache/` 647 MB。

已经发生的事实：Agent 在实现过程中取到旧决策（业主 2026-10-17 观察）。本规格的目标是消除这个条件。

## 3. 目标

### 3.1 成功标准

一个**没有历史上下文**的 Agent，按 `AGENTS.md` 的阅读顺序只读 5 份文件，就能回答：

- 当前版本是什么、哪些通过、哪些失败、哪些未测；
- 系统由哪些模块构成、边界在哪、端到端链路怎么走；
- 哪些决策仍然生效、为什么、影响哪些契约；
- 对外承诺了哪些公共契约；
- 下一步该做什么、什么不能做。

且不需要读任何 0.21 之前的文档，也不会读到已被取代的决策。

### 3.2 非目标

- 不修改任何代码、测试、构建脚本、Manifest、资源文件。
- 不修改 `plugin-api` / `core-contracts` 的公开面。
- 不重新测量 0.21 的 F4/M2/AC 结果；不把 `NotMeasured` 升级为通过。
- 不重写历史证据的测量内容（证据只做保留/删除，不改数字）。
- 不提交、不 push、不合并、不打 tag（提交授权不继承）。

## 4. 目标文档系统

### 4.1 目录

```
docs/
├── superpowers/
│   ├── specs/
│   │   └── 2026-10-17-edith-0.21-baseline-architecture-design.md   # 唯一权威架构基线
│   └── plans/                                                       # 下版本新建；0.21 旧计划删除
├── project/                                                         # 项目扩展（Superpowers 未定义）
│   ├── STATUS.md                     # 状态 + 交接（每次 checkpoint 覆写）
│   ├── DECISIONS.md                  # 活动决策登记（仅生效/部分生效）
│   ├── CONTRACTS.md                  # 当前公共契约索引
│   ├── ACCEPTANCE.md                 # 当前验收矩阵
│   └── evidence/                     # 仅保留被当前验收行引用的证据
└── skills/                           # 删除；规则并入 AGENTS.md / 决策登记
```

删除后 `docs/superpowers/plans/` 可以为空（git 不跟踪空目录）；下版本写计划时再建。

### 4.2 权威顺序（写入 `AGENTS.md`）

1. `docs/project/STATUS.md` — 现在在哪、什么没过、下一步、交接注意
2. `docs/superpowers/specs/2026-10-17-edith-0.21-baseline-architecture-design.md` — 架构与边界
3. `docs/project/DECISIONS.md` — 仍生效的裁决与理由
4. `docs/project/CONTRACTS.md` — 对外承诺
5. `docs/project/ACCEPTANCE.md` — 已证明/未证明
6. 当前计划（下版本才有；0.21 无）

### 4.3 权威规则

- 同一主题只允许一处权威。权威文档之间只做链接，不复制正文。
- `docs/project/evidence/` 是证据，不是规范；证据内容不可改写。
- `.superpowers/sdd/` 是过程账本，不是权威；关闭的账本在必要裁决持久化后删除。
- 旧版本内容只存在于 git 历史，不再进入阅读路径。

## 5. 各文档规格

### 5.1 基线架构规格

路径：`docs/superpowers/specs/2026-10-17-edith-0.21-baseline-architecture-design.md`

内容必须覆盖（按此顺序）：

1. 版本、范围与判定（单插件；P4 按 D57 搁置；0.21 已闭环但**未完全通过**）
2. 术语与证据边界（`Confirmed/Accepted/Proposed/Superseded`；实测 vs 官方文档 vs 推断）
3. 模块地图与职责：`core-contracts`、`plugin-api`、`host-runtime`、`agent-runtime`、`audio-runtime`、`audio-android`、`storage-runtime`、`model-runtime`、`output-runtime`、`transport-rokid`、`plugins-smart`、`plugins-diagnostic`、`phone-app`、`glasses-app`，以及探针/工具模块（明确标注"非交付模块"）
4. 端到端链路：会话启动 → 采音/VAD/ASR → 唤醒与主动辅助 → AgentLoop → 请求装配 → 记忆注入 → 摘要/压缩 → SKILL 两层注入与生命周期 → 工具面/确认 → 输出/上屏/TTS
5. App 与插件职责边界、公共契约面（指向 `CONTRACTS.md`）
6. 模型与协议：模型档案、适配器、流式、预算与三刀裁剪顺序、工具往返
7. 数据与存储：会话存储（按路由）、记忆（原话 + 规范形）、加密命名空间、不落盘清单
8. 安全与隐私：D53 上传口径、D33/D36、日志只记计数/id、无障碍与 Shizuku 边界
9. 设备与测量方法：K40 验收（D37/D46/D65）、官方 demo 保真（D41）、测量预登记（D114）、debug-only 接缝
10. 当前验收状态摘要（指向 `ACCEPTANCE.md`）：M2 0/10、AC-13/16 设备失败、AC-14 降级、AC-15 未测、R-8 工具收缩
11. 模块/关键文件索引
12. 决策映射：每个架构段落对应哪些 D 号
13. 附录 A：被取代的旧架构口径及原因（D60→D73、旧上传同意模型、K70 目标等），只保留"为什么改、改成什么"
14. 修订记录

规格里的每条架构断言必须能落到以下之一：代码文件/行、测试、保留的证据、生效决策。不得复述实施前设计中的未落地内容。

### 5.2 `DECISIONS.md`：活动决策登记

格式：按领域分组（范围/设备、架构与契约、请求与会话、记忆与 SKILL、工具面、安全与隐私、测量与验收），每组一张表：

| ID | 日期 | 规则 | 理由与边界 | 影响 | 状态 |
|---|---|---|---|---|---|

- `状态` 只有 `Active` 与 `Partially superseded`；被部分取代的必须写清"第 N 条由 Dxxx 取代"。
- 每条压缩为可执行规则，不保留实施流水账；实施细节归代码/测试/证据。
- 保留/删除判定：
  - **保留**：被代码或测试引用；约束当前架构、行为、安全、设备、范围；被保留验收行引用；关闭了代码里仍可见的问题。
  - **部分保留**：整条仍有约束力，但个别子条被新决策取代（在条目内逐条标注）。
  - **删除**：纯 checkpoint/本地实施裁决；被完整取代且无代码/验收依赖；一次性测量裁定且结论已进入 `ACCEPTANCE.md`；旧版本范围已关闭。
- 编号不重排、不复用。删除项在处置表中逐条给出理由（处置表是审计产物，不入库）。
- **底线**：代码/测试引用的 ID（D33、D35、D41、D46、D47、D49、D53、D57、D60、D73）必须存在且与代码一致。

### 5.3 `CONTRACTS.md`：当前公共契约索引

- 公共 API 版本（`1`）与兼容性政策。
- `core-contracts`（8 个文件）与 `plugin-api`（21 个文件）的类型/接口清单，按"类型 → 用途 → 消费者"组织。
- 宿主服务、能力声明、生命周期回调。
- 线缆协议：CXR 自定义命令、`Caps` 载荷、hint codec、音频上行。
- 破坏性变更的**当前结果**（如 D61 的 `SystemOneService` / `LayaInferenceEngine` 重塑），不保留逐次增量流水。
- debug-only 测量接缝（Phase 7 的三个接收器与 internal 访问器），明确"不是公共 API"。
- 删除所有 `Current Increment`、历史 checkpoint 段落。

### 5.4 `ACCEPTANCE.md`：当前验收矩阵

- 行集合：0.21 的 AC-1…AC-18、F4、M2，加上仍具约束力的旧行（B1–B11 等，按 0.21 规格 R3 逐条保持）。
- 旧行是否保留由处置表逐行判定：仍约束当前代码的保留，已随版本关闭且无约束力的删除；删除行不改变已记录的 0.21 判词。
- 每行：判据 / 状态（`Verified` / `NotMeasured` / `Failed`）/ 证据链接 / 口径备注。
- 版本级结论：**0.21 范围内未完全通过**；M2 0/10 是有效失败，AC-13/16 设备行为失败；任何 `NotMeasured` 不得读成通过。
- JVM 基线：310 套件 / 2671 tests / 0 failures / 0 errors / 0 skipped（project-only，`--rerun-tasks`），注明"本次文档会话未重跑"。
- 删除旧 increment、旧版本结项段、已关闭版本的重复行。

### 5.5 `STATUS.md`：状态 + 交接

固定小节，每次 checkpoint 覆写：

1. 当前版本/分支/HEAD/checkpoint
2. 0.21 判定（一句话 + 失败项）
3. 未通过项（M2、AC-13/16、AC-14、AC-15、R-8）
4. 下一版本范围（应用工具重构；M2/AC-13/16 复测；F4 不重跑）
5. 硬约束（K40、官方 demo 保真、隐私与上传、未 push/合并）
6. 本次交接注意（环境、设备、未关闭问题）
7. 下一动作
8. 阅读顺序（指向 §4.2）

不得追加历史段落；历史由 git 保存。

### 5.6 `AGENTS.md` / `README.md`

- 只改：文档入口、阅读顺序、版本口径、已失效路径引用。
- 保留：官方 demo 保真、设备无人值守、a11yprobe、隐私、未授权不 push/合并、构建/安装纪律等全部操作铁律。
- 不引用将被删除的文档（蓝图、旧证据、旧计划）。
- 不新增与代码实现相冲突的规则。

## 6. 证据与文档删除规则

### 6.1 删除前必须完成"三类抽取"

对每一份将删除的文档：

1. **仍生效的决策** → 进入活动登记或确认已被登记覆盖。
2. **仍未关闭的问题/裁决** → 进入 `STATUS.md` 的"交接注意"或明确记为已关闭。
3. **被当前验收行引用的证据** → 保留证据文件，或把该验收行降为 `NotMeasured`（不得虚构证据）。

已实测的检查点：`2026-10-14-pending-rulings.md` 的 I2/I3/B11 必须先核对是否已由 D62/D63 等关闭；`2026-10-13-systemone-interface-change-proposal.md` 必须核对是否已由 D61 落地。

### 6.2 证据保留

- 只保留被保留验收行引用的 evidence；删除其余。
- 证据文件内容不改写；只可能修正指向它的链接。
- `probes/` 下的厂商样本结果、`.local/` 原始日志不进入文档体系。

### 6.3 删除清单（按类别）

- `docs/project/` 散落文档：session prompts、pending rulings、interface proposal、0.2 handoff prompt、P0/P2/P3 progress、P2 manual verification、P2 plan index、RESUME_PROMPT、`handoffs/`。
- `docs/superpowers/specs/` 与 `plans/`：0.21 之前的全部；0.21 的 7 份阶段 spec/plan 在基线吸收后删除。
- `docs/superpowers/prompts/`、`docs/skills/`、`docs/project/skills/`。
- 未被保留验收行引用的 evidence。
- `.superpowers/sdd/` 已关闭账本（先持久化必要裁决）。

每项的最终去留进入处置表，由业主确认后执行。
