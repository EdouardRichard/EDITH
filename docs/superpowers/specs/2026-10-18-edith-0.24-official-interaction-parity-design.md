## 1. 结论、目标与范围

### 1.1 0.23 的验收结论（业主 2026-10-18）

- **0.23 版本级判词：用户验收不通过。** 业主原话的交互问题：
  1. 唤醒后未按官方逻辑“弹出界面并等待继续输入；一定时间无输入自动关闭”。
  2. 未实现官方的持续对话：回答一次后 EDITH 就停止。
  3. 唤出界面后的动态效果与官方不一致。
- 0.23 的 JVM 计数、P6 设备走查、U-5/U-6/U-8/U-9/U-10 的视觉/按键证据仍是**历史读数**，不删除；但其中与本文件冲突的**交互语义**由本文件取代。不得把 0.23 写成“通过”，也不得把本文件写成已实现。
- 0.23 规格 §12 风险 6「官方自动退出超时不可得、EDITH 不实现自动退出」与 `D133`「pin 只映射停/恢复 ticker」被本文件取代。

### 1.2 0.24 目标

把官方「乐奇助手」的**会话内交互**照搬到 EDITH，包括：

- 唤醒 → 面板出现 → 等待输入 → 10 s 无输入自动关闭；**眼镜息屏时也能被唤醒并点亮**。
- 回答完成后自动进入下一轮聆听（持续对话），直到达到官方静默超时。
- 官方的 PAG 语音球三段动画、ASR “…”/思考 GIF、ASR 逐字上屏、答案流式、每轮对话条目、状态行、Markdown。
- 官方的单击钉住、双击退出/打断、左下提示、10 s / 120 s 超时语义。
- 用户点一次「开始」后进入**常驻会话**：关闭面板不结束会话；「停止」才结束。

### 1.3 范围内

| 编号 | 范围 | 阶段 |
|---|---|---|
| S-1 | 常驻会话 + 眼镜端前台服务/悬浮窗 + 息屏唤醒/点亮 | S1–S2 |
| S-2 | 会话状态机、10 s 自动关闭、持续对话、120 s 钉住行为 | S2–S3 |
| S-3 | 官方按键/钉住/提示/BACK 语义 | S3 |
| S-4 | ASR 逐字、答案流式、每轮 item、工具状态行、Markdown | S4 |
| S-5 | PAG 三段语音球、官方 GIF、面板动态 | S4 |
| S-6 | 两端设备走查、JVM 回归、协议/兼容/回退、文档收口 | S5 |

### 1.4 明确不做

1. **不照搬官方相机、JSUI 卡片、官方云助手/工具卡片**：EDITH 没有对应能力、数据源或 UI 通道；本版只照搬“会话内交互”。
2. **不改唤醒词**：保持 `伊迪丝` / `EDITH`；官方唤醒词「乐奇」只用于指代官方助手。
3. **不照搬官方窗口类型/系统 UID**：官方是 `TYPE_SYSTEM_ERROR` + uid 1000；EDITH 用第三方可用的 `TYPE_APPLICATION_OVERLAY` + 前台服务。窗口类型差异如实记录。
4. **不照搬厂商 FX 音效**：官方 `aiWakeSound`/退出音是厂商系统 FX（34/62），第三方不可达；继续用 `ToneGenerator` 短音（`D135`），差异如实记录。
5. **不把相机/录像/导航场景冲突、官方错误文案全表、头盔模式**纳入本版；EDITH 现有错误提示保持。
6. **不新增上传授权**：D53 不变；常驻会话不改变“会话运行即允许唤醒回合上传”的口径（见 §7.1）。
7. **不复制官方 `agent` 名/自动 pin、退出语 `launcher_ai_quit_tts`、`onWaitTts` FX 35**：EDITH 没有 agent/JSUI 概念；关面板不结束会话，“退出语”语义不成立；厂商 FX 不可达。以上差异在 §10 记录，不写成已照搬。

## 3. 官方行为基线（代码级，反编译 `com.rokid.os.sprite.assistserver` v0.3.8）

> 以下路径相对 `D:\Project_new\rokid_glasses_UI\raw\rokid-wake-ui\cfr-src\`。等级：**J** = CFR Java，**A** = 真机日志/截图，**B** = 官方资源。

### 3.1 唤醒、显示、10 s 超时

- `AIOpenHandler.handle`：`cancelContinuation()` → `beginAiAssistRound("explicit_wake")` → `assemblyDataToLauncher(caps,"open")` → `AIModeManager.startNewTalk()` → `controller.startTimeout(10000L)`。**J**
- `AIModeManager.startNewTalk`：插入一条 `status=1` 的空对话项；UI 进入聆听。**J**
- `AsrMessageHandler.handle`：`removeTimeout()`、`cancelContinuation()`、`removeExit()`；有非空 ASR 才 `ensureAiAssistRound("user_speech_input")`。**J**
- `AsrEndHandler.handle`：`removeTimeout()`、`removeExit()`、`armAiAssistRoundForNextAsr()`、`AIModeManager.asrEnd()`、`startWaitTts(1200L)`。**J**
- `TtsResultHandler.handle`：`removeTimeout()`、`cancelContinuationBeforeDeadline()`、`removeWaiteTTS()`、`removeExit()`、`AIModeManager.ttsResult()`。**J**
- `RokidAIController.onTimeout()`：
  - `agentBean == null && !isNotAutoExit` → `clearAll()` + `exit()`（关闭面板）；
  - `isNotAutoExit`（已钉住）→ `clearAll()` + `AIAssistUtils.sendExit(true)` + `AIModeManager.aiIdle()` + `sendExitToLauncher("Ai_Idle")`；
  - `agentBean != null` → 同上 idle 路径。
- `AIAssistUtils.sendExit(true)` → `sendQuitAI(120000L)`：服务侧 120 s 延迟退出。**J**（服务侧执行未真机形成因果，`NotMeasured`）
- 官方常量：`RokidAIController.TIME_OUT = 10000L`、`TIME_WAITE_QUIT_TTS = 120000L`。**J**
- `AiAssistantDialog.onCreate`：屏幕未亮时 `PowerManagerUtils.wakeUp()`；`setOnShowListener` 里 `getWindow().addFlags(0x80)`（`FLAG_KEEP_SCREEN_ON`），layout `keepScreenOn=true`。**J+B**
- 摘下眼镜：`glassTackOnChange tackOn[false]` → `sendExit isNotAutoExit:false` → `sendExitToLauncher` → `dismissAiDialog`。**A**

### 3.2 持续对话

- `AudioFinishedHandler.audioFinished`：
  - `removeWaiteTTS()`、`removeTimeout()`、`removeExit()`、`finishAiAssistResponse()`；
  - 若 `settings_ai_assistant_continue_dialogue == "close"` 或场景不在跑 → `scheduleExit(1000L)`；
  - 否则 `startTimeout(10000L)` + `assemblyDataToLauncher(caps,"TTS_AudioFinished")` + `AIModeManager.audioFinished(caps)`；还按情况 `aiAudioFinishWake()`/`aiWake(1)`。**J**
- `AIModeManager.audioFinished`：先发 status 5，再 `startNewTalk()`（status 1）。**J**
- `showAudioFinishUI`（status 5）：`lastFinish()`、`showAgentName`；**它本身不插入下一条**；同一条 `AIModeManager.audioFinished` 在 post status 5 之后调用 `startNewTalk()`（status 1）插入新聆听项。**J**
- 「持续对话」是设置项 `settings_ai_assistant_continue_dialogue`，**默认 `"open"`**。**J**
- **声音边界**：`aiWakeSound()` 是首次唤醒的 FX 34（800 ms 去抖）；`aiWake(1)`/`aiAudioFinishWake()` **不是声音**，它们调用 `startAudioStream`、`aiWakeLight`、`startAIScene` 并向手机发 Caps，用来重新开始音频流。持续对话的下一轮不播放提示音。

### 3.3 状态机、提示、按键、钉住

- `AIModeReceived` status 0–7 的 `doubleClickExit`/提示/UI 方法见 0.23 实现解析 §2；本文件只取可观察行为：
  - status 3（播报中）把 `doubleClickExit=false`；仅当 `isHold` 时左下提示改为 `滑动翻页 / 双击打断`；
  - 其它 status 提示为 `滑动翻页 / 双击退出`。
- **`Hi, 我在听` 的显隐是 status 的副作用，且只在首次/status 0 出现**：
  - `showNoneView`(status 0) 置 `idTvSpeak` VISIBLE；
  - `showASRResultMessage`(2)、`showUpdateTTSUI`(3)、`showTranslateStateUI`(4)、`showJSUI`(6) 置 GONE；
  - `showListenerUI`(status 1) **不设置** `idTvSpeak`；`showAudioFinishUI`(status 5) 也不设置。
  - 因此自动下一轮 status 5→1 时 Hi 仍为 GONE；0.23 实现解析 §3.2 的“Hi 会在多轮之间反复出现”与 `showListenerUI` 代码不符，本版以代码为准：首次打开/status 0 才显示 Hi，持续对话的下一轮只有 ASR “…” + listener 球。

- `showIdleStatus` **不是 status 0**：它由 `stopTalk()` / `aiIdle` 调用，置 `doubleClickExit=true`、提示“双击退出”、隐藏 Hi、`finalizeTextItemIfNeeded`、`autoScrollRecycler`、`lastFinish()`，保留面板与对话内容；EDITH 用独立 `IDLE` 事件表达，不复用 status 0。
- `AiAssistantDialog.onKeyUp`：
  - `KEYCODE_BACK(4)`：先让 JSUI 卡片处理；否则
    - `isHold` 且 `doubleClickExit` → `exit()`（关闭）；
    - `isHold` 且 `!doubleClickExit`（播报中）→ `stopTalk()`（只打断，不关闭）；
    - `!isHold` → `exit()`（无论是否在播报）。
  - `KEYCODE_ENTER(66)` → `holdAIAssistant()`。
- `holdAIAssistant()`：`isHold=true`；`sendNotAutoExitToService(true)`；隐藏“单击钉住”文字、显示 20×20 图钉。**没有取消路径**。**J**
- `stopTalk()`：`sendExitToService(2)` + `showIdleStatus()`，**不 dismiss**。**J**
- `showIdleStatus()`：`doubleClickExit=true`、提示恢复“双击退出”、隐藏 `id_tv_speak`、`lastFinish()`；对话内容保留。**J**
- `ErAIRecyclerView` 只处理 `KEYCODE_DPAD_DOWN(20)`/`UP(19)`；左右键交回父类。步长 `min(剩余, 视图高度×0.85)`。**J**
- `startAutoScroll`：`ValueAnimator` 每帧 `scrollBy(0,1)`，前 3 帧跳过；用户手动滚动即停；**pin 不清除/不停止 auto-scroll**。**J**

## 4. EDITH 现状与差距（代码级）

### 4.1 当前主链路

- 手机点「开始」→ `SessionService`（前台）+ `HostRuntime.startSession` → CXR `SessionConfig(CUSTOM_APP, glassesPackageName, glassesActivityName)` 建链 → 眼镜 `GlassesActivity` 收 `HELLO/PING/SYNC`。
- KWS 在手机 `HostCompositionRoot` 的 `WakeWordDetector`；`emitWakeDetected` 要求 `host.currentIdentity()` 非空（会话已开始）。
- `WakeDetected` → `SmartAssistantPlugin.openTurn`（等待转写）→ final transcript → `runTurn` → 一次模型回合 → `emit` 生成一次 `Assistance`/`SHOW` → `wakeBusy=false`；没有下一轮。
- 眼镜 `GlassesActivity` 只处理 `HELLO/PING/SYNC/SHOW/CLEAR/ACK/SAID/BUSY`；没有面板自动关闭；没有悬浮窗；没有 ASR 逐字/答案流式；`VoiceOrbView` 是自绘近似。

## 5. 目标架构

### 5.1 会话生命周期（D157）

```
手机「开始」
  → SessionService 前台服务（已存在）
  → HostRuntime.startSession + CXR 建链
  → 眼镜 GlassesActivity（trampoline）/ 已安装服务
  → GlassesOverlayService 前台常驻 + CXR 订阅
  → UI_READY
  → 手机 HELLO/PING/SYNC（D15 重试）
  → 面板隐藏，等待唤醒
```

- 当前 `glassesApkPath=null`，`SessionConfig` 是否会自动拉起眼镜 Activity **未确认**。因此会话开始后，手机在等待 `UI_READY` 的宽限期内若未收到，就必须调用 `appStart`；这是 S2 必须实测的分支，不能假设 SDK 已拉起。
- 「开始」= 常驻；「停止」= 结束会话并关闭面板/服务。
- 关闭面板（10 s 超时/BACK/120 s）只隐藏 overlay、清眼镜缓存；**不结束手机会话**。
- 进程/服务被杀后，手机在下次唤醒时检测无 `PONG`/无 `UI_READY`，调用 CXR `appStart(glassesActivityName)` 拉起 trampoline，服务重建后重新 `HELLO/PING`。
- `pause/resume` 保持 0.21 语义；本版不把暂停当作结束。若暂停导致 generation 变化，沿用 `D152` 的 sessionId 校验；恢复后按现有重握手路径处理。

### 5.2 眼镜端窗口模型（D158）

- **组件**：
  - `GlassesActivity`：保留为 CXR 入口/授权跳板；检查 `Settings.canDrawOverlays`；授权后启动 `GlassesOverlayService` 并 `finish()`。不再承载会话 UI（测试可用 headless host）。
  - `GlassesOverlayService`：`startForeground`，持有 `WindowManager`、`RokidBridgeEndpoint` 监听、`GlassesPanelController`、唤醒锁；负责显示/隐藏 overlay。
  - `GlassesPanelView`：从 `GlassesActivity.buildLayout()` 抽出，接收渲染模型；Activity 与 Service 共用同一实现。
  - `GlassesPanelController`：会话缓存、状态机、按键/超时/渲染决策；可脱离 Activity 测试。
- **权限/声明**：
  - `SYSTEM_ALERT_WINDOW`（特殊 app-op，需用户授权；测试用 `appops set ... allow`，回读确认）。
  - `FOREGROUND_SERVICE`（Android 12 前台服务）；服务 `foregroundServiceType` 按设备可用的 `specialUse`/`connectedDevice` 实测定，不臆造。
  - `WAKE_LOCK`（已有）。
- **Overlay 参数（spike 验证后定稿）**：
  - `TYPE_APPLICATION_OVERLAY`；`gravity=BOTTOM|START`；宽 480 px、高 380 px（只覆盖底部面板，保留状态栏/上方画面）。
  - `PixelFormat.TRANSLUCENT`；背景透明；`FLAG_LAYOUT_NO_LIMITS`/`FLAG_LAYOUT_IN_SCREEN`；`FLAG_NOT_TOUCHABLE`（眼镜无触摸屏）。
  - **焦点**：官方窗口 `NOT_FOCUSABLE`；第三方要收侧键，需实测“可聚焦但不拦截触摸”的组合。若可聚焦浮层收不到键，S1 停下交业主，不擅自改成无键浮层。
  - `FLAG_KEEP_SCREEN_ON` + 显式唤醒锁（`SCREEN_BRIGHT_WAKE_LOCK | ACQUIRE_CAUSES_WAKEUP`，平台 API；厂商无 API，沿用 D42 先例）；显示面板时 acquire，隐藏/销毁 release，时长上限兜底。
- **服务存活**：前台服务 + 通知（低重要性）；`START_STICKY` 仅作为恢复策略，必须有手机侧重连检测；进程死亡时下次唤醒 appStart。
- **开面板**：手机发 `PANEL_OPEN` 或首条 `STATE`；服务 addView + 唤醒锁；面板显示后发 `PANEL_SHOWN`。**仅在面板从隐藏变为可见时清缓存/重置**；面板已可见（例如 STOP 后的 IDLE）再收到 `PANEL_OPEN`/status 1 时**不重置内容**（对应官方 `showAiDialog` 在 `isShowing()` 时只 `setAiItemInfo`、不 `resetDialogUiState`）。
- **关面板**：手机发 `CLOSE`，或用户 BACK；服务 removeView + release 唤醒锁 + 清眼镜缓存；发 `UI_CLOSED`；服务保留。

### 5.3 会话状态机（D160/D164）

以官方 status 为准，WAKE 路由：

| status | 含义 | 面板 | 左下提示 | BACK（isHold） | 下一动作 |
|---|---|---|---|---|---|
| 0 | 空态 `showNoneView` | `Hi, 我在听` + “…” + PAG listener | 双击退出 | 退出 | 仅空态；**不是 idle** |
| 1 | 聆听 | Hi 仅首次/status 0 后可见；否则只有 “…” + PAG listener | 双击退出 | 退出 | 10 s 无 ASR → 关闭/idle |
| 2 | ASR 进行 | 用户行逐字亮绿，“…”消失，Hi 隐藏 | 双击退出 | 退出 | ASR 继续；10 s 已取消 |
| 3 | 播报/答案 | 答案行流式；PAG `think_last→finish`；Hi 隐藏 | **双击打断**（仅 pin） | **打断，不关闭** | 播完 → 5 |
| 4 | ASR 结束/思考 | 思考行 + PAG `listener_last→think`；Hi 隐藏 | 双击退出 | 退出 | 等 TTS/答案；10 s 已取消 |
| 5 | 本轮音频结束 | 答案定稿；PAG `finish_last`；Hi 隐藏 | 双击退出 | 退出 | 持续对话 → 新 status 1（**不重显 Hi**） |
| 7 | 工具执行 | 工具行 + GIF；PAG `think_last→finish` | 双击退出 | 退出 | 工具结束 → 3/4 |
| `IDLE` | `showIdleStatus` | 隐藏 Hi/思考/“…”；`finish_last`；保留内容 | 双击退出 | 退出 | pin 超时 → 120 s 后 `CLOSE`；STOP → 保持 idle（是否也 120 s 未证实，S3 设备确认） |
| — | 关闭 | 隐藏 | — | — | 清眼镜缓存，会话保留 |

- **10 s 计时只属于聆听态（status 0/1）**：面板从隐藏变为显示时，从 `PANEL_SHOWN` 开始；面板已显示时，turn 打开即开始。**任何 ASR 消息**（包括空白/唤醒词回声；对应官方 `AsrMessageHandler` 在 `hasNonBlankAsr` 之前就 `removeTimeout`）取消计时；status 2/3/4/7 不设计时；status 5 后新的 status 1 再开始。官方在 dialog `show` 时启动计时；EDITH 以 `PANEL_SHOWN` 等价替代，避免把 overlay 拉起耗时算进用户静默窗口。手机等待 `PANEL_SHOWN` 设短上限（S2 实测后定，初值 3 s）；超时记 `P3_CONV panel_not_shown`，不开 10 s 计时并关闭本次聆听，不把“面板没出来”算成用户静默。
- **关闭**：未 pin → `CLOSE`，隐藏面板；已 pin → `IDLE`（不是 status 0），120 s 后 `CLOSE`。
- **持续对话**：status 5 后自动开新 turn（status 1），不要求再唤醒；`continue_dialogue` 默认开（新增持久开关，默认 true）。官方 `showListenerUI` 不恢复 `Hi, 我在听`，所以新一轮只有 ASR “…” + listener 球；我们不为了“好看”额外把 Hi 打开。**续听不播放提示音**：`aiWake(1)`/`aiAudioFinishWake()` 是音频流/灯的重新开始（`startAudioStream` + Caps），不是声音；唯一的声音是首次唤醒的 `aiWakeSound()`（FX 34，800 ms 去抖）。
- **关闭持续对话时**：官方 `AudioFinishedHandler` 走 `scheduleExit(1000)`，**不**发 status 5、不 `AIManager.audioFinished`、不开新聆听；EDITH 在答案完成/语音结束后 1 s 发 `CLOSE`，不保证 status 5。此分支不得写成“先 5 再 1”。
- **STOP/IDLE**：眼镜双击打断（pin+status 3）或手机停止当前回合后发 `IDLE`；不自动开下一轮，面板保留，用户再次双击退出或重新唤醒。`stopTalk` 只发 `sendExitToService(2)` + `showIdleStatus`，**服务侧是否也触发 120 s 延迟退出未在源码中追平**；S3 设备确认前不把 STOP 写成 120 s 关闭。pin 超时走 `onTimeout → sendExit(true)`，120 s 是代码级（服务执行未实测）。
- **pin**：单击一次置 true；不取消；面板关闭/新窗口复位。pin 不停止 ticker；ticker 只被用户翻页/到底/隐藏停止。
- **BACK**：完全按 §3.3。未 pin → 眼镜隐藏面板并发 `STOP` + `UI_CLOSED`（手机取消 turn/计时）；pin+status 3 → 只发 `STOP`，面板保留；pin+其它 → 隐藏面板并发 `STOP` + `UI_CLOSED`。

> **已被 D173 取代 / superseded by D173（2026-10-19）**：EXIT 只发 `UI_CLOSED`，不额外发 `STOP`（手机 `onClose` 取消 turn/计时）；pin+ANSWERING 只发 `STOP` 并保留面板。以实现为准。

- **物理拍照/录像键与触摸面板亮屏**：不拦截、不改；触摸面板 ENTER/BACK/DPAD 仅在面板可见时按上表处理。

### 5.4 线缆协议（加法式，`wireVersion=1`）

保留 `HELLO/PING/PONG/SYNC/SHOW/CLEAR/ACK/SAID/BUSY/STOP`。新增：

| 命令 | 方向 | 字段（顺序） | 语义 |
|---|---|---|---|
| `STATE` | 手机→眼镜 | `wireVersion, command, sessionId, generation, route, turnId, status, sequence` | 状态电平；`status` 用官方 0–7；同 turn 新 sequence 覆盖旧。**status 0 是 `showNoneView`，不是 idle** |
| `IDLE` | 手机→眼镜 | `..., sessionId, generation, route, sequence` | 官方 `showIdleStatus`：隐藏 Hi/思考/“…”、`finish_last`、保留面板与内容；不自动开下一轮；与 `STATE` 同一 sequence 域，低于当前 sequence 的迟到状态丢弃 |
| `ASR` | 手机→眼镜 | `..., route, turnId, revision, text` | 用户行逐字；revision 单调；final 由 `SAID` 承载 |
| `ANSWER` | 手机→眼镜 | `..., route, turnId, hintId, revision, text` | 答案行逐字；final 由 `SHOW` 承载 |
| `TOOL` | 手机→眼镜 | `..., route, turnId, phase(start/end), label` | 工具行 |
| `CLOSE` | 手机→眼镜 | `..., route`（可 `ALL`） | 关闭面板；清眼镜缓存 |
| `PIN` | 眼镜→手机 | `..., sessionId, generation, route` | 已钉住（只置 true） |
| `PANEL_OPEN` | 手机→眼镜 | `..., route` | 显示面板（不改状态） |
| `PANEL_SHOWN` | 眼镜→手机 | `..., route` | 面板已显示，手机开始 10 s 计时 |
| `UI_READY` | 眼镜→手机 | `..., sessionId, generation` | 服务就绪、可收命令 |
| `UI_CLOSED` | 眼镜→手机 | `..., route` | 面板已隐藏（服务仍在） |

- 旧解码器对未知命令返回 null（安全失败）；新眼镜对旧手机仍能显示 `SHOW/SAID/BUSY`（降级为“无逐字/无自动关闭”）。
- 文本上限沿用 400 code point。`ASR`/`ANSWER` 是显示增量：手机发送前截取**最后 400 个 code point**（不拆代理对），眼镜端不再因长度拒绝；final `SHOW` 仍按现有 400 上限与 `ReadableHintAssembler` 口径，是权威文本。
- `SESSION_END` 不新增；手机「停止」通过 CXR 会话关闭/断开让眼镜服务收尾（`RokidBridgeEndpoint` 的断开回调）。
- `SPEECH_DONE` 不走线缆；它是手机宿主内部事件，用于决定下一轮聆听的开始时机。

### 5.5 手机侧改动

- **`ConversationDisplay` 扩展**（带默认空实现，避免破坏旧 fake；方向是插件→宿主）：
  - `state(route, turnId, status, sequence)`
  - `showIdle(route, sequence)`（官方 `showIdleStatus`，与旧 `idle(route)` 的 busy 电平不是同一件事）
  - `userPartial(route, turnId, revision, text)`
  - `assistantPartial(route, turnId, hintId, revision, text)`
  - `toolStatus(route, turnId, phase, label)`
  - `panelOpen(route)` / `closePanel(route)`
- **宿主→插件**：新增 `PinChanged` 宿主事件（来自眼镜 `PIN`），插件置 `pinned=true`；它不属于 `ConversationDisplay`（方向相反）。`UI_READY`/`UI_CLOSED` 由 `HostCompositionRoot`/链路处理，不进插件业务。
- **`ConversationWireDisplay`**：记录手机端 `ConversationLog`（带 `turnId`），并发送 `STATE/IDLE/ASR/ANSWER/TOOL/PANEL_OPEN/CLOSE`；用户 final 仍由 `SAID` 承载；答案 final 仍由 `SHOW` 承载（保留 ack/TTL）。
- **插件 `SmartAssistantPlugin`**：
  - wake turn 语义不变；新增 `conversationActive`/`continuation` 模式。
  - 10 s 聆听窗改为官方常量（WAKE 会话使用；模型请求超时仍用 profile 的 `timeoutMillis`）；**任何 ASR 消息**（含空白/唤醒词回声）都取消计时；status 2/3/4/7 不设计时；status 5 后的新 status 1 再开始。
  - 持续对话：答案 `Displayed`（无语音）或 `SpeechPlayback.FINISHED/FAILED`（有语音）后，自动 `openTurn(bypassWakeGates=true, continuation=true)`；新 turn 监听窗口 10 s；不触发唤醒冷却；**新一轮不重显 `Hi, 我在听`**（官方 `showListenerUI` 不设置它）。
  - 若答案没有被 `Displayed`（拒绝/过期）或没有可确认的语音结束，则**不开下一轮**；按失败/超时关闭面板并记 `P3_CONV no_display`，不把“继续聆听”建立在没显示过的答案上。
  - `ASR` partial 只发布可用用户文本；空白或仅唤醒词的 partial 不发布（与 final 的 `isUsableUtterance` 同口径），但该 ASR 消息仍取消 10 s 计时。
  - pin：`PIN` 事件置 `pinned=true`；10 s 静默 → `IDLE`（不是 status 0）+ 120 s 关闭；不自动开下一轮。
  - BACK/STOP：取消当前 turn、发 `IDLE`（不是 status 0），不关闭面板；未 pin 的 BACK 由眼镜直接关面板并取消 turn。
  - 工具状态：`AgentLoop` 执行工具前/后回调 `toolStatus`；仅映射 EDITH 自己的 action 名称。
  - 答案流式：在 `ModelClientGateway`/`AgentLoop` 暴露 `TextDelta` 回调（不改变 final 装配），插件调用 `assistantPartial`。
- **`HostRuntime`/`OutputArbiter`**：
  - 新增 `SpeechFinished` 宿主事件（session/generation/hintId/result），在 speech `FINISHED/FAILED` 时发出；插件据此开下一轮。
  - `OutputArbiter` 只做通知，不改变现有 TTL/ack 语义。
- **`CxrHintLink`/`CxrBackend`/`RokidSessionTransport`**：
  - 新增发送 `STATE/ASR/ANSWER/TOOL/CLOSE/PANEL_OPEN` 的 fire-and-forget 路径（复用 `sendCommand`）。
  - 新增加 `openGlassesApp()`：通过 `CxrSession.glassesClientOrNull()?.appStart(glassesActivityName, callback)`；仅在无 `UI_READY`/无 `PONG` 时调用。
  - 注册 `IGlassesEventListener`（`addGlassesEventListener`）：
    - `onWearingStatusChanged(false)` → 关面板/取消当前 turn（尽力）；
    - `onGlassesAppResumed/Paused` 作为 UI 状态辅助，不替代 `UI_READY/UI_CLOSED`；
    - `onScreenOff/On` 记录，用于诊断。
  - `PIN`/`UI_READY`/`UI_CLOSED` 入站路由到 `HostCompositionRoot`/插件。
- **`SmartSettings`**：新增 `continueDialogue: Boolean = true`（持久化，默认开）；设置页可关；关闭时**不**发 status 5/新聆听，答案完成/语音结束后 1 s 发 `CLOSE`（对应官方 `scheduleExit(1000)`）。
- **`SessionViewModel`/手机 UI**：状态文案改为“常驻监听中/会话运行中”；「开始/停止」语义不变；面板关闭不影响会话状态。

- **`IDLE`**（官方 `showIdleStatus`）：隐藏 Hi/思考/“…”；把流式答案 finalize 到当前条目；`finish_last`；提示切“双击退出”；保留面板/内容；由 STOP 或 pin 超时触发。pin 超时走 `sendExit(true)` → 120 s 后 `CLOSE`（代码级，服务执行未实测）；STOP 是否也 120 s **未证实**，S3 设备确认前只保证 idle。

- **PAG 球**：`PagOrbView` 55×45；官方 9 个资产；`first/middle/last` 自门控；`OrbState.IDLE`（无工作）停止；官方 `showIdleStatus` 的 `IDLE` 命令仍先播 `finish_last` 再停；`onPause`/隐藏停止；`onAnimationEnd` 串链；失败回退到自绘 `VoiceOrbView` 并记 `PAG_LOAD_FAILED`（回退只保证可用，不声称照搬）。
- **面板**：380 px、上下 30 px 遮罩、合规标识、px 字号、绿阶保持不变；列表 item 内边距按官方（ASR 10/4 px、TTS 5/10 px、思考行 22 px）；列表 `itemAnimator` 关闭（用 View 重建时避免动画）。
- **pin 显示**：未 pin 显示 14 px `单击钉住`；pin 后隐藏文字、显示 20×20 图钉（`GREEN_NORMAL` 40% alpha）；pin 不停止 ticker。
- **滚动**：1 px/帧、前 3 帧跳过、用户翻页停、pin 不停、到顶/到底停；流式更新不重建整表（只更新当前行）。
- **按键时机**：DPAD 上/下在 `ACTION_DOWN` 处理并消费（官方 `ErAIRecyclerView.dispatchKeyEvent` 只处理 `getAction()==0`）；ENTER/BACK 在 `ACTION_UP` 处理并消费（官方 `AiAssistantDialog.onKeyUp`）；左/右不消费，交回父类。
- **缓存**：面板关闭清空两条路由、pin、状态；手机 `ConversationLog` 保留。新面板从空开始（官方 dismiss 后 clearData）。

### 5.7 息屏、摘镜、重连

- 息屏唤醒链：手机 KWS 命中 → 若面板隐藏发 `PANEL_OPEN`/`STATE`；服务显示 overlay 并 acquire 唤醒锁 → 屏幕点亮 → `PANEL_SHOWN` → 手机开始 10 s。
- 若服务未运行：手机检测无 `UI_READY`/`PONG` → `appStart` → trampoline 启动服务 → `UI_READY` → `PANEL_OPEN`/`STATE`。appStart 在息屏下是否成功、是否点亮，S1 设备 spike；不通过则停下交业主。
- 摘镜：`onWearingStatusChanged(false)` → 手机取消当前 turn + `CLOSE`；眼镜服务隐藏面板/释放唤醒锁。设备验证；失败记 `NotMeasured`。
- 重连：CXR `onSessionClosed`/`onDisconnected` → 眼镜服务隐藏面板、清缓存；手机停止 turn；会话若仍在则下次唤醒 appStart。

### 5.8 路由隔离与主动辅助

- WAKE 与 PROACTIVE 继续独立 `ConversationStore`/`ConversationLog`/`ContextManager`（D74/D111/U7）。
- 持续对话只属于 WAKE；PROACTIVE 仍是一次主动提示，按现有 TTL/关闭逻辑，不自动开下一轮。
- 眼镜只显示当前路由；`SHOW`/`STATE` 决定；`SAID`/`ASR` 不切换。
- 面板关闭清空两条路由缓存（D130 窗口缓存）；手机记录不受影响。

## 6. 数据、状态与不变量

- **手机 `ConversationLog` 是会话完整记录**；眼镜缓存是当前窗口，关闭即清。
- `ConversationEntry` 增加 `turnId`；`entryId` 稳定：
  - 用户：`asr-${turnId}`（partial/final 同一 id 更新）；
  - 助手：`say-${hintId}`（partial/final 同一 id 更新）。
- 每路由有界（40 条/6000 字符）不变；流式更新不新增条目（同 id 替换）。
- **状态顺序**：`STATE` 用 `sequence` 单调；`ASR/ANSWER` 用 `revision` 单调；乱序丢弃。`turnId` 用于归属。
- **不重排**：手机/眼镜都按到达顺序/日志顺序显示；不按时间戳二次排序。
- **面板关闭/新窗口**：清空眼镜 `ConversationLog`、`ConversationOrder`、`pin`、`status`；手机保留记录。
- **不新增会话结束线缆命令**：手机停止通过 CXR 会话关闭；面板关闭用 `CLOSE`，不等于会话结束。

## 7. 权限、安全、隐私与设备纪律

### 7.1 上传与同意（D53 不变）

- 点「开始」仍是唯一同意动作；常驻会话期间，唤醒回合的转写与回合上下文可发往所配置模型服务（D53 原文）。
- 面板关闭、静默超时、后台常驻**不新增**上传种类；记忆写入零网络；日志/证据只记计数/id/哈希/字符数。
- `continueDialogue` 只影响是否自动开下一轮，不影响上传授权。

### 7.2 新增权限/系统设置

- 眼镜 `SYSTEM_ALERT_WINDOW`：用户授权/测试 `appops set`；必须回读确认（`appops get`），不能只看命令退出码。
- 眼镜 `FOREGROUND_SERVICE`：前台服务通知；服务类型按设备实测定。
- `WAKE_LOCK`：已有；显示面板时 acquire，隐藏/销毁 release，时长上限兜底。
- 不改 `applicationId`、不新增上传权限、不改记忆/SKILL 存储格式。

### 7.3 设备纪律

- 手机侧人工操作仍一律 `edith.phone.a11yprobe`（D95）；`adb shell input tap/text` 禁用。
- 眼镜侧按键注入只作按键链证据，不作物理手感证据；钥匙/触摸面板亮屏属系统层，不拦截。
- 眼镜重装：同一调试签名优先 `install -r`；若签名不一致需 `uninstall`，先记录并确认不影响邻居工作线。
- 证据只含合成文本；不记录用户正文、原始音频/声纹/简历。
