## 2. 术语与证据边界

| 术语 | 含义 |
|---|---|
| `Confirmed` | 用户明确提供的事实/要求 |
| `Accepted` | 书面设计或技术决策被用户明确批准 |
| `Proposed` | Agent 建议，尚未批准（本版不作为承诺） |
| `Superseded` | 被具名新记录替代（活动登记中已删除或标注） |

- **代码事实**：文件/类/行号可核对；本规格的模块、类型、路径均可在仓库中解析。

## 4. 端到端链路

### 4.1 会话启动与设备连接

- 入口：`phone-app` 的 `MainActivity` / `SessionViewModel` / `SessionService`；宿主状态机在 `HostRuntime`。
- 用户点「开始」即唯一同意动作（D53①）；App 自己建立 CXR 连接（D53③，`ensureCxrLink()`），不再有独立"连接眼镜"入口。
- `transport-rokid` 的 `RokidSessionTransport` 负责 CXR-L 会话、授权解析（`CxrAuthorizationOutcome`）、音频订阅与自定义命令；眼镜侧 `glasses-app` 的 `RokidBridgeEndpoint` / `GlassesActivity` 接收并显示。
- 眼镜与手机交互的层级、API、`Caps` 载荷字段与顺序**以官方 demo/样本为准**（D41/D44）；"与 demo 一致"即正确性判据，不需要重复真机验证；硬件/功耗/可读性仍要实测。

### 4.2 采音、VAD、ASR、声纹

- 眼镜麦克风 → CXR 音频 → `PcmIngress` → `SpeechPipeline`（`audio-runtime`）。
- `SpeechPipeline` 持有 VAD/ASR/声纹引擎接口，按回合切分，产出 `TranscriptEvent` / `AcousticEvent`；`TurnTimeline` 维护回合与说话人窗口。
- Android 引擎实现位于 `audio-android`（sherpa-onnx）：`SherpaVadFactory`、`SherpaEngines`、`SherpaKeywordSpotter`；引擎清单与选择见 `EngineManifest*`/`EngineSelection`。
- 唤醒：生产 0.21 走 **KWS**（`KeywordSpotterWakeWordEngine`，`HostCompositionRoot` 的 `WakeWordDetector`）；`AsrTextWakeWordMatcher` 仍存在但**生产无调用者**（只在测试中；其 KDoc 的 "P3.1 实际运行" 是历史陈述，已过时）。
- 声纹：`SpeakerPolicy` / `LocalSpeakerService`；本版**不注册声纹**、不承诺 SELF/OTHER/UNKNOWN 归因（D57 影响）。

### 4.3 唤醒与主动辅助

- 两条会话路由：`WAKE` 与 `PROACTIVE`（`ContextRoute`），历史互不污染（B1）。
- 主动辅助：`SmartProactive` + `ProactiveGate`（`NoulGate`/`ChoiceGate`）+ `ProactiveArming`；Laya 只做"此刻是否该介入"的闸门（D60 §2），运行在 **GPU**（D64），NPU 不作为后端。
- 唤醒不守护端到端预算；1.5 s 只对主动辅助（D70）。
- 闸门是**纯事件驱动**：state 不含时间特征（D60 §3）；事件集必须覆盖 state 的每个输入维度。

### 4.4 回合执行（AgentLoop）

- `AgentLoop` 执行一次回合：组装请求 → 调模型 → 有工具调用则执行并追加工具回合 → 直到模型声明结束。
- 确认：`ConfirmationGate` / `ConfirmationPort`；插件闸门为权威（D47/D48）；**人时不计入回合预算**（D49），`AgentLoop` 量测等待并顺延 deadline。
- 进度：`ProgressGuard` 防重复/无进展；终态为 `COMPLETED` / `INSUFFICIENT` / `NO_PROGRESS` / `DEADLINE` / `CANCELLED` / `FAILED`。
- 上屏不驱动循环终态（D78）；动作层与任务层分开判。

### 4.5 请求装配（0.21 核心）

- **唯一 owner**：`agent-runtime` 的 `TurnRunner`。插件只贡献 `Segment`，不再构造消息数组（D71）。
- `SegmentOrigin` 共 10 种：`INSTRUCTIONS`、`SKILL`、`MEMORY_POLICY`、`MEMORY_EVIDENCE`、`PERCEPTION`、`SUMMARY`、`TRANSCRIPT`、`USER_INPUT`、`TOOL_ROUND`、`RETRY`。
- `RequestFrame` 约束：系统槽只允许 `INSTRUCTIONS`/`SKILL`/`MEMORY_POLICY`；会话流**恰好一个** `USER_INPUT` 且必须是最后一条（`RequestFrame.init`）。
- 装配顺序：`ConversationStore` 快照 → `PERCEPTION` → `MEMORY_EVIDENCE` → `USER_INPUT`（`TurnRunner.assemble`）。
- 裁剪：`TurnTrimmer` 固定三刀 **旧整回合 → 最不相关记忆 → 压缩**（D97）；**②在带回合组的流上通常是 no-op**（记忆随①一起离开并记 `droppedTurns`，只在 `[memory, USER_INPUT]` 时单独生效）；本轮发言按构造不被裁；`TrimReport` 只记计数/来源，不记正文。
- 预算：`ContextBudgeter` 只做形状校验与窗口预算（`ContextBudgeter.prepare`）；`ModelRequest` 是纯线缆形状，`ContextPart` 与三处 `context` 已删除（D80）。

### 4.6 记忆

- `MemoryModule` 是门面：写入（`MemoryLog`）、检索（`SemanticRetriever` + 词法降级）、渲染（`MemoryEvidenceRenderer`）。
- 写入侧规范化（D87）：原话 + 规范形双存（D90）；两份都索引（D91）；纯模板改写、零模型调用（D89）；语义口径 (a)（D88）。
- 检索：查询 embed 一次；无语义服务/embed 失败 → 词法降级；namespace 读失败 → 空，不造记忆。
- 相关性下限：本轮只交付 seam + 计数（`below=`/`cutoff=`），不预设数值（D92）。
- 注入：`MEMORY_EVIDENCE` 在 **RequestFrame 层**是独立带标签段，位于本轮 `USER_INPUT` 之前；不进系统帧、**不写入 `ConversationStore`**（D72）。**线上（wire）层**由 `ModelClientGateway` 把 `SUMMARY`/`MEMORY_EVIDENCE`/`PERCEPTION` 折进**首条 user 历史消息**（首轮没有 user turn 时折进请求 `input`），与是否压缩无关。
- 渲染：生产用 `ProductionMemoryEvidenceRenderer`；Phase 7 的 `LegacyRawMemoryEvidenceRenderer` 只用于 F4 测量（D116）。

### 4.7 会话与压缩

- `ConversationStore`：**每路由一条**（D74），有界、可压缩，独立于单次回合执行器。
- 压缩（方案 E）：同步规则截断 + 异步云端摘要；同步半永不出错，异步半是纯改进（`ContextCompressor`）。
- 摘要：`origin=SUMMARY` + 显式边界（D82/D98）；摘要与真实用户消息可识别。
- 压缩门：`droppedTurns > 0 && compressionOwed`（D100）；压缩不会救当前请求，只影响下一回合。
- 记忆与摘要**在线上**折进首条 user 历史消息（D99）；`RequestFrame`/`ConversationStore` 层仍是独立段；`AC-1b` 不受影响。

### 4.8 SKILL

- 定义：程序性知识四要素；`examples` 不存在；`triggers` 不再作为选择依据，但**代码仍解析该字段（drift，无消费者）**；新增 `applies_when`/`not_applies_when`（D75）。
- 注入：**两层**——系统帧放有界目录（name + description），正文由 `load_skill` 按需 pull（D73/D105）。
- `SkillManager.injection()`（D60 全量注入）已退出生产，只保留为回退参考，**不得重新接线**。
- 生命周期：`LibraryState` 三态（ACTIVE/DORMANT/RETIRED）；`LibraryEntry` 携带该状态；`LibraryGovernor`（D106）；drift 只对"本轮真正被列出的条目"计数（D107）；disabled/删文件条目在治理之外（D108）；降级/退役不静默（D109）。
- 作者回路：L1（人工审阅 + 测试效果，D76）。
- `applies_when` 生产未接线（AC-14 已知降级）；判定器与过滤测试只在 JVM 经注入 evaluator 生效。

### 4.9 工具面

**0.21 验收记录的口径**：工具面 9 个——`read_screen` / `tap` / `long_press` / `scroll` / `input_text`（无障碍）+ `launch_app` / `list_apps` / `system_action`（Shizuku）+ `notify_user`（交付）；`set_alarm` / `compose_note` / `dial` 本版不可用（R-8）。

**代码事实（必须一起读）**：生产 `HostCompositionRoot` 的 `ExecutionRouter` 在通道可用时会把以下 descriptor 全部广告：

- `IntentActionExecutor` 的 6 个（`IntentExecutionBackend.available()` 恒 `true`）：`open_app`/`open_url`/`open_settings`/`set_alarm`/`compose_note`/`dial`；
- `ShizukuExecutionBackend` 的 5 个 Shizuku 特权/系统工具（Shizuku ready 时；4 个 L3/L4 + `set_brightness` L2）：`clear_data`/`uninstall`/`disable_app`/`set_permission`/`set_brightness`；
- 其余：无障碍 5 + `launch_app`/`list_apps` + `system_action` + `notify_user` + `load_skill`。

⇒ **通道全开时实际广告 19 个动作工具 + `notify_user` + `load_skill` = 21 个**；验收口径的 9 个（含 `notify_user`、不含 `load_skill`）与代码不一致。这是 0.21 的 **doc/code drift**：验收按当时的“R-8 收缩”记录，代码没有对应过滤。

- 本规格按**代码事实**记录：工具面 = 所有可用 backend 的 descriptor 并集 + `notify_user` + `load_skill`。
- `ACCEPTANCE.md` 保留 0.21 的 R-8 原文与 M2 失败判词，不把 drift 改写为通过。
- `STATUS.md` 把该 drift 列入"已知偏差 / 下版本工具面重构"；**下版本按 D121 处理，D120 只表示本轮不修**。
- **2026-10-22 Phase 4A 实现注记**：0.3 Phase 4A 已把生产组合根收成一个 `Capability.Actions` 的 **24 默认工具**（18 atomic + 4 umbrella + `notify_user`/`load_skill`），`ExecutionRouter` 不再作为生产 provider；这取代 0.21 的 21 工具代码事实用于 0.3，但 **0.21 M2 0/10 与验收判词不改**。**Phase 4B 的权限/确认/不拦截实现与 JVM 收口已完成（2026-10-22），设备矩阵为 Partial；不是 P4-B/C/D/E 全部通过，不是版本级通过。** Phase 4A/4B 均无版本级设备通过声明。
- 能力边界不变：模型不知道通道；无障碍是手和眼，Shizuku 是开门和扳开关；坐标点击不暴露（D84）；`launch_app` 用模糊名 + 候选（D85）；`read_screen` 无障碍优先（D86）；**Shizuku `uiautomator dump` 降级尚未实现**（生产只有无障碍路径，dump 只在探针里）。

**工具语义**：
- 每个动作类工具返回 `applied`（界面状态真的变了）+ 可观测性声明（D79）。
- `notify_user` 带 `final`（D78/D79）；`load_skill` 按名 pull，不计入 `maxSteps`（D110）。
- 风险分级与确认：`WhitelistActionPolicy`；L3/L4 永不免确认；插件只能收紧（`requiresConfirmation`）。

### 4.10 输出与上屏

- `OutputArbiter`（host）仲裁提示：优先级、过期、revision、队列上限 8、显示中替换规则。
- `HintPolicy` / `HintWireCodec` / `ReadableHintAssembler` 三处上限 400 且由测试钉住不能各自漂移（D63）。
- 眼镜侧 `glasses-app`：`HintPresentation` / `HintAutoScroll` / `HintReveal`；旧眼镜 APK 会把 >120 的提示静默丢成 `undecodable` ⇒ 涉及提示上限的验证**两端必须同一次构建**（D63）。
- TTS：手机侧合成 + Android 原生音频输出（A2DP 到眼镜），眼镜端 TTS 不做（D58）；`TtsAvailability` 给出 `READY` / `NO_ENGINE` / `LANGUAGE_UNSUPPORTED` / `INIT_FAILED`，不写死厂商引擎包名。
- 语音不单独走优先级通道；朗读无独立计时器；播放只驱动 `PlaybackGate` 的真实出声区间（D58）。

### 4.11 安全、隐私与权限（摘要）

## 6. 模型、协议与预算

### 6.1 模型档案

`ModelProfile`（`plugin-api/ModelServices.kt`）的字段：`id`、`revision`、`name`、`service`、`baseUrl`、`protocolId`、`model`、`secret`、`usableWindowTokens`、`inputBudgetTokens`、`maxOutputTokens`、`safetyTokens`、`timeoutMillis`、`inputs`、`outputs`、`verifications`。

- 开发测试使用 DeepSeek / Responses API（D24/D25）；正式 App 由用户配置多模型（D28）。
- `timeoutMillis` 是**单次模型请求**上限，不是回合预算（D49）。
- 档案与凭证不写入仓库；`api_key.yaml` 只在本地、gitignored。

### 6.2 适配器与线缆

- `DeepSeekResponsesAdapter`：Responses API；system 槽 + input/history + tools；流式解码见 `SseDecoder`/`ResponsesDecoder`。
- `OpenAiChatCompletionsAdapter`：Chat Completions；**必须发 system 消息**（0.21 D1 修复）、**必须支持工具往返**（D2 修复）；`ChatCompletionsDecoder` 解码。
- `ModelClientGateway`：把插件的一轮请求送到 `ModelClient`，负责 envelope、取消、超时；不再持有 `context` 兜底检索（D80）。
- 工具往返：`ModelHistoryItem.ToolCall`/`ToolOutput` 必须成对；孤儿输出由预算/归一校验拒绝。

### 6.3 请求形状与预算

- `ModelRequest` 是纯线缆形状：`envelope`、`requestId`、`turnId`、`profileId`、`profileRevision`、`instructions`、`input`、`history`、`output`、`tools` 等；`ContextPart` 与三处 `context` 已删除（D80）。
- `ContextBudgeter.prepare` 只做**形状校验 + 窗口预算**，不做装配：
  - `profileId`/`profileRevision` 必须匹配；
  - 输入只接受 `InputPart.Text`（媒体估计器缺失时抛 `CapabilityMissing`）；
  - history 必须从 `USER` 开始、USER/ASSISTANT 交替；**例外**：工具项之后的 assistant text 可直接跟随（同一 assistant 回合跨多个工具轮，`ContextBudgeter` 明确允许）；工具项必须属于某个 assistant 回合；
  - 预算上限 = `min(inputBudgetTokens, usableWindowTokens - maxOutputTokens - safetyTokens)`；
  - 超限从**最旧整组**开始删；删完仍超则拒绝，不做截断。
- 裁剪顺序固定为**旧整回合 → 最不相关记忆 → 压缩**（D97）；**②在带回合组的流上通常是 no-op**（记忆随①一起离开并记 `droppedTurns`，只在 `[memory, USER_INPUT]` 时单独生效）；**统一窗口预算，超限按整回合/整条记忆省略**（D81；规格里的 per-block `maxBytes` 未实现，drift）；本轮 `USER_INPUT` 按构造不被裁。
- 全量回归口径：`test` + `testDebugUnitTest` 同一命令同时跑（D103）。

## 7. 数据、会话与记忆

### 7.1 会话

- `ConversationStore`：每路由一条（D74），有界、可压缩；回合执行器只持有一次 run 的快照。
- 会话流元素是 `Segment`，带 `origin`/`trusted`/`role`；归属是元数据，不由文本反推。
- 摘要：`origin=SUMMARY` + 显式边界（D82/D98）；摘要与真实用户消息可识别。
- 压缩：同步规则截断 + 异步摘要；压缩门 `droppedTurns > 0 && compressionOwed`（D100）；压缩不救当前请求，只影响下一回合。
- 记忆与摘要**在线上**折进首条 user 历史消息（D99）；`RequestFrame`/`ConversationStore` 层仍是独立段。

### 7.2 记忆

- 存储：按插件的加密命名空间（`storage-runtime/NamespaceStorage`）；原话 + 规范形双存（D90）。
- 索引：原话 embedding + 规范形 embedding，两份都索引（D91）。
- 写入：写入侧规范化，纯模板、零模型调用（D87/D89）；语义口径 (a)（D88）。
- 检索：查询 embed 一次；语义失败降级为词法；namespace 读失败返回空，不造记忆。
- 下限：只交付可注入 seam + 计数（`below=`/`cutoff=`），默认关闭、行为不变；数值本轮不标定（D92）。
- 生命周期：**记忆侧**的 `LibraryGovernor` 可注入但**生产不接线**（D112）；默认关闭时检索/渲染逐字节不变。**SKILL 侧已在生产接线**（D106，`SmartAssistantPlugin` 构造 `SkillManager` 时传入同一个 governor）。
- 注入：`MEMORY_EVIDENCE` 在 **RequestFrame 层**是独立消息、带边界标签，位于本轮 `USER_INPUT` 之前；不进系统帧、**不写入 `ConversationStore`**（D72）。**线上**由网关折进首条 user 历史消息（首轮无 user turn 时折进 `input`）。

### 7.3 不落盘与不记录

- 不落盘：原始音频、声纹、简历/JD、凭证。
- 日志/证据只记：计数、类型、id、SHA-256、字符数、reason code；正文永不进日志（D117）。
- 记忆写入不产生任何网络请求；记忆注入仍受“会话在运行”这一唯一同意约束（D53）。

## 8. 安全、隐私与权限

### 8.1 上传与同意

- **零旋钮**（D53①）：没有会话级上传开关；用户点「开始」即唯一同意动作；会话运行期间，转写与其所在回合上下文可发往**所配置的模型服务**。
- 仍然不变：会话必须由用户显式开始；只发往所配置服务；日志只记计数/id；记忆写入零网络；不落盘原始音频/声纹/简历；不记录凭证。
- D33 的固定测试句只进手机 RAM；**该测试路径不上传文本或音频**；正常会话的上传按 D53（会话运行即允许），D53 优先。D35 的 16 kHz/mono/16 bit LE 是当前流的源参数，不等于已实测；旧的一次性 30 句授权已随 0.2 关闭，不再作为当前授权。

### 8.2 确认与风险分级

- 风险级别 `L0`–`L4`；`WhitelistActionPolicy`：天花板绝对、L3/L4 永不免确认、插件只能收紧（`requiresConfirmation`）。
- 确认窗口 120 s（D47）；确认必须可感知并弹在主屏（D48）；插件闸门是权威，宿主只展示/不结算。
- 人时不计入回合预算（D49）；等待确认期间回合 deadline 顺延，提示有效期同步顺延。

### 8.3 权限与设备

- 通知：`POST_NOTIFICATIONS`；主屏弹窗：`SYSTEM_ALERT_WINDOW` + 后台拉起；全屏 intent：`USE_FULL_SCREEN_INTENT`；缺任一项按降级处理，不静默扩大。
- 无障碍：`EdithAccessibilityService`；Shizuku：`PrivilegedShell`/`EdithShellService`；"不可用就不广告"。
- 设备侧无人值守模拟一律走 `edith.phone.a11yprobe`（D95）；`adb -s 2696813b` 显式指定设备；禁用 `gradlew installDebug`；`input text` 对非 ASCII 必失败，中文只能走无障碍。
- 眼镜↔手机互联 100% 按官方 demo/样本（D41/D44）；厂商无此 API 时才允许平台官方 API，并在代码注释与证据中写明依据。
