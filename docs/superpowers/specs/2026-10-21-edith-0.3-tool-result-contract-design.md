## 1. 背景与问题

Phase 2.1 的自动视觉证明了“成功动作带观察”的价值，但 T7 暴露了更根本的问题：

- 失败的 `open`（`STATE_UNCHANGED`/`verified=false`）只回文本错误和前台/根包，没有图/vision；模型仍错误声称已回桌面。
- 这不是“少一张图”，而是**工具结果契约不完整**：成功路径各工具拼自己的 `detail`，失败路径经常只回 code；`ACTION_TIMEOUT`/`ACTION_TIMEOUT_UNCERTAIN`/`TOOL_THREW` 在 `AgentLoop`/`ToolRegistry` 层生成，工具没机会补观察。
- 模型无法稳定回答四件事：**动作是否执行/生效？现在屏幕是什么？还有没有未知/部分副作用？下一步需要的事实是什么？**

Phase 2.2 的目标：**任何工具、任何执行状态的结果，都能让模型据此判断下一步**；图片只是观察的一部分。

## 2. 当前代码事实与缺口

| 事实/路径 | 当前行为 | 缺口 |
|---|---|---|
| `ActionResult` | `outcome/detail/fingerprint/stateChanging/images/nonPersistent` | 无统一 execution/observation 字段；detail 为各工具字符串 |
| `ToolResult` | `payload` 字符串 + images/fingerprint/stateChanging/nonPersistent | 失败经 `"Failed: "`/`"Refused: "` 前缀；无结构化执行事实 |
| `AgentLoop` timeout | `ToolResult.error(call.id, ACTION_TIMEOUT)` + 固定 note | 无当前屏幕/图/前台；无法判断动作是否生效 |
| `AgentLoop` uncertain | `ACTION_TIMEOUT_UNCERTAIN` + note，run 终止 | 无部分执行事实、无观察、无 `applied=unknown` |
| `ToolRegistry` throw | `TOOL_THREW`，仅 code | 无观察、无“可能已产生副作用” |
| policy/确认拒绝/超时 | `ToolResult.error(call.id, code)` | 无 `applied=false`、无当前观察 |
| `open` verified 成功 | 图 + foreground/root/verified | 成功路径信息相对完整 |
| `open` 失败/alreadyForeground/ambiguous/appNotFound/channelUnavailable/invalid URL | 文本错误/短路 | 无观察；失败无图/vision |
| `device.act` 参数/kind/timeout 拒绝 | `refused(code)` | 无观察、无 applied=false |
| `device.observe` invalid include/provider-less | code/旧投影 | 无当前观察 |
| `device.status/wait` 失败 | 文本/投影 | 无图/vision；成功按范围不自动图 |
| `device.screenshot` VISION_DISABLED/无 IMAGE profile | 拒绝 code | 无 `vision` 原因/观察 |
| `shell`/`dial` | 只有命令/通话结果 | 两者都可能改变前台/屏幕，但完全无调用后观察 |
| `notify_user`/`load_skill` | 插件结果 | 缺统一执行事实（如 accepted/applied 语义） |
| `Descriptor.observation` | 表示“返回 fingerprint，供进步检测” | 不是“屏幕观察”语义；`open` 为 false 但会改屏幕 |

**当前广告工具面**：`device`、`open`、`shell`、`dial`（宿主）+ `notify_user`、`load_skill`（插件）。Intent/Shizuku 后端动作不是当前主工具面；若未来广告，按同一契约处理。

## 3. 已确认的决策

1. **所有工具统一结果契约**；`device/open/shell/dial` 带调用后观察；`notify_user/load_skill` 只带执行事实，`observation=null`。
2. **所有状态覆盖**：done / refused / failed / timeout（已停止）/ uncertain（未确认停止）/ `TOOL_THREW` / 部分执行（scroll、accepted-but-no-effect）/ policy/确认拒绝或超时 / cancellation。
3. **图片边界**：
   - `device`/`open`/`shell`/`dial` 的屏幕读写结果（observe/act/scroll/open，含失败/超时/uncertain/alreadyForeground）尝试附图；
   - `device.status/wait` 成功只给文本观察，失败附图；
   - 纯参数拒绝只给观察文本 + `vision` 原因，不强制附图；
   - `open list`/`UNKNOWN_ACTION` 不是屏幕操作，不附图；仍带执行事实。
4. **uncertain** 做 best-effort 观察/截图，短 deadline；明确 `uncertain=true`、`applied=unknown`、`changed=unknown`；不把中途帧当稳定终态。
5. **只给事实，不给“下一步建议”**：不新增 `next=retry/reobserve` 之类提示；由模型根据事实自己判断。
6. **结构化字段 + adapter 统一渲染**：在 `ToolResult`/`ActionResult` 落结构化 execution/observation，不由各工具自拼字符串。
7. **成功也统一 envelope，替换现有 detail 字符串**：模型看到的所有工具结果形状一致。
8. **envelope 结构**：`{ execution, observation|null, data }`；`data` 保留工具特有 JSON，不再重复 observation 字段。
9. **隐私**：observation/data 内容只在当轮模型请求；失败图同 `nonPersistent`/C2；日志/证据只记 code/计数。
10. **预算**：失败图同样计入 `ImageBudget`/`IMAGE_KEEP`；T7/T6 实测是否触发淘汰/超预算。
11. **验收**：T7 重跑看失败 open 是否能纠正；T6 回归；不重跑 0.25 冻结 27 行。

## 4. 结果 envelope（模型可见）

建议所有工具结果统一为：

```json
{
  "execution": {
    "outcome": "done|refused|failed|timeout|uncertain|cancelled",
    "code": "STATE_UNCHANGED",
    "message": "the launch command succeeded but the request is not verified in front",
    "recoverable": true,
    "accepted": true,
    "applied": null,
    "verified": false,
    "changed": null,
    "uncertain": false,
    "partial": false
  },
  "observation": {
    "snapshotId": "…",
    "capturedAtEpochMillis": 0,
    "foreground": {"package": "com.miui.player", "activity": "…"},
    "rootPackage": "com.miui.player",
    "coverage": "screen=ok notifications=truncated media=ok calendar=empty acoustic=ok clipboard=unavailable(background_restricted) vision=ok glasses=ok device=ok",
    "screen": "#n1 ... compact text ...",
    "truncated": false,
    "vision": "ok|disabled|unavailable(reason)|not_requested"
  },
  "data": {
    "…": "工具特有字段（apps/shell stdout/dial number 等）"
  }
}
```

- `execution.applied/verified/changed` 用 `true|false|null`；`null` 明确表示 unknown，不允许用 false 冒充未生效。
- `observation` 对纯工具为 `null`；`status/wait` 成功有 observation 但 `vision=not_requested`。
- 图片仍通过既有 `ToolResult.images`/`ImageRef` 通道；`observation.vision` 说明图片是否可用，不内联 bytes。
- `data` 不含 observation 字段；工具原有 detail 中属于观察的内容迁移到 observation，避免模型重复读/两份事实不一致。
- 取消（cancelled）如果模型不会再继续，则不产生模型请求结果；仍记录执行事实供审计。若未来向模型返回，使用同一 envelope。

## 5. 执行事实（ToolExecution）

字段：

| 字段 | 语义 |
|---|---|
| `outcome` | `done/refused/failed/timeout/uncertain/cancelled`；比现有 `ok` 更细 |
| `code` | 稳定机器码（如 `STATE_UNCHANGED`/`ACTION_TIMEOUT_UNCERTAIN`/`TOOL_THREW`） |
| `message` | 稳定人类可读原因；不含用户内容 |
| `recoverable` | 是否值得重试/换方式 |
| `accepted` | 平台/工具是否受理；`null` 表示未知 |
| `applied` | 是否实际生效；`null` 表示未知（uncertain/超时/部分执行） |
| `verified` | 是否经独立证据验证（如 open 前台+根） |
| `changed` | 是否改变屏幕/状态；`null` 未知 |
| `uncertain` | 工具是否可能仍在执行/有未知副作用 |
| `partial` | 是否已知部分完成（scroll 部分、accepted-no-effect） |

规则：
- 任何失败/超时/异常都不得把 `applied`/`changed` 默认写成 false；未知就 null。
- `uncertain=true` 时 `applied=null`、`changed=null`，并附 best-effort observation（可为 null+原因）。
- `TOOL_THREW` 必须有 `uncertain=true` 或明确“无副作用证据”，不能只回 code。
- 参数/策略拒绝：`accepted=false`、`applied=false`（动作未派发）、`verified=null`；若有观察，附当前屏幕。
- `done` 也必须有 `applied/verified/changed` 的明确值，不再依赖 detail 文本。

## 6. 调用后观察（ToolObservation）

字段：

- `snapshotId`、`capturedAtEpochMillis`
- `foreground`（package/activity）、`rootPackage`
- `coverage`（九 token，沿用 Phase 2 语义）
- `screen`（compact text；不写 bounds）
- `truncated`
- `vision`（`ok|disabled|unavailable(reason)|not_requested`）

规则：
- 屏幕工具（device/open/shell/dial）每次结果尽量给出 observation；拿不到时 observation 仍应存在但 `screen=null`/`vision=unavailable(reason)`，或者显式 `observation=null` + reason（不能静默）。
- `device.observe/act` 用现有 compact snapshot；`open/shell/dial` 用同一 host observation 源。
- `status/wait` 成功：observation 文本 + `vision=not_requested`；失败：尝试图。
- 失败图必须复用 `PerceptionProvider.screenshot()` 的 gate（用户开关 + profile IMAGE + 当前 revision `IMAGE_REQUEST=Verified`）；不可截图时 `vision=disabled/unavailable`。
- `uncertain` 的观察标注“可能中途”，不做稳定承诺；短 deadline（建议 250ms，可配置；未实测）。
- observation 内容一律 `nonPersistent`，不得进 `ConversationStore`/`AgentRun.transcript`/log/evidence；转录脱敏沿用 C2。
- `data` 不复述 observation；模型先读 execution/observation 再看 data。

## 7. 失败/超时/异常补齐机制

1. **工具层失败**（device/open/shell/dial 内部返回 Refused/Failed）：工具在返回前 best-effort 调 observation 源（含图，按图片边界），填 execution/observation；不改 outcome。
2. **参数/策略拒绝**：不执行动作；填 `accepted=false/applied=false`，附当前 observation 文本（参数拒绝不强制图）。
3. **AgentLoop timeout（confirmed stop）**：取消并等待停止后，通过注入的 failure observer 做一次短 deadline observation；`outcome=timeout`、`uncertain=false`、`applied` 按已知证据；无证据则 null。
4. **AgentLoop timeout uncertain（未停止）**：不做第二次等待；best-effort observation（可能中途），`outcome=uncertain`、`uncertain=true`、`applied/changed=null`；run 终止，不再执行后续写。
5. **ToolRegistry `TOOL_THREW`**：异常发生点未知；标记 `outcome=uncertain`（或 failed+uncertain），补 observation best-effort；不能静默当作无副作用。
6. **policy/确认拒绝/超时**：`outcome=refused`/`failed`，`accepted=false/applied=false`，补当前 observation 文本；图按屏幕工具失败规则。
7. **部分执行**（scroll_to_text 中途、accepted-but-no-effect）：`partial=true`/`changed=false`（有证据时），observation 为最终已知屏；不确定则 null。
8. **failure observer 的注入**：`ToolRegistry`/`AgentLoop` 通过一个 host-neutral `ObservationSource`（或 `ToolResultObserver`）拿 observation；JVM 用 fake；无源时返回 `observation=null` + reason，不阻塞、不伪造。
9. **deadline**：timeout/uncertain 的观察有独立短 deadline；超时则 `observation=null`/`vision=unavailable("observation_timeout")`。

## 8. 迁移与兼容

- `ToolResult`/`ActionResult` 增加结构化 `execution`/`observation`；`payload` 由 adapter 统一序列化 envelope；现有 detail 字符串迁移进 `data`，不保留 `"Failed: "`/`"Refused: "` 前缀。
- 所有工具和 adapter 同步：OpenAI Chat Completions、DeepSeek Responses、任何测试/提示 golden。
- 旧工具结果 golden 会大量变化；这是有意的破坏性契约变更（0.3 内），不是“兼容旧 detail”。
- `nonPersistent` 判定扩展：observation 存在即 nonPersistent；纯 execution facts 可持久化；data 含内容时仍按工具标记。
- 图片仍走 `ToolOutput.images`；`TurnTrimmer`/`ImageBudget` 不改语义，只新增失败图计数。
- `ActionDescriptor.observation` 继续只表示 fingerprint/进步检测；新增/明确的屏幕观察由工具集合（device/open/shell/dial）决定，不再复用该字段语义。

## 10. 风险与非目标

**风险**
- 成功 envelope 全替换：大量 golden/prompt/测试变化，模型行为可能短期波动；迁移成本最高。
- 失败图/每次 observation：延迟、图片 token、artifact 存储、`IMAGE_KEEP=3` 淘汰；T7/T6 需实测。
- uncertain 观察与仍在执行的工具竞争：只能 best-effort，不能保证稳定；必须诚实标 unknown。
- shell/dial 观察可能带来隐私/体积问题；C2、deadline、截断必须覆盖。
- `TOOL_THREW` 的 observation 可能拿不到；无源时必须显式 null+reason，不能编。
- 300ms 级观察 deadline 是建议值，未实测；实现计划需给测试与设备读数。

**非目标**
- 不给模型“下一步建议”（只给事实）。
- 不启动 Phase 3/4；不改 D53 同意口径。
- 不重跑 0.25 冻结 27 行；旧判词不变。
- 不新增图片格式/依赖；WebP、按像素预算等仍推迟。
- 不把 `notify_user/load_skill` 变成屏幕观察工具。
