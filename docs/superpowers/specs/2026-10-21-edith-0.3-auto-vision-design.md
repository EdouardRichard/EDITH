## 1. 背景与目标

Phase 2 已具备视觉开关、截图工具和 `ImageRef` 链路，但**默认只在显式 `device.screenshot` 时截图**。Phase 2 设备语料中：

- T7 失败：模型播放了《七里香》而非《稻香》，最终 `playing=false`；T7/T2/T4 的 `P3_METRIC images=0`。
- T6 `NotMeasured`：debug 页面服务被 harness 的 cold start 杀死，模型从未看到页面。
- 视觉覆盖率不足以支持“模型对当前屏幕做出判断”。

本变更的目标：

1. 每次**屏幕操作**（observe、act、open 成功）返回一张当前屏幕的压缩视觉，让模型在判断前/动作后都能看到真实界面。
2. 保留既有 `ImageRef`/`ActionResult.images`/`ToolOutput.images` 路径，不新增图片通道。
3. 用 Android 内置能力控制图片尺寸与编码，**不引入 Gradle 依赖**。
4. 重跑 Phase 2 未通过的 T7/T6，按真实结果记录，不承诺通过。

## 3. 范围与非目标

### 3.1 范围内
- `device.observe`：当 `include` 含 `screen`（默认含）时，返回 a11y 快照 + 一张压缩截图。
- `device.act`：包括 `scroll_to_text`；动作派发后返回一张压缩截图；stale/refused 的 act 也返回当前屏幕截图（动作未派发，但屏幕事实可用）。
- `open`：**仅 `verified=true` 成功后**返回一张压缩截图；ambiguous/not-found/failed 不截图。
- `device.screenshot`：保留显式工具，仍返回一张图，但现在走压缩。
- 截图压缩：按原生比例、宽≤720、长边≤1600、不放大、不裁切、JPEG q80。
- 自动截图的 `vision` 结果记录在工具 `data.vision`：`ok` / `disabled` / `unavailable(no_image_profile)` / `unavailable(reason)`。
- T7/T6 重跑与证据；T6 的 harness 页面服务修复（测试工具，不是产品功能）。

### 3.2 非目标
- `device.status`、`device.wait` 不自动附图（按业主选择）。
- 不实现 proactive 回合自动视觉（Phase 3）。
- 不引入 WebP/第三方图片库（首轮）；不引入 VLM。
- 不把 `ImageBudget.UNITS_PER_IMAGE` 改成按像素计费（首轮保持 1024；若 T7/T6 被预算/`IMAGE_KEEP` 限制，另立变更）。
- 不改 D53 同意口径：会话运行即允许把截图发给所配置的模型服务；设置页现有风险说明继续生效。
- 不把 T7/T6 的成功判据改成“有图即通过”；视觉只是输入，行为仍需按原判据测量。

## 4. 行为设计

### 4.1 `device.observe`
1. `perception.refresh()`（真实重读，C1 已有）。
2. 构建 `PerceptionSnapshot`（a11y 紧凑元素、coverage、前台等）。
3. 若 `include` 含 `screen`：调用 `perception.screenshot()`：
   - `Image` ⇒ 把 `ImageRef` 加入 `ActionResult.images`；`data.vision=ok`。
   - `Disabled` ⇒ 不附图；`data.vision=disabled`。
   - `Unavailable(reason)` ⇒ 不附图；`data.vision=unavailable(reason)`。
4. 操作本身仍按原 envelope 成功/失败；截图失败只降级视觉，不改变 `observe` 结果。

### 4.2 `device.act`
1. 保持现有 stale 预检查、动作派发、`afterAction()`、`changed` 语义不变。
2. 在结果组装前调用 `perception.screenshot()`：
   - 成功派发的 act：截取动作后的当前屏幕。
   - stale/refused 的 act：截取当前屏幕，供模型重新定位；`STALE_REF` 语义不变。
3. 图片加入 `ActionResult.images`，`data.vision` 记录状态；`nonPersistent=true`（C2 已使所有 DeviceTool 内容结果不落 store）。
4. `scroll_to_text` 内部可能多次滚动；**只在最终结果附一张图**，不逐步截图。

### 4.3 `open`
1. 保持现有 `resolvedPackage/foreground/rootPackage/verified` 判据。
2. `verified=true` 且 result 成功时，调用注入的 `capture()`：
   - `Image` ⇒ 附加 `ImageRef`，`data.vision=ok`，`ActionResult.nonPersistent=true`（截图内容不落 store）。
   - `Disabled`/`Unavailable(reason)` ⇒ 不附图，`data.vision` 记录原因；`open` 仍可 Done。
3. `verified=false`/`STATE_UNCHANGED` 不截图。

### 4.4 不自动附图
- `device.status`、`device.wait`、`device.observe` 中 `include` 不含 `screen` 的调用。
- 显式 `device.screenshot` 仍可单独调用；它同样走压缩。

## 5. 截图与压缩

### 5.1 尺寸
纯函数（建议放在 `phone-app/app/.../actions/a11y/ScreenshotSizing.kt`，JVM 可测）：

```kotlin
fun targetSize(width: Int, height: Int, maxWidth: Int = 720, maxLongEdge: Int = 1600): Pair<Int, Int>
```

- `scale = min(1.0, maxWidth.toDouble()/width, maxLongEdge.toDouble()/height)`
- 宽高同乘 `scale`，向下取整，最小 1；**不放大、不裁切、不改变比例**。
- 设备比例各自保留：1080×2400 → 720×1600；1200×2000 → 720×1200；2000×1500 → 720×540；400×800 → 400×800。

### 5.2 编码
- 在 `EdithAccessibilityService.screenshot()` 的 `ARGB_8888` 拷贝之后：
  - 若目标尺寸更小：`Bitmap.createScaledBitmap(software, tw, th, true)`。
  - `Bitmap.compress(Bitmap.CompressFormat.JPEG, 80, output)`。
  - 返回 `Screenshot(bytes, "image/jpeg", tw, th)`。
- 回收中间 bitmap，避免每次操作泄漏原图/缩放图。
- 所有截图路径（自动 observe/act、open、显式 screenshot）都走同一编码。

### 5.3 依赖结论
- **不需要新增 Gradle 依赖**：`Bitmap.createScaledBitmap`、`Bitmap.compress(JPEG)` 都是 Android 平台 API。
- WebP（`WEBP_LOSSY`，API 30+）也是内置，但需要先验证所配模型服务接受 `image/webp` 且 T6 小字可读；不在首轮。
- 不引入 Coil/Glide/libwebp；它们解决的是加载/缓存/解码，不是这里的编码问题。

### 5.4 预算与保留
- `ImageBudget.UNITS_PER_IMAGE` 首轮保持 1024。
- `TurnTrimmer` 的 `IMAGE_KEEP=3` 不变；自动附图可能让旧图更早被淘汰，这是预期行为，需在 T7/T6 证据中记录 `P3_METRIC images`、`P3_CONTEXT trim elidedImages` 或 `droppedTurns`。
- 图片只进当轮模型请求；C2 的 `nonPersistent` 使 `AgentRun.transcript`/`ConversationStore` 不含正文和 `ImageRef`。

## 6. 门控、隐私与失败语义

- **自动截图门控**：`visionEnabled`（用户设置）**且** 当前选择 profile 的 `inputs` 含 `IMAGE` **且** 该 profile 当前 revision 的最近一次 `IMAGE_REQUEST` 验证为 `Verified`（与 `CapabilityGate` 同规则：同 revision、按 `testedAtEpochMillis` 取最新、同 index；旧 revision/失败/未验证均 false）。仅声明 `IMAGE` 不够。
  - 用户关闭 ⇒ `Disabled`，`data.vision=disabled`，不截图。
  - profile 无 `IMAGE` ⇒ `Unavailable("no_image_profile")`，`data.vision=unavailable(no_image_profile)`，不截图；避免 `CapabilityGate` 拒绝含图请求。
  - 组合 lambda 由 `HostCompositionRoot` 按**与回合配置相同的来源**解析：`AndroidProfileRepository.selections()[smart plugin id]` 优先，缺失/读取失败时回退 `smartWiring.selectedProfile()`；不得只用 `smartWiring.selectedProfile()`（它是装配时 settings blob 的选择，可能不是用户当前选中的 profile）。解析结果必须声明 `IMAGE` 才允许自动截图；传给 provider、DeviceTool、OpenTool。provider 仍保留两个结果分支。
  - 显式 `device.screenshot` 不在本次“自动附图”门控改动内：它仍只受用户开关约束；profile 无 `IMAGE` 时仍可能被 `CapabilityGate` 拒绝。这是已知的 Phase 2 残留，记录在 spec/ACCEPTANCE 的未测/后续项，不本次顺手修。
- **隐私**：截图只进模型请求和 artifact store，不进 logcat/evidence/docs；设置页现有“感知截图（图片随请求发送）”风险说明继续适用；D53 的“会话运行即同意”不变。
- **失败**：截图失败/超时/服务不绑定 ⇒ 该次操作无图，`data.vision=unavailable(reason)`；操作结果与 `changed` 语义不因截图失败而改变。
- **产物**：沿用现有 artifact store；压缩后的 width/height/mime 进入 `ImageRef`；不落原始截图到仓库。

## 9. 风险与未验证项

1. **延迟/成本**：每次 observe/act 多一次平台截图；估算单次约 100–300 ms（未实测），T7/T6 的步数会放大。图片增加模型侧 token/上传量。
2. **预算**：本地 `ImageBudget` 仍是 1024/图；`IMAGE_KEEP=3` 可能淘汰旧图。首轮不按像素折算预算；若 T7/T6 被预算限制，另立变更。
3. **模型分心**：每步图片可能让模型更依赖视觉、增加推理时间；也可能改善 T7/T6，需实测。
4. **T6 harness**：页面服务修复是本地测试工具；若启动仍失败，T6 记 `NotMeasured`，不伪造通过。
5. **T7 行为**：自动视觉不保证模型选对曲目；仍按媒体状态判据。
6. **WebP/外部库**：未采用；后续若模型服务支持且实测可读，再评估。
7. **设备/最终构建**：本变更是 Phase 2.1；设备证据对应新构建，不能沿用 `d4a749e0` 的读数。
