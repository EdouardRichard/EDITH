## 1. 背景与当前事实

### 1.1 业主 2026-10-29 的反馈

0.4 的脱离眼镜模式 Agent 能力可用，但用户交互很弱：**AI 回复用户完全感知不到**。0.5 要求：

1. 脱离眼镜模式重命名为「纯手机模型」，设置开关也用这个名字。
2. 开启纯手机模型后，桌面出现可拖动、可依附边框的半透明悬浮球；长按进入 ASR；Agent 循环时用半透明消息气泡展示 AI 回复与过程提示；工具调用信息与眼镜端一致；旧消息淡化后消失。
3. 修复「语音朗读」无效。
4. 样式评审后的追加要求：
   - 用 Android 通用组件与系统默认字体/颜色；
   - 悬浮球背景用 EDITH 应用图标；
   - 悬浮球与气泡都半透明，且**透明度可调**；
   - 旧消息是独立消息框，整体比新消息淡化，2s 后自动消失；旧消息**按固定比例在气泡透明度上再淡化**，不单独配置；
   - 保留悬浮球外围的动态光影线条，用于表示 AI 思考状态。

### 1.2 当前代码事实（0.5 设计依据）

- **模式与持久化**：`SmartSettings.glassesDetached`（`phone-app/.../host/SmartSettings.kt:108`）是最后一个字段，默认 false；`DetachGate` 是唯一写者（`DetachGate.kt`），写前按 `load → copy → save` 保留其它设置；`DetachUi` 持有所有设置页文案。
- **设置页**：`SmartToggles`（`ui/PhoneScreen.kt:846`）绘制模式开关、主动辅助、语音朗读；模式开关直接调 `DetachGate.set`，语音朗读调 `HostCompositionRoot.setSpeechEnabled`；悬浮窗授权入口在 `PermissionEntries`（`PhoneScreen.kt:957`）。
- **手机端显示**：脱离模式下 `PhoneHintDevice`（`app/PhoneHintDevice.kt`）只 ack `Displayed`，不写回答行；回答由插件的 `publishAssistantFinal` 写入 `ConversationLog`，手机端「对话上下文记录」页签读取它。
- **对话事件**：插件通过 `ConversationDisplay`（`common/contracts/plugin-api/.../ConversationDisplay.kt`）发出 `userFinal`、`assistantPartial`、`assistantFinal`、`assistantNotice`、`toolStatus`、`state`、`showIdle` 等；生产实现 `ConversationWireDisplay`（`bridge/ConversationWireDisplay.kt`）把官方命令转发给 CXR，把文本写入 `ConversationLog`；`toolStatus` 目前**只发给眼镜**，手机端没有工具行数据。
- **最终回答的朗读**：插件 assembler 的 `onEmit = { text -> emit(it, text) }`（`SmartAssistantPlugin.kt:2931`）没有传 `optionalSpeech`；`emit` 只有在 `optionalSpeech != null` 时携带 `SpeechRequest`（`:5404`/`:5443`）。全链路只有 `notify_user(voice/both)`（`NotifyUser.kt:56-59`）会请求朗读。因此「语音朗读」开着也不会念最终回答。
- **朗读开关的运行期行为**：`HostCompositionRoot` 只在组装时按 `settings.speechEnabled` 创建 `AndroidSpeechPlayer`（`:3820-3827`），把它固定传给 `CxrHostEnvironment(speech = ...)`；`setSpeechEnabled` 只写 `speechOn` 与持久化（`:498-504`）。运行中打开开关要重启 App 才生效；关闭也不会立刻停掉已有 player。
- **听写**：`HostCompositionRoot.startDictation()`（`:1769`）要求 `SessionState.Ready/Listening`，使用 `DictationController` 重定向 `SpeechPipeline`；final 通过 `dictationUi.final` 交给助手页追加到草稿，**不发送**。停止/取消/15s 超时语义见 `DictationController.kt`。
- **悬浮窗能力**：`SYSTEM_ALERT_WINDOW` 已在 manifest 声明，`Settings.canDrawOverlays` 已用于确认弹窗；目前没有任何 `WindowManager` 悬浮窗代码。`EdithAccessibilityService` 存在，但本设计不依赖它。
- **UI 技术栈**：手机 App 全量 Compose（Material3，`MainActivity` 用 `lightColorScheme(primary=0xFF126B50, secondary=0xFF405B79)`）；**没有** Material Components Views 依赖。应用图标是自适应图标（白底 + `logo_edith` 抠图前景，`mipmap-*/ic_launcher*`）。
- **设备/构建**：K40 `2696813b`（Android 13 / API 33）与眼镜 `1901092544027662` 连接；设备已装有 0.4 并完成模型 materialize。无人值守操作规则见 `AGENTS.md`：所有人工操作模拟走 `edith.phone.a11yprobe`，禁止 `adb shell input`；调试广播只作为**有标注的仪器**，不得冒充 UI 验证。

### 1.3 已知限制与不在本设计静默改写的事实

- `PhoneHintDevice` 的 ack 契约、`ConversationLog` 的替换/逐出规则、`OutputArbiter` 的朗读生命周期都是 0.4 已批准行为；0.5 只消费它们，不改它们的语义，除非本节明确。
- 悬浮球是系统悬浮窗，会出现在所有应用之上；它需要「显示在其他应用上层」权限和前台服务常驻通知。这不是纯 App 内 UI。
- 手机端「语音朗读」的默认值在 0.4 是关闭；0.5 在纯手机模型下按下文 D213 处理。

## 2. 范围、非目标与完成判据

### 2.1 本版范围

1. **重命名**：所有用户可见文案、设置文案、README/文档从「脱离眼镜」改为「纯手机模型」；内部标识与持久化 key 不变。
2. **悬浮球**：系统悬浮窗；EDITH 应用图标；半透明且可调；可拖动；松手吸附最近左右边框并隐藏一半；长按显示麦克风并进入 ASR；外围动态光影线条表示 AI 思考；点击打开 EDITH。
3. **消息气泡**：系统 Material 默认组件/字体/颜色；半透明且可调；每条消息独立气泡；新消息满不透明（文字默认色），旧消息整体淡化（固定比例 × 配置的气泡透明度）并在被替代 2s 后消失；工具调用信息（标签、运行/完成）与眼镜端一致；语音朗读时显示系统说话/播放图标。
4. **语音朗读修复**：最终回答按开关请求朗读；开关运行中即时生效；纯手机模型下默认开启（仅当用户从未显式设置过）。
5. **听写直发**：悬浮球长按的识别结果直接作为用户消息发送给 Agent（`requestTypedMessage`），不再追加到草稿。
6. **设置**：悬浮球透明度、气泡透明度两个 0–100 设置；旧消息淡化比例固定、不暴露。
7. **验证与文档**：JVM 全量门禁、K40 真机（含眼镜回归）证据、README/STATUS 更新。

### 2.2 非目标（0.5 不做）

- 不改 CXR 协议、眼镜端 APK、眼镜面板样式或官方对话行为。
- 不重做 0.4 的脱离模式采音/模型/锁屏唤醒；不重开 0.4 判词。
- 不做悬浮球内的完整对话历史、滚动、富文本/Markdown、图片；完整内容仍在 App 的「对话上下文记录」。
- 不做悬浮球/气泡的拖拽位置持久化（服务重启回到默认右侧）；不加自定义字体、主题色或自绘绿色文字。
- 不新增旧消息的独立透明度配置；不把旧消息做成可点/可展开。
- 不做多窗口/分屏/平板适配；以 K40 竖屏为准。
- 不推送、不打 tag、不合并到 `dev`/`main`（除非业主另行授权）。

### 2.3 完成判据（DoD）

- 用户可见处不再出现「脱离眼镜」；设置开关标题严格为「纯手机模型」。
- 开启纯手机模型（已授予悬浮窗权限）后，桌面出现 EDITH 图标悬浮球；关闭模式或撤权后消失；重启 App 后模式仍生效。
- 悬浮球可拖动，松手吸附左右边框并隐藏一半；长按显示麦克风并进入 ASR；识别 final 直接发给 Agent；无会话时给出可见提示。
- Agent 循环时气泡出现；工具运行/完成各有一条独立消息信息（同一工具行内更新，不新增重复消息）；旧消息在新消息出现后整体淡化，2s 后消失；气泡/悬浮球透明度按设置实时变化；思考时球外光影出现，回答后消失/减弱。
- 纯手机模型下，「语音朗读」开启时最终回答被朗读（logcat `P5_SPEECH state=start/end` 与 `dumpsys audio` 播放轨道），关闭时立即停止并可再次开启，无需重启；眼镜模式的最终回答保持 HUD-only（D213）。
- JVM 全量门禁 0 failures / 0 errors；设备证据与未测项如实记录；README/STATUS 收口；不 push/tag/merge。

## 3. 业主决策（D209–D217）

- **D209 重命名**：中文名「纯手机模型」。设置开关标题就是「纯手机模型」；摘要说明不连眼镜、只用手机麦克风/屏幕/悬浮球。内部标识、JSON key、类名、测试名保持不变；只改用户可见文案与文档。若业主本意是「纯手机模式」，一次全量替换即可。
- **D210 悬浮球**：背景使用 EDITH 应用图标；圆形；半透明；透明度可调（默认 82%）；保留球外动态光影线条表示 AI 思考；可拖动、吸附左右边框、隐藏一半；长按显示麦克风并进入 ASR；点击打开 EDITH。
- **D211 气泡样式**：使用系统 Material 默认组件、字体、文字颜色；半透明；透明度可调（默认 75%）；每条消息独立气泡；新消息文字保持默认不透明色，卡片背景用配置透明度；旧消息整体（卡片+文字）按固定比例 `0.42` 乘配置透明度再淡化；被替代 2s 后消失；不单独配置旧消息透明度。
- **D212 长按 ASR**：识别 final 直接作为用户消息发送（`requestTypedMessage`），不再追加到草稿；无运行中会话时，长按只显示「会话未开始」提示，点击球打开 App。
- **D213 语音朗读**：运行期开关两种模式都即时生效（创建/释放 player、能力同步、停止在播）；**纯手机模型下**最终回答在开关开启且 player 可用时请求朗读（手机端没有 HUD 可读，这是 0.5 修复的直接目标）；眼镜模式保持 0.4 的「最终回答上 HUD、不额外朗读」，`notify_user(voice/both)` 仍按原规则朗读——把眼镜模式的回合完成语义一并改成等 TTS 结束是另一项行为变更，不在本次手机模型修复范围内。纯手机模型下若用户从未显式设置过语音朗读，默认开启一次；用户显式关闭后任何路径不得自动打开（D53②同形规则）。
- **D214 生命周期**：纯手机模型开启且悬浮窗权限已授予时，悬浮球常驻（桌面与 App 前台）；前台服务为 `specialUse` 类型，带低优先级常驻通知；权限缺失时模式仍保存，但球不出现，设置页显示授权入口；关闭模式或撤权后停止服务与窗口。
- **D215 尾巴**：只有紧邻悬浮球的最新一条气泡带右下角尾巴；旧消息是同样圆角/颜色的独立卡片但不再重复画尾巴（避免尾巴指向下一条消息）。球在左边缘时整体水平镜像。
- **D216 气泡容量**：最多同时 3 条（最新 + 最多两条旧消息）；新消息到达时若超过 3 条，最旧一条立即加速淡出；气泡最大宽度为屏宽 72%，整栈最大高度为屏高 45%；超长回答最多显示 8 行并以省略号结尾，全文在 App 记录。
- **D217 气泡收起**：回合 `showIdle` 后如无新消息，3s 后整栈淡出；任何新消息取消收起；点悬浮球打开 App（不通过气泡点击，气泡不可触摸）。

## 5. 悬浮球设计

### 5.1 组件与窗口

- 新增 `com.sheen.rokid.phone.overlay` 包（app 模块）：
  - `PhoneOnlyOverlayService`：`LifecycleService`（或 `Service` + 自建 lifecycle），前台服务 `specialUse`；拥有两个窗口、一个协程作用域、一个 `OverlayLifecycleOwner`。
  - `PhoneOnlyBallWindow`：`TYPE_APPLICATION_OVERLAY`，`FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCH_MODAL | FLAG_LAYOUT_NO_LIMITS`，正方形约 3r（含光影），ComposeView 绘制球+光带；触摸只在这个窗口。
  - `PhoneOnlyBubbleWindow`：`TYPE_APPLICATION_OVERLAY`，`FLAG_NOT_FOCUSABLE | FLAG_NOT_TOUCHABLE | FLAG_LAYOUT_IN_SCREEN`，全屏透明，ComposeView 绘制消息栈；**不可触摸**，不阻挡下层应用。
  - `PhoneOnlyOverlayController`：纯 Kotlin 的状态/手势/布局决策（JVM 测试）；`BallGestureMachine`、`BallPlacement`、`BubbleStackModel` 等纯类。
- 悬浮球图标：`Image(painterResource(R.mipmap.ic_launcher_foreground))` 白色圆底 + 圆形裁切；整体 `graphicsLayer { alpha = ballOpacity }`；系统阴影用 `Modifier.shadow`。
- 光影：`Canvas` + `rememberInfiniteTransition` 的旋转两/三段弧 + 呼吸 alpha；只在 AI 思考/工具执行时显示，回答期间减弱，待机为 0；颜色使用 EDITH 绿（`0xFF40FF5E` 附近），只作用于光影，不作用于文字/字体。
- 颜色/字体：球内麦克风用 `Icons.Default.Mic`；透明度和颜色由主题/设置给出；**不新增自定义字体**。

### 5.2 生命周期

- 开启条件的唯一事实：`detachGate.enabled == true && Settings.canDrawOverlays(context)`，且模型已 ready（`ModelStartGate`）。
- 启动点：
  - `DetachGate.onModeChanged(true)` → 生产 `HostCompositionRoot` 回调 → `ContextCompat.startForegroundService(PhoneOnlyOverlayService)`；
  - `MainActivity.onResume`：若模式已开且服务未运行，尝试启动（用户在前台；不后台自启）；
  - `onModeChanged(false)` → `stopService`；服务 `onDestroy` 移除两个窗口、停止通知。
- 权限缺失：`DetachGate.set` 仍按 0.4 语义保存模式；服务启动时若 `canDrawOverlays=false`，不添加窗口、记录 `P5_PHONE_ONLY state=no_permission`，并停止前台服务；设置页在开关下显示「需要悬浮窗权限」与授权按钮（复用 `PermissionEntries` 的入口）。
- 前台服务：`specialUse`（API 34+），API 28–33 传 0；通知 channel 低重要性、静默、常驻，文案「纯手机模型 · 悬浮球正在运行」，contentIntent 打开 MainActivity。服务只在前台/可见时启动；进程被杀后不自动恢复悬浮球（下次打开 App 时恢复），文档写明。
- 会话未运行：球仍在；长按显示一条 Material 提示气泡「会话未开始，点悬浮球打开 EDITH」；点击球打开 App。
- 会话运行中：长按 → 球内麦克风 + 白色脉冲 → `startDictation(BALL)`；松手 → `stopDictation()`；final 直发（§7.2）；取消/超时 → 气泡显示「没有听到内容」/「识别失败」，不发送。

### 5.3 手势与位置

- 触摸窗口中心为球心；拖动时窗口 `x/y` 跟随手指（服务在主线程 `updateViewLayout`），球心限制在屏幕内（允许吸附半隐藏）。
- 按下：球轻微放大（1.0→1.08），0.5s 内未移动且未松手 → 长按：滑动到完整可见（`cx = screenW - r - 8` 或镜像），显示麦克风并启动 ASR；松手结束。
- 移动超过 touch slop → 拖动模式，取消长按计时；松手后按 `BallPlacement.snap()` 吸附最近的左右边缘（`cx = edge ± r/2`，即隐藏一半），垂直位置限制在状态栏/导航栏之间；吸附用 250–350ms 的缓动。
- 短按（未拖动、未长按）→ 打开 MainActivity（`FLAG_ACTIVITY_NEW_TASK`）。
- 位置只在内存中；默认右侧、垂直 62.5%；服务重启回默认。`BallPlacement` 纯函数含：最近边缘、半隐藏 x、垂直 clamp、拖动阈值、吸附缓动值。

### 5.4 透明度

- 设置项 `ballOpacityPercent`：20–100，默认 82；只作用于球体（图标/圆底/阴影），光影保持其状态强度（避免思考提示被调没）；长按时球体可临时 0.9 以保持手感。
- 修改后立即作用于运行中的球（服务收集 `StateFlow`）；不需要重启 App/服务。

## 6. 消息气泡设计

### 6.1 组件与样式

- 用 Compose Material3 的 `Surface`/`Card`（系统组件）+ `MaterialTheme.typography.bodyMedium/bodyLarge` + `MaterialTheme.colorScheme.surface/onSurface/onSurfaceVariant`；不指定字体文件、字号（除 Material token）、文字颜色。
- 新消息卡片：`surface.copy(alpha = bubbleOpacityPercent/100)`、圆角 12dp、`shadowElevation = 3.dp`；文字 `onSurface` 全不透明；工具图标 `onSurfaceVariant`。
- 旧消息：对整张卡片（含文字）应用 `Modifier.alpha(0.42f * bubbleOpacityPercent/100)`；2s 后 `animateFloatAsState` 到 0 并移除。
- 尾巴：只有最新一条，右下角（球在左时左下角）一个约 12×14dp 的圆角小尾巴，颜色与卡片一致（含透明度）；旧卡片无尾巴。
- 工具行：Material 图标（运行中转圈/完成对勾）+ 与眼镜端相同的 `ToolLabelMap` 文案；不新增自定义绿色文字（D211 覆盖“样式一致”的字面理解；信息一致）。
- 语音朗读：回答气泡右上角显示系统 `Icons.Default.VolumeUp`（`onSurfaceVariant`），仅在该回答正在朗读时显示；不新增文字。

### 6.2 消息模型与轮换

- 消息类型：`User`、`Thinking`、`Tool(running/done, label)`、`Answer(text, speaking)`、`Notice(text)`。
- 每条消息独立卡片；新建时淡入 + 轻微上移（Material 默认时长 ~200ms）。
- 最新一条满不透明（文字默认色，卡片配置透明度）；被更新消息替代时，旧消息整体变为 `0.42 × 配置透明度`；从被替代时刻起 **2.0s** 后开始 250ms 淡出并移除。
- 同一工具行的 START/END 是**同一条消息原地更新**（转圈→对勾），不产生新旧轮换。
- `Thinking` 被第一条工具/回答替代；若回合在无回答下结束，`Thinking` 在 idle 后按 2s 规则消失。
- 最多 3 条；第 4 条到达时最旧一条立即淡出（200ms），不等待完整 2s；`BubbleStackModel` 纯类实现并测试。
- 回答流式：`assistantPartial` 更新当前回答消息文本（同一 hint/turn，不新建）；`assistantFinal` 落定；`assistantNotice` 新建一条独立消息。
- 回合结束（`showIdle`）后 3s 无新消息 → 整栈淡出；有新消息取消。气泡不可触摸，收起不依赖用户点击。

### 6.3 布局

- 气泡栈锚定在球上方：最新卡片右下角在球心左上（球在右侧）或左下角（球在左侧）；间距 8dp；整栈向上生长。
- 最大宽度 72% 屏宽；整栈最大高度 45% 屏高；超出时最新回答最多 8 行并省略号；旧消息不因新消息过长而被挤压。
- 球移动时气泡栈跟随（同一 `ballCx/ballCy` 状态）；不可触摸窗口全屏透明，避免位置测量问题。
- 系统字体缩放：使用 Material typography 的 sp，跟随系统；不做 px 固定。最大行数随屏高做 clamp，防止大字体溢出。

### 6.4 透明度

- `bubbleOpacityPercent`：30–100，默认 75；只作用于卡片背景（含尾巴），文字保持默认不透明；旧消息的整体 alpha 按 D211 计算。
- 修改后立即作用于运行中的气泡；滑块显示百分比，保存到设置；不需要重启。

## 7. 数据路径

### 7.1 气泡事件源

- 新增 app 内部接口（不改变 `ConversationDisplay` 公共契约）：
  ```kotlin
  interface PhoneBubbleFeed {
      fun onUserFinal(route, turnId, text)
      fun onThinking(route, turnId)
      fun onTool(route, turnId, phase, label)
      fun onAnswerPartial(route, turnId, hintId, text)
      fun onAnswerFinal(route, turnId, hintId, text)
      fun onNotice(route, text)
      fun onTurnIdle(route)
  }
  ```
- `ConversationWireDisplay` 在现有方法内转发（`userFinal`/`assistantPartial`/`assistantFinal`/`assistantNotice`/`toolStatus`/`showIdle`）；生产装配传入一个 `PhoneBubbleFeed`（`PhoneBubbleRepository`），测试传 fake。
- `PhoneBubbleRepository` 维护 `StateFlow<PhoneBubbleState>`（消息列表+状态），线程安全；UI 只在主线程读；JVM 测试覆盖 2s/3 条/流式/工具原地更新/幂等。
- 用户 final 到达时先产生 `User` 消息，并立即产生 `Thinking`（同一 turn）；第一条工具/回答替代 thinking。插件 `toolStatus` 也映射为 `Tool`；`state`/`showIdle` 只用于回合生命周期。
- 只处理 `AssistantRoute.WAKE`（纯手机模型没有主动辅助）；其它 route 忽略，避免把主动提示混进气泡。
- 事件字段只含计数/id/标签，日志不记回答正文。

### 7.2 悬浮球听写

- `HostCompositionRoot.startDictation(target)`：`COMPOSER`（默认）保持 0.4 行为；`BALL` 使用同一个 `DictationController`/pipeline，但 final 走 `requestTypedMessage(text)`，不写 `dictationUi.final`。
- `DictationUiState` 增加 `owner`（COMPOSER/BALL）；助手页只消费 `owner == COMPOSER` 的 final/状态；球只消费 `owner == BALL`。避免球在 App 前台时把文字塞进草稿。
- 球的长按在 `SessionState.Ready/Listening` 下才启动；`startDictation` 的拒绝码映射为气泡提示（无会话/权限/忙/无源/已关闭）。
- 发送结果：`Accepted` → 气泡显示用户消息并进入思考；`Busy/Blank/NoSession/Stale` → 气泡显示可读提示，不产生用户消息（或按实现保留最后一次 final 供重试？本版不重试）。
- 球听写期间，助手页若在前台，显示同一个「正在听写…」状态但只读；不改变 0.4 的手动听写链路。

### 7.3 眼镜回归

- 纯手机模型下不建 CXR；眼镜模式仍走原链路。气泡 feed 在两种模式都接收事件，但球/气泡只在纯手机模型显示；眼镜模式不改变 HUD。
- 眼镜模式回归：官方显示/工具行/唤醒/typed 输入仍由既有测试与设备检查覆盖；0.5 不改变 CXR 协议。

## 8. 语音朗读修复

### 8.1 根因（已定位）

1. 最终回答 emit 从不携带 `optionalSpeech`，所以只有 `notify_user(voice/both)` 会朗读；最终回答永远静音。
2. `语音朗读` 开关只在 App 组装时决定是否创建 player；运行中切换只写设置，不创建/释放 player，也不更新 `Capability.SpeechOutput`；必须重启 App 才生效。

### 8.2 修复

- **最终回答请求朗读（纯手机模型）**：插件 assembler 的 `onEmit` 改为 `emit(it, text, optionalSpeech = if (phoneOnly() && speechAvailable()) SpeechRequest() else null)`；`phoneOnly` 是 `SmartWiring` 传入的实时 `detachGate.enabled`，默认 false = 眼镜模式。`emit` 现有 gate 保持（`speechAvailable()` 为 false 时不请求）。记忆确认（`recordAsAnswer=false`）仍不朗读；`notify_user` 行为不变。回答朗读后，`ConversationCycle` 已按 `answerEmitSpeech` 等待 `SpeechFinished`，沿用；眼镜模式不进入该等待，保持 0.4 的 `Displayed` 结算。
- **回声半双工**：0.4 的 `EchoMuteWindow` 原本只包住脱离模式的唤醒应答（「我在」）。0.5 的最终回答也经同一窗口：`AndroidSpeechPlayer` 在 `onStart` 打开、在 `onDone/onError/cancel` 关闭，手机麦在可听区间内只收到静音帧。设备测试（K40）证实：修复前 ASR 会把回答自己的声音转成用户句并触发续聊循环（`P3_ASR final=true` 在 `P5_SPEECH` 播放区间内），修复后同一轮只有注入的用户句，播放结束后没有自听转写、没有下一轮自答。窗口看门狗从 5s 放宽到 120s（与 `SpeechFinished` 活性上界一致），否则长回答播到一半会解除静音。
- **运行期开关**：引入 `SpeechPlayerRouter : SpeechPlayer`（app 模块）：
  - 构造时持有 `AtomicReference<SpeechPlayer?>`；`play()` 委托给当前 player，没有时立即 `FAILED` 并返回 no-op handle；`stopCurrent()` 停当前并清空。
  - `CxrHostEnvironment` 的 `speech` 参数改为 router（非空），新增 `speechAvailable: () -> Boolean`，`availableCapabilities` 用它决定 `SpeechOutput`；`OutputArbiter` 仍拿 router，插件仍通过 `speechAvailable` gate。
  - `setSpeechEnabled(true)`：创建 `AndroidSpeechPlayer`（如果还没有），安装到 router，更新 `speechOn` 与 `speechPlayerHolder`，写设置；`false`：`router.stopCurrent()`、`AndroidSpeechPlayer.close()`、清引用，写设置。失败（engine 缺失）保持关闭并记录。
  - 运行期切换不再要求重启；已显示的回答在关闭时立刻停止（arbiter 的 handle 收到 `FINISHED`，cycle 继续）。
- **纯手机模型默认开启**：`SmartSettings.speechEnabled` 保持默认 false；新增 `speechConfigured: Boolean = false`；`setSpeechEnabled` 写 `speechConfigured=true`。`DetachGate.set(true)` 成功后，若 `speechConfigured == false`，调用 `setSpeechEnabled(true)`。这样：从未设置过 → 纯手机模型默认朗读；用户显式关闭过 → 不会被自动打开（D53②同形）。
- **能力表**：`CxrHostEnvironment.speech = router`，`SpeechOutput` 只在 `speechAvailable()` 为真时声明；`deviceState` 的 `tts` capability 也读同一个实时 lambda。
- **行为回归**：纯手机模型下，最终回答会朗读（D213）；眼镜模式的最终回答仍只在 HUD 上出现，`notify_user(voice/both)` 的朗读不变；运行期开关两种模式都即时生效、关闭即停。设备验证两种模式。
- **证据**：logcat `P5_SPEECH state=start/end hintId=... chars=N`（不记正文）；`dumpsys audio` / `dumpsys media.audio_flinger` 的 active track；必要时用 `screenrecord` 观察说话图标；不记录音频内容。

## 11. 风险与未决

- **悬浮窗权限/MIUI**：K40 上 `appops set` 是否让 `Settings.canDrawOverlays` 为真需实测；失败则模式可保存但球不出现，记 `NotMeasured`/阻塞并如实报告。
- **前台服务类型**：API 34 `specialUse` 在 API 33 设备上的声明/运行兼容需实测；若平台拒绝，回退到 `dataSync` 或仅在会话运行时的 `microphone` 服务需要业主裁决（本设计先按 specialUse 实现，失败即记录）。
- **Compose in overlay**：`ComposeView` + 自建 lifecycle owner 在 `TYPE_APPLICATION_OVERLAY` 中的重组/触摸/回收需实测；替代方案是 Material Components Views（需新增依赖）。
- **TTS 行为变化**：最终回答开始朗读会改变眼镜模式的音频节奏与 ConversationCycle 的等待；需要设备回归，确保不会卡住下一轮。
