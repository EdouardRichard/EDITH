## 1. 背景与当前事实

### 1.1 产品目标（业主 2026-10-26）

1. **唤醒词路线可以脱离眼镜单独运行**。增加全局开关「脱离眼镜」：
   - 开关打开时，主动辅助禁用；
   - 开关打开时，从手机收音唤醒，唤醒之后的处理与旧版本一致，复用现有 WAKE 路线与代码；
   - 不要求开关在手机独立运行时仍然连接眼镜；
   - **开关打开后，锁屏/息屏状态下也必须能唤醒**（业主 2026-10-26 追加）。
2. **唤醒路线上下文记录页增加输入框入口**：
   - 支持文字输入，也支持语音 ASR 输入；
   - 用户点发送后给 AI 发消息，消息处理与原逻辑一致；
   - 不管「脱离眼镜」开关是否打开，入口默认展示。
3. **EDITH 依赖的模型不再要求单独配置**，全部打包集成到 APK 中。
4. 业主澄清（2026-10-26）：**唤醒词唤醒后，说话触发的 ASR 是直接给 LLM 的，不改**；只有**输入框的语音输入按钮**才是 ASR 到输入框、由用户再点发送。

### 1.2 当前代码事实（0.4 设计依据）

- **唤醒已是眼镜麦克风单路**：眼镜 PCM 经 CXR 进入 `transport-rokid` 的 `PcmIngress`（`RokidConnection` 持有），`HostCompositionRoot` 的 `AudioIngressLoop` 轮询后把同一帧喂 `WakeWordDetector`（sherpa-onnx KWS，8 条错相流）与 `SpeechPipeline`（VAD/ASR/声纹）。无 CXR 连接时 `armAudioEpoch` 以 `TRANSPORT_MISSING` 拒绝启动（`HostCompositionRoot.kt:1148-1201`）。
- **不存在手机麦克风生产路径**：`phone-app` main 源码没有 `AudioRecord`；历史/分支检索只有眼镜探针与 debug PCM 注入，没有可恢复的"旧手机唤醒"实现。
- **无眼镜时插件不激活**：`maybeMarkSceneReady` 依赖 `linkReady`（`HostCompositionRoot.kt:1098-1107`、`:1580-1590`）；`CxrHostEnvironment.availableCapabilities` 仅在 `liveOutput()`（CXR 时钟映射就绪）时广告 `Capability.TextOutput`（`CxrHostEnvironment.kt:86-93`、`CxrHintLink.kt:479-481`），而 `SmartAssistantPlugin` 的 descriptor 把 `TextOutput` 列为必需能力（`SmartAssistantPlugin.kt:574-624`）。
- **面板耦合**：`ConversationCycle.onWake` 读 `isPanelVisible`；不可见时 3 s 面板等待（`ConversationCycle.kt:164-187`、`:824`），超时 `P3_CONV panel_not_shown` 关窗。手机独立模式没有眼镜面板可等。
- **主动辅助多层闸门**：`ProactiveArming`（持久全局开关，默认开，D53②）、host `armedAcousticSink`/`armedContextSink`、上下文键 `proactive.armed`、插件 `armedNow`/`SmartProactive.admit`；存储值一旦关闭不得被自动打开。
- **文字输入没有生产入口**：`AssistantTab`（`PhoneScreen.kt:270-378`）只读 `ConversationLog`；唯一文字注入是 debug-only `DebugUtterance`（release 不含）；`handleHelp`（`SmartAssistantPlugin.kt:5595`）是"重放最近一条 ASR final"的手动求助，不是任意文字。
- **模型现状**：
  - ASR 引擎包 240,967,541 B（encoder int8 / decoder fp32 / joiner int8 / tokens / Silero VAD / speaker / manifest），只在 App 私有 `no_backup/engine-models-import` 由 **debug 构建**冷启动导入；
  - KWS 8,779,150 B，已由 Gradle 从 `.local/p3-kws-model/...` 校验 SHA 后打进 `assets/kws/`（唯一已在 APK 的模型）；
  - Laya（SystemOne）交付微调集 679,266,520 B / 7 文件（运行时只需 6 个），当前手工 adb push 到 `files/`；
  - EmbeddingGemma 183,815,055 B（图 + SentencePiece 词表），当前在外部 files 目录；
  - 合计 **1,112,828,266 B（约 1.03 GiB）**；当前 release APK 90,568,560 B、debug APK 102,799,450 B，均不含 ASR/Laya/Embedding 权重。
  - **release 无 provisioning 路径**：`allowDebugImport = BuildConfig.DEBUG`（`HostCompositionRoot.kt:2198`）；release 只 `recover()` 已导入 store，全新安装 release 会 `ENGINE_MISSING`；Laya/Embedding 缺失时插件仍激活但每回合 `SYSTEM_ONE_UNAVAILABLE`/`EMBEDDING_UNAVAILABLE`。
- **版本/发布线**：两端 `versionName "0.3.0-preview"`/`versionCode 3`；`v0.3.0-preview` 是 `main` 上 `2ae264d7` 的 lightweight tag；无 0.4 spec/plan/branch/decision；README 仍要求网盘下载 + adb push 四组模型。
- **项目规则**：D53（唯一同意动作=点「开始」；会话运行即允许转写与该回合上下文发往所配置模型服务）、D117/日志零正文、D161（唤醒词 伊迪丝/EDITH）、D164/D169（10 s/120 s）、D181/D188/D194（主动辅助与 WAKE/PROACTIVE 隔离、下一句队列）、D60/D64（Laya GPU）、D116（测量接缝 debug-only）、D195（Phase 4 设备验收是业主接受，不是版本级通过）、`AGENTS.md`（不 push/tag/merge、不撤销用户改动）。

### 1.4 对"旧版本逻辑"的澄清

仓库内**不存在**可恢复的手机麦克风唤醒实现（0.21 基线只有眼镜麦克风 → CXR → PcmIngress）。本版"从手机收音唤醒，与旧版本逻辑不变，路线、代码复用"确定为：

- **只换采音源**：手机麦克风 PCM 进入同一个 `PcmFramer` → `AudioIngressLoop` → `WakeWordDetector`/`SpeechPipeline`；
- **唤醒之后完全走既有 WAKE 路线**：同一会话/路由/`SmartTurn`/`ConversationStore`/提示词/工具面/输出/记忆/确认；不新建第二条唤醒路线，不改唤醒词与 10 s/120 s；
- **唤醒词唤醒后的 ASR 仍旧直接给 LLM**；输入框的语音输入是**独立的一次性听写**，不改变前者。

## 2. 范围、非目标与完成判据

### 2.1 本版范围

1. 持久化全局开关「脱离眼镜」，默认关；保存后下个会话生效；会话运行中修改则先停止会话并提示。
2. 脱离模式下：
   - 不发起 CXR 连接、不向眼镜发送任何内容；
   - WAKE 路线从手机麦克风采音（KWS/VAD/ASR/声纹复用既有实现），手机麦克风几何必须与现有 16 kHz/mono/16-bit 流一致；
   - 主动辅助有效关闭（不覆盖用户持久化的「主动辅助」值）；
   - 会话可在无眼镜时启动并激活智能助手插件；
   - **锁屏/息屏时 KWS 仍持续工作**（前台服务 microphone 类型 + 必要 CPU 唤醒锁）；唤醒后回合照常执行；
   - 答案显示在手机「对话上下文记录」页；TTS 沿用「语音朗读」开关；唤醒提示音沿用既有行为；
   - 必要的权限/前台服务类型与错误码。
3. 「对话上下文记录」页的 WAKE 视图增加输入行：
   - 文字输入 + 发送；
   - 语音输入按钮：手机一次性采音 → ASR → 填入输入框（可编辑）→ 用户点发送；
   - 输入行始终展示（不受「脱离眼镜」开关影响）；会话未运行/忙时按明确语义禁用或拒绝。
4. 全部端侧模型内置 APK：
   - 四组模型（ASR 包、KWS、Laya、EmbeddingGemma）全部随 APK 分发；
   - 首启自动、幂等、可校验地落到现有运行目录，无需用户/开发者单独 push；
   - release 构建也能从 APK 资产完成 provisioning；
   - 提供仅开发/CI 使用的轻量构建开关（不交付）；
   - 模型许可证/声明随 APK 内置；
   - README/`NOTICE`/版本号更新。
5. 版本：两端 `versionName = "0.4.0-preview"`、`versionCode = 4`（同一次 bump 提交）；不打 tag、不 push、不 merge。
6. JVM 全量门禁 + K40/眼镜设备验证（可验证项）与明确 `NotMeasured` 边界。

### 2.2 非目标（0.4 不做）

- 不改眼镜端 App、CXR 自定义命令协议、`Caps` 载荷形状或官方 demo 对齐方式；不借"脱离"引入第二套互联协议。
- 不改唤醒词（仍 `伊迪丝`/`EDITH`）、10 s 监听窗、120 s 关闭、持续对话、队列语义；不改"唤醒后 ASR 直接给 LLM"。
- 不改主动辅助判据、Laya GPU/NPU 选型、提示词体系、工具面（23）。
- 不做模型下载/增量更新/云端分发；不做 Play Asset Delivery；不做旧 bundle 自动 GC。
- 不做手机端 UI 框架/导航重构；输入行嵌入现有 `AssistantTab`。
- **不承诺锁屏下自动点亮屏幕或锁屏 UI 呈现**；本版只保证唤醒与回合执行（TTS 若开启则朗读）。
- 不处理 0.4 之外的历史 `NotMeasured`；不修改 0.21/0.23/0.24/0.25/0.3 判词；不 push/tag/merge/release。

### 2.3 完成判据（DoD）

- §8 的 JVM 行全绿（0 failures/0 errors，环境允许的既有 skip 除外）；
- 设备行按实际读数记录 `Verified`/`Partial`/`NotMeasured`，不把 Partial/NM 写成通过；
- 完整 APK 内含四组模型资产；全新模型目录下冷启动自动 provisioning 后会话可运行；
- 眼镜模式回归：开关关时 CXR/唤醒/上下屏路径语义不变（JVM 契约/回归 + 设备冒烟）；
- 锁屏唤醒有设备读数或如实 `NotMeasured`；
- 文档收口：`STATUS` checkpoint、`DECISIONS` 新 D、`CONTRACTS`、`ACCEPTANCE` 新 §2.x、README/NOTICE/版本号；
- 不 push/tag/merge，除非业主另行授权。

## 4. 脱离眼镜模式设计

### 4.1 开关、持久化与生效

- 字段：`SmartSettings.glassesDetached: Boolean = false`（与 `proactiveEnabled` 同在一个加密 JSON blob；缺键取安全默认 **false**）。**只属于 host**，不进入 `pluginValues()`/插件配置 schema。
- 读取：组合根组装时读取一次，用 `StateFlow<Boolean>`（`DetachGate`）暴露给 UI 与 host 内部；保存后立即更新 gate（下一次 `ensureCxrLink`/`armAudioEpoch`/能力广告读到新值）。
- 保存语义（业主已选；实现 `9db5fcb4`）：
  1. 若会话处于**任何非 Idle 状态**（`Authorizing`/`Connecting`/`BuildingScene`/`Ready`/`Listening`/`Paused`/`Interrupted`/`Reconnecting`/`Error`），先 `stop()` 宿主会话，再直接 `Context.stopService`；停止失败即拒绝保存；
  2. 读/写持久化（失败可见）；
  3. UI 显示"已保存，下次开始会话生效"；
  4. 不自动重启会话。
- UI：`SettingsTab` 的开关区新增「脱离眼镜（仅用手机麦克风与屏幕）」及说明：不连接/不使用眼镜；主动辅助不生效；是采音/显示选择，不是上传授权（D53）；会话运行中修改会先停止会话；「主动辅助」开关保持可见但标注"脱离眼镜模式下不生效"，其持久值不变。
- 默认 false（现有用户行为不变）。
- 竞态：保存/停会话/能力广告在同一把锁内；脱离模式下迟到的 `onSceneReady` 不得把会话误认为眼镜就绪。

### 4.2 手机麦克风采音路径

- 新增手机采音源（建议 `PhoneMicDevice` + `PhoneMicCapture`，app 模块）：
  - `AudioRecord`，16 kHz、单声道、16-bit LE；几何必须与现有 CXR 帧一致（同一 `PcmFramer`/`SpeechPipeline`）；启动时校验实际配置，不一致报 `MIC_FORMAT_UNSUPPORTED`，不重采样、不猜；
  - 独立采集线程每次读约 10–20 ms，按 `PcmIngress.offer(epoch, bytes)` 投递（640 B 级 chunk，同一 `PcmFramer` 20 ms 成帧）；
  - 起始失败/权限缺失/设备占用变成明确错误（`MIC_PERMISSION_MISSING`/`MIC_UNAVAILABLE`/`MIC_START_FAILED`），不静默停在"已开始"；
  - `P3_FRAME`/`P3_AUDIO` 只记计数、格式、epoch、失败原因，不记音频。
- `AudioIngressLoop`/KWS/`SpeechPipeline` 复用：
  - 手机源与 CXR 源实现同一 ingress 契约；`armAudioEpoch` 在脱离模式不要求 `activeConnection`，打开手机 ingress、启动采集、只启动 loop（无 transport port）；
  - 同一帧仍喂 `wake.accept` 与 `pipeline.accept`；KWS 唤醒词、冷却、`PlaybackGate` 行为不变；
  - `CxrAudioChain` 的 ingress 选择需要可切换（loop 只持一个 ingress）：用动态选择的 ingress 或在模式变化时重建 loop；不重建引擎；
  - stop/pause/会话结束停采集线程并释放 `AudioRecord`（幂等）。
- 权限与前台服务：
  - `RECORD_AUDIO` 运行时权限：只在脱离模式需要；点「开始」前由会话页请求；拒绝则拒绝启动并显示 `MIC_PERMISSION_MISSING`；
  - `FOREGROUND_SERVICE_MICROPHONE` 与 `SessionService.foregroundServiceType`（`microphone`）——与 `connectedDevice` 并列声明，运行时按模式选择（Android 14 需 FGS 权限；K40 API 33 按平台实际验证）；
  - 脱离模式启动不要求蓝牙权限（现有 SessionService 的 Android 12+ 蓝牙门禁只在眼镜模式保留）；眼镜模式权限行为不变。
- 回声：手机扬声器 + 手机麦克风是新增声学回路；既有 `PlaybackGate` 只抑制 KWS（以及既有 TTS 相关抑制），本版不扩大抑制范围；设备验证记录实际干扰，不声称已解决。

### 4.3 无 CXR 的会话启动、插件激活与手机显示

- **启动路径**：`start()` 在脱离模式下：
  - 不调用 `ensureCxrLink()`/`connectCxr()`；`attachCxrActivity` 不发起连接；
  - 仍 `host.startSession(...)`；scene 就绪判定允许"脱离模式 = 本地就绪"（`maybeMarkSceneReady` 的 detached 分支：mark ready + activate，跳过 `hintLink.sessionEstablished`），不依赖 `linkReady`；
  - 环境照常组装（模型、ASR、工具、确认、存储、感知等 provider 不变）；`Capability.TextOutput` 由手机显示设备使能；
  - 身份/激活走既有 `host.activate` 流程，不绕过 `HostRuntime` 的 generation/identity 闸门。
- **手机显示设备**（D201）：
  - host 的 `liveOutput` 在脱离模式返回手机 `HintDevice`（如 `PhoneHintDevice`），使 `CxrHostEnvironment` 广告 `TextOutput`；眼镜模式仍 `hintLink.liveOutput()`，选择在同一个 lambda 内按 gate；
  - 手机设备 **ack-only**：不写 `ConversationLog`（插件已 `publishAssistantFinal` 写最终答案；再写会覆盖 `say-<hintId>` 的 memory-ack 行，`AnswerEmitIdentityIntegrationTest` 钉住）；
  - **ack 语义（D201 实施裁决，2026-10-26）**：`show` **无条件、同步、恰好一次**回调 `listener(OutputStatus.Displayed)`；ack 只表示手机显示设备已接管该提示（记录页由 `ConversationLog` 渲染），**不检查也不要求** `say-<hintId>` 已存在；
  - **顺序与不变量**：插件先 `sink.submit`（`PhoneHintDevice.show` 在 submit 内同步 ack），再 `publishAssistantFinal` 写 `say-<hintId>`，写完行之后才据 `Displayed` 结算答案/续听。答案行存在是**设计不变量**，不是运行时检查；若在 `show` 内按字面要求行已存在，会拒绝每个回合的首个答案——本版不做行存在运行时 gating，真要做需另立插件排序/异步 ack 的独立任务；
  - `clear` 只清"当前提示"状态，不删历史；
  - 不发任何 CXR 命令；`ConversationWireDisplay` 的 wire 保持静默/未建立（不伪造 `PANEL_SHOWN`）。
- **面板/续听适配**：`ConversationCycle` 在脱离模式 `isPanelVisible = true`（由 host `SmartWiring` lambda 提供，不调用 `onPanelShown`、不发协议命令）；眼镜模式仍用原 `isPanelVisible`。10 s/120 s/持续对话语义保持。
- **TTS/提示音**：沿用 `AndroidSpeechPlayer`/`speechEnabled` 与 `WakeChime`/`ToneGenerator`；不改变默认值。
- **眼镜模式**：`glassesDetached=false` 时上述分支全部不进入；`ensureCxrLink`/`attachCxrActivity`/`onSceneReady`/`panelShownArrived`/`liveOutput` 的眼镜路径保持原样；官方 demo 对齐、CXR 连接、面板/提示路径语义不变（契约/回归测试钉住）。

### 4.4 主动辅助的有效禁用（D202）

- `effectiveProactiveArmed = storedProactiveEnabled && !glassesDetached`：
  - host：`armedAcousticSink`/`armedContextSink` 发射条件、`CxrContextSignals` 的 `proactive.armed` 键都用有效值；
  - 插件：`armedNow`/`SmartProactive.admit` 读到的已是有效值；补测试钉住无其他读取路径；
  - **不修改** `SmartSettings.proactiveEnabled`；关闭脱离并重启后用户原选择恢复。
- 会话运行中切换脱离会先停会话（D199），因此不存在"正在显示的主动提示被热切换打断"；异常路径走既有 `stop` 清理。
- 遥测：`P4_DETACH state=on|off effective_proactive=<bool> audio=phone_mic|cxr`（**不带** `lockscreen_hold`：`DetachGate.set` 先停会话，此时锁已释放，该字段只会恒为 false，没有真实锁状态可报）；`lockscreen_hold=true|false` 属于 `P4_AUDIO`（`state=armed|disarmed source=phone_mic|cxr transport=<bool> loop=<bool> lockscreen_hold=<bool> reason=...`），只记状态。

### 4.5 生命周期与失败语义

| 事件 | 行为 |
| --- | --- |
| 脱离模式点「开始」但未授权 `RECORD_AUDIO` | 拒绝启动，UI 显示 `MIC_PERMISSION_MISSING`（可请求/跳设置）；不进入 Ready |
| 手机麦克风被占用/初始化失败 | 启动失败/会话停止，`MIC_UNAVAILABLE`/`MIC_START_FAILED`；不得显示正常收音 |
| 采集中断（设备抢占等） | 有界失败：停会话或明确 degraded；不静默丢帧 |
| 会话暂停/停止 | 停采集、清 epoch、释放 `AudioRecord`；重复调用幂等 |
| 蓝牙权限缺失（脱离模式） | 不影响启动 |
| 眼镜模式下保存脱离 | 停止会话并持久化；下次开始走脱离模式 |
| 眼镜模式但无眼镜 | 保持现行为：CXR 连接失败/无法激活，UI 如实报告（不进入手机模式） |
| 锁屏/息屏（脱离） | KWS 继续工作；唤醒后回合照常执行；不因锁屏拒绝采音/停会话 |
| MIUI 省电策略杀掉后台 | 有界失败：会话停止/FGS 通知消失，UI 如实报告；记录设备设置前提，不假装"永远存活" |
| 进程重启 | 读取持久化开关；模型/会话按既有冷启动路径恢复 |

### 4.6 锁屏/息屏唤醒（D199）

- 机制：
  - 脱离会话用前台服务采音；`foregroundServiceType` 加 `microphone`（与 `connectedDevice` 并列声明，运行时按模式选择）。
  - 采音/推理期间持有 **`PARTIAL_WAKE_LOCK`**（平台官方 API；厂商无对应能力，注释与证据写明"厂商无此 API + Android 官方依据"），保证锁屏/息屏下 CPU 不被挂起、KWS 持续处理；pause/stop/释放路径必须释放；异常路径也不得泄漏。
  - **不要求亮屏**：本版不承诺锁屏下自动点亮屏幕或弹出锁屏 UI；答案写入 `ConversationLog`，TTS 若开启则朗读。设备验证以 `P3_WAKE` 与回合状态为准。
- 设备前提：MIUI 可能额外电池优化/自启动限制；记录实际设置（可用 `adb shell cmd deviceidle whitelist +com.sheen.rokid.phone` 或系统设置）；若仍被杀则如实记 `Partial`/`NotMeasured`，不把"设置过"当"已验证"。
- 风险：持续唤醒锁耗电、锁屏下 ASR/TTS 回声、FGS 类型在 API 33/34 的差异；证据记录，不推断。屏幕点亮/锁屏 UI 如需后续版本再单独批准。

## 5. 「对话上下文记录」输入入口设计

### 5.1 UI 与可用性

- 位置：`AssistantTab` 的 WAKE 视图，聊天 `Surface` 下方的输入行；标题/路由切换/刷新按钮保持在滚动容器外（U-1 约束不破坏）；PROACTIVE 视图不显示输入行。
- **始终展示**：不论 `glassesDetached` 是否 true，WAKE 视图都渲染输入行（需求原文）。
- 元素：多行文本输入（长度上限在 plan 定）、发送按钮、麦克风按钮、状态提示（空闲/正在听写/识别中/发送失败/会话未开始）。
- 可用性：
  - 会话未运行（`SessionState` 不是 `Ready`/`Listening`）或没有插件身份 → 输入行可见但禁用，显示"请先开始会话"（不靠 `currentIdentity()` 在 UI 线程判身份）；
  - WAKE 回合忙（`AwaitingTranscript`/`Running`/Idle-未结算/已有排队句）→ 发送被拒绝并显示原因（不替换进行中的回合）；
  - 空白/纯空白 → 本地拒绝，不产生事件；
  - 成功后清空输入；失败保留便于重试。
- 可访问性：输入框/按钮有中文标签/`contentDescription`；设备验证用 `edith.phone.a11yprobe` 读回/输入（中文只能走无障碍）。

### 5.2 文字消息契约与回合语义（D203）

- 契约：`UserAction.Action.Typed` + `UserAction.text: String? = null`（不序列化、不上线缆；唯一穷尽 `when` 在插件，编译器强制分支）。**不复用** `Help`/debug `DebugUtterance`；不新增 `HostEvent` 子类型（生产 `when` 带 `else`，漏分支会静默失效）。
- 组合根 API：`HostCompositionRoot.requestTypedMessage(text): TypedSendResult`（`Accepted/Blank/NoSession/Busy` 一类），仿 `requestHelp()`：从 `host.currentIdentity()` 取身份，无身份返回 `NoSession`；只经 `HostRuntime.onEvent`；提交前可用插件公开 `canAcceptTypedMessage()` 预检查，插件在 `gate` 锁内再原子检查。
- 插件处理：
  - 不写 `lastFinalTranscript`；只释放/重置 WAKE 路由 cycle（不复用 Help 的双路由 `reset()`，不清 PROACTIVE 窗口/不取消 pending proactive hint panel）；
  - `openTurn(... runsImmediately=true, bypassWakeGates=true, turnId="typed-<uuid>", startsCooldown=false)`；`openTurn` 加 `turnId`/`startsCooldown` 参数并以默认值保持 Help/wake 不变；
  - 文本不经 `isUsableUtterance`；空白在组合根/插件两层至少拒绝一次；
  - 进入 WAKE `ConversationStore`；用户行 `asr-<turnId>`（`publishUserFinal` 既有约定，眼镜端只认 `asr-` 前缀）；助手答案走既有输出/确认/TTS；
  - **不得**进入 PROACTIVE、不得触发 Laya gate、不得产生额外 WAKE 回合；
  - 忙判定：`queuedUtterance == null` 且（`turn == null` 或 `turn.phase == Idle && turn.answerNotified`）才接受；其余拒绝，不取消进行中的回合。
- 持续对话：业主已确认**不打开** 10 s 免唤醒窗口（与 `handleHelp` 一致）；下一条仍可打字/按麦克风/重新唤醒。本路径没有 cycle 的 10 s turn，`onAnswerDone` continuation 早退保持不变。
- 显示：眼镜模式走既有 Help/答案上屏路径，**不显式请求 `PANEL_OPEN`**（业主已确认）；设备验证若答案不可见再按既有提示上屏机制补齐，不新增协议。脱离模式走手机显示设备（§4.3）与 `ConversationLog`。
- 日志：接受为 `P4_TYPED state=accepted turn=typed-<uuid> chars=N`（**没有** `reason` 字段）；拒绝为 `P4_TYPED state=refused reason=blank|no_session|busy|stale turn=typed-<uuid> chars=N`。**不记文本、不记 textSha256**；正文永不进 logcat/证据。

### 5.3 语音听写（D204）

- 触发：输入行麦克风按钮；仅会话运行且 mic 权限已授予时可用。
- 采音：**手机麦克风**；一次性会话，16 kHz/mono/16-bit；VAD 端点或用户点停止或 15 s 上限结束。
- 识别：复用同一 ASR 引擎/`SpeechPipeline`（**不创建第二 recognizer/pipeline**：重载约 241 MB 且会与唤醒抢占）：
  - 唤醒 KWS 不把听写内容当唤醒/回合（听写文本只去 UI）；
  - 唤醒后 ASR 直接给 LLM 不变；
  - 眼镜模式下用**帧路由暂停/重定向**（停止把 CXR 帧喂 wake/pipeline，改喂手机麦克风帧；结束恢复），**不** `disarmAudioEpoch`/重启 CXR 传输/改变官方握手；
  - 脱离模式下唤醒管线本就用手机麦克风，听写复用同一来源与管线，仅切换输出目的地；
  - `SpeechPipeline` 需要一个小而可测的"当前回合强制收尾/输出重定向"扩展（VAD 端点之外的停止/取消路径用）；不得改变既有唤醒回合 emit 语义。
- **路由闸门与刻意代价（`c3b4272a`）**：听写终态（final/timeout/cancel/error）在 cleanup 恢复唤醒环之前关闭宿主转写路由；只有显式输入（KWS wake、typed、`Help`、新会话/新 audio epoch）才重新打开。听写后到达的尾音/环境语音被计数丢弃（`P3_TRANSCRIPT_ROUTE state=drop ...`），**不会**成为 WAKE 回合或续接队列项；这是“听写文本只进 UI”的刻意隔离代价，不是屏蔽音频、不是自动发送。眼镜模式的 ambient/proactive 转写同样按此规则丢弃；若产品要求“听写后不唤醒也能续聊”，需另立产品裁决。
- **ASR re-arm（进程级管线）**：`SpeechPipeline.rearm()` 清除故障 `paused`、撤销遗留回合/挂起请求、清 deferred/pre-roll、重置 ASR/VAD/speaker；healthy/closed 时 no-op；同一 session 继续拒收，只有另一个 session/generation 首帧或新 audio epoch arm 才恢复。`P3_PIPELINE` 记录 `state=fault reason=<code>`、`state=paused`、`state=rearmed reason=session`。
- **换 audio epoch 重置唤醒流（`b2d03c06`）**：`AudioIngressLoop.start(epoch)` 在换 epoch/音频源时调用 `wake?.reset()`，让 8 条原生 KWS 流重新错相；同一 epoch 的重复 start 仍为 no-op。JVM `AudioIngressLoopTest.startingAFreshEpochResetsTheWakeStreams` 钉住；设备在「眼镜会话 → 脱离 → 手机麦」路径上：有利素材 5/5，但同一 APK 冷启动脱离对同一素材 0/3（`wake-zh` 1 次亦 0）；两读数并列，只能证明 reset 后至少可命中一次，切换后可靠性未建立（D5 Partial（中文合成不稳定））。真实人声、多轮切换与长稳 `NotMeasured`；证据 [KWS epoch reset](../../project/evidence/2026-10-27-0.4-kws-epoch-reset-device.md)。
- 结果：最终 transcript 追加到输入框（已有文字后空格分隔；不自动发送），用户可编辑；无结果/超时给可见状态；听写失败不产生模型请求。
- 权限/并发：与唤醒共用 `RECORD_AUDIO`；同一时刻只有一个采音所有者（唤醒或听写），用显式 lease/状态机，不用"两个 AudioRecord 试试看"。
- 遥测：`P4_DICTATION state=started|refused|final|stopped|timeout|cancel|error chars=<n> reason=<...|none>`（**无 `turn`**；不记正文/hash）；`P3_TRANSCRIPT_ROUTE state=closed|open|drop reason=<dictation_end|dictation_final|session|help|typed|wake>`（drop 行可带 `partials=<n> chars=<n>`）；`P3_PIPELINE state=fault reason=<code>` / `state=paused` / `state=rearmed reason=session`。

### 5.4 既有唤醒链路不变的证明要求

- JVM 证明：正常 `TranscriptEvent(final)` 仍只触发一次 WAKE 回合、不额外触发 PROACTIVE；听写文本不进 `HostRuntime`/插件；文字消息不产生 PROACTIVE gate 调用；眼镜模式 CXR/面板既有测试全保持。
- 设备：唤醒词 → 直接说请求 → 答案（ASR 不经输入框）；输入框听写 → 填入 → 点发送 → 答案；两条路径互不串扰。

## 10. 风险与未验证项

1. **APK 体积/构建/安装**：约 1.0–1.1 GB APK 在 AGP/aapt2/R8/MIUI/K40 上能否稳定构建、安装、更新尚未实测；deflate 估算是估算，不是读数。若不可行，按"打包方式/压缩策略"变更回到业主，不静默降级为外置。
2. **首启耗时/存储**：拷贝约 1.03 GiB + 引擎校验；K40 实际耗时、安装空闲空间、失败恢复需实测。
3. **手机麦克风唤醒声学**：KWS 在手机麦克风上的检出率/误触发/回声（扬声器）未测；设备优先合成 WAV；真实人声/长稳 `NotMeasured` 除非实际做到。换音频 epoch 的唤醒流重置已实现；中文合成 5/5（`word=伊迪丝`），但同 APK 冷启动脱离对同一素材 0/3；英文/弱素材不参与判定；真实人声/多轮仍 NM；多轮切换/长稳仍未测。

## 11. 业主确认

### 11.1 已于 2026-10-26 确认

1. 脱离眼镜 = **严格本地**（不连 CXR、不向眼镜发内容；手机屏显示答案；TTS 可选）。
2. 输入框语音 = **手机麦克风**、识别后**填入输入框**、用户再点发送。
3. 模型 = **四组全部打包**，另设仅开发/CI 的轻量构建开关。
4. 开关 = **默认关**；保存后下个会话生效；运行中保存**先停止会话**。
5. 唤醒后 ASR **直接给 LLM，不变**；只有输入框语音走 ASR→输入框。
6. **开关开启后锁屏下要能唤醒**。
7. 文字消息**不打开** 10 s 持续对话窗口；眼镜模式**不显式请求**面板，走既有 Help/答案上屏路径。

### 11.2 实现中已确认的剩余口径（2026-10-26/27）

1. **锁屏呈现**：只承诺唤醒+回合执行、答案进 `ConversationLog`、TTS 按既有开关朗读；**不**自动亮屏/弹锁屏 UI。若后续要求亮屏/锁屏卡片，需单列平台行为与设备验证。
2. **轻量构建说明**：`-PwithoutBundledModels=true` 只在 README 的开发/CI 说明中出现，不作为用户选项；release 禁用。
