## 1. 目标、范围与非目标

### 1.1 目标

把需求文档 U1–U12 转成可实施、可验收的 0.23：

- **手机 App**：助手对话页固定头/聊天框、只有消息列表滚动、刷新图标、AI 左/用户右（U1/U2）；技能/记忆点击查看全文（U3/U4）。
- **眼镜 App**：照官方「乐奇」视觉与交互（U5/U9），底部 380px 面板、绿阶、px 字号、语音球、聆听/思考行、合规标识、上下渐隐遮罩；对话行全部左对齐。
- **眼镜交互**：不切路由、只显示当前路由（U8）；1px/帧 ticker 自动滚动（U10）；单击钉住、四向键翻页；忙碌 BACK 打断/空闲退出（U11）。
- **唤醒链路**：删除 TTS「在的」；短提示音 + 800 ms 去抖，受「语音朗读」开关控制（U12/U6）。
- **隔离与回归**：唤醒与主动辅助互相独立，主动辅助不显示唤醒会话内容（U7）；P6 做路由独立回归、端到端设备走查与文档收口。

## 3. 总体设计与不变量

### 3.1 设计原则

1. **官方依据优先**：眼镜视觉/交互以 `D:\Project_new\rokid_glasses_UI` 的 A/B/J 级材料为准；官方没有的语义不发明。
2. **纯函数先行**：所有可离线判定的规则（对齐、颜色、字号、ticker、路由、摘要、去抖、STOP 编解码）放进纯 Kotlin 对象，先写失败测试，再接线 Android。
3. **单一权威**：会话内容仍由 `ConversationLog` 权威；手机与眼镜各自持有同形状的日志，顺序不重排；手机记录完整会话，眼镜缓存只是当前窗口。
4. **加法式协议**：线缆仍 `wireVersion = 1`；STOP 是新增命令，旧解码器对未知命令返回 null（安全失败）；不改变既有字段顺序/含义。
5. **证据先于结论**：JVM 通过只写 `Verified (JVM)`；设备/听感/可读性未测写 `NotMeasured`。
6. **无人值守优先**：P1–P6 的自动化部分由 Agent 连续执行；只在必须人参与的审阅门/主观项停下，主观项集中到 P6 末尾。

### 3.2 不变量（不得破坏）

- **D41/D44**：眼镜↔手机互联 100% 按官方 demo/样本；回调层级、`Caps` 字段与顺序不改；STOP 也走同一 `Caps` 字符串通道。
- **D53**：上传零旋钮；点「开始」仍是唯一同意动作；本版不新增上传或隐私授权。
- **D58**：TTS 在手机侧合成、Android 原生输出；眼镜端不做 TTS。
- **D63**：提示上限 400 codepoint，三处常量相等；手机/眼镜同一次构建验证。
- **D72/D74/D99**：记忆不进系统帧、不写入 `ConversationStore`；每路由一条 `ConversationStore`。
- **D95**：手机侧人工操作模拟一律走 `edith.phone.a11yprobe`；禁用 `adb shell input tap/text`；安装显式指定 `adb -s 2696813b`。
- **D117**：日志/证据只记计数、类型、id、哈希、字符数，不记正文；原始截图可存，但不含敏感正文。
- **D120/D121**：0.21 工具面 drift 不在本版修；M2/AC-13/16 的失败判词不改写。

### 3.3 术语

| 术语 | 含义 |
|---|---|
| **会话（session）** | 手机点「开始」到「停止」之间；由 `SessionId` + `Generation` 标识 |
| **窗口（window）** | 眼镜 `GlassesActivity` 的一次可见生命周期；窗口结束 = Activity 销毁或新会话 `HELLO` 到达 |
| **路由（route）** | `WAKE`（唤醒）/ `PROACTIVE`（主动辅助）；内容互相独立 |
| **忙碌（busy）** | 某路由正在工作；由手机插件以电平形式 `BUSY` 下发，眼镜本地 60 s 上限 |
| **钉住（pin）** | 眼镜侧单击 `ENTER` 后停止 ticker 并显示图钉；再按恢复（EDITH 无官方的服务侧自动退出，见 §5.3） |
| **ticker** | 自动滚动引擎：每帧 1px，前 3 帧跳过；用户手动翻页/钉住即停 |
| **窗口缓存** | 眼镜内存中的 `ConversationLog`；不落盘，窗口结束即清空 |

## 4. 手机 App

### 4.1 P1：助手对话页（U1/U2）

#### 4.1.1 现状与问题

- `PhoneScreen` 的主体 `Column` 统一套了 `.verticalScroll(rememberScrollState())`；`AssistantTab` 的标题、路由切换、聊天记录、刷新按钮都在同一滚动列里，记录一长，切换按钮就被滚走（U1 的原始缺陷）。
- `AssistantTab` 用 `ListItem` 平铺、不分左右；刷新是底部文字按钮（U1/U2 的改造点）。

#### 4.1.2 目标布局

```
PhoneScreen body (fillMaxSize, 不再整页 verticalScroll)
└─ AssistantTab (fillMaxSize)
   ├─ 固定标题：对话上下文记录
   ├─ 固定路由切换：唤醒 / 主动（SingleChoiceSegmentedButtonRow）
   ├─ 固定说明文字（只读、切换不影响会话）
   └─ 聊天框 Surface/Card (weight(1f), fillMaxWidth)
      ├─ 聊天框头：左侧当前路由全名 + 右侧刷新 IconButton
      └─ LazyColumn (weight(1f))  ← 唯一滚动区域
         ├─ 空态：暂无记录
         └─ 消息行：AI 左 / 用户右气泡
```

- **聊天框头固定**：路由全名（`唤醒对话` / `主动辅助对话`）+ `Icons.Default.Refresh` 图标；刷新图标在聊天框右上（U1）。
- **刷新**：点击 `revision++`，重新读取 `ConversationLog`；图标 `contentDescription = "刷新对话"`。
- **轮询**：保持 2 s 轮询（现有行为），只在 tab 组合时运行；不改为订阅，避免引入新生命周期机制。
- **列表**：`LazyColumn` + `items(entries, key = entryId)`；只有它滚动，标题/切换/聊天框头不动。
- **气泡**：
  - `ConversationRole.ASSISTANT` → 左对齐（`Arrangement.Start`）；
  - `ConversationRole.USER` → 右对齐（`Arrangement.End`）；
  - `Surface(shape = RoundedCornerShape(12.dp))`，用户气泡 `primaryContainer`，AI 气泡 `surfaceVariant`；最大宽度约 80%；内边距 12dp；不显示大头像/图标（减少干扰）。
- **自动滚动（新增但受控）**：仅当用户已在底部时，新条目到达后滚到最新；用户向上阅读时不抢位置。判定放进纯函数 `AssistantConversation.shouldAutoScroll(atBottom, newCount, oldCount)`，P1 单测。
- **路由标题**：`AssistantConversation.routeLabel(WAKE) = "唤醒对话"`，`PROACTIVE = "主动辅助对话"`；分段按钮仍用短标签「唤醒 / 主动」。
- **不自动跟随**：主动辅助新消息不切当前路由（P0 裁决 1）；两侧记录仍独立。

### 4.2 P2：技能与记忆全文（U3/U4）

#### 4.2.1 技能页

  - `StorageAccessSkillView.read` 先校验名字（非空、以 `.md` 结尾、不含 `/`、`\`、不等于 `.`/`..`），再要求 shared storage 授权，再调用 `StorageAccess.readFile("$SKILLS_DIR/$name")`；

  - `readFile` 返回 null → `Unreadable`；空/全空白 → `Empty`；否则 `Text`，**不截断**。

#### 4.2.2 记忆页

- 缩略规则：
  - `const val PREVIEW_CODE_POINTS = 40`；
  - 按 **code point** 截断，不拆 UTF-16 surrogate；超过 40 个 code point 时截前 40 个 + `…`；不超过则原样；
  - 空白文本按空处理；
  - 全量文本仍保存在 `MemoryLine.text`，**缩略不改变存储**；删除/清空逻辑不变。

### 5.2 P4：单路由、ticker、钉住、四向键（U8/U10）

#### 5.2.1 单路由

- 删除眼镜顶部路由标签；删除 `KEYCODE_DPAD_LEFT/RIGHT` 切路由。
- `ConversationOrder` 简化：
  - `selected()` 只由 `show(route)`（`SHOW` 到达）改变；默认 `WAKE`；
  - `SAID`、`BUSY` **不切换**视图；
  - `reset()` 新会话回 `WAKE`；
  - `pinned` 状态由 `ENTER` 切换；`reset` 清 pin。
- `ConversationLog` 仍按路由存两份；只渲染 `selected()` 的那一份；另一条缓存不显示、不持久化，窗口结束（新 `HELLO` / Activity 销毁）清空（P0 裁决 3）。
- 不新增会话结束命令；手机端 `ConversationLog` 与会话管理不变。

#### 5.2.2 ticker

- **1 px/帧**，前 **3 帧**跳过（等布局稳定），`ValueAnimator` 驱动；`duration = Integer.MAX_VALUE`、线性、无插值；每帧 `hintScroll.scrollBy(0, 1)`。
- 启动条件：内容高于窗口、未钉住、未在用户阅读暂停中；停止条件：到列表底部、用户手动翻页、钉住、`onPause`、`onDestroy`。
- 新条目到达：**新内容优先**——无论是否钉住，先 `scrollTo` 新条目的顶部（保证新答案可见）；随后仅在**未钉住**时启动 ticker。钉住只停止连续 ticker，不阻止新条目的首次定位（2026-10-15 的缺陷是“新答案藏在折叠下方”，不能复现）。
- 用户手动翻页：停止 ticker，标记用户已读；新条目到达后重新定位并恢复 ticker。
- 纯函数 `HintTicker`：
  - `PIXELS_PER_FRAME = 1`、`SKIP_FRAMES = 3`、`PAGE_FRACTION = 0.85`；
  - `fun pageStepPx(remainingPx: Int, viewportPx: Int): Int` = `min(remaining, (viewport * 0.85).toInt())`；
  - `fun shouldScroll(offset: Int, max: Int): Boolean`；
  - `fun offsetAfterFrames(start: Int, frames: Int, max: Int): Int`（前 3 帧不变，之后每帧 +1）。
- `HintReadingBudget` **不改**（P0 裁决 4）：手机发送的 `remainingTtlMillis` 仍是旧保守值；眼镜端不再用 `HintAutoScroll.READ_DELAY/LINE_READ` 的阅读节奏；`HintAutoScroll` 的旧 pacing 函数由 `HintTicker` 取代，相关测试改为 ticker 口径。
- `HintPresentation.renderReport` 的 `scrollMillis` 字段改为 ticker 口径（如 `ticker=true`/`offset=`），不引用已删除的 pacing。

#### 5.2.3 四向键翻页

- `KEYCODE_DPAD_DOWN` / `KEYCODE_DPAD_RIGHT` → 向下翻页；`KEYCODE_DPAD_UP` / `KEYCODE_DPAD_LEFT` → 向上翻页。
- 步长 = `min(剩余可滚动量, 视口高度 × 0.85)`；翻页同时停止 ticker。
- **边界**：官方 J 级只处理上下键，左右键交回父类；业主 P4 口径写「四向键翻页」，本版按业主口径把左右也映射为翻页（左=上、右=下）。这是对官方的有意扩展，P0 规格审阅时由业主确认。
- 仅处理 `ACTION_DOWN` 并消费，避免一次手势触发两次。

#### 5.2.4 钉住

- `KEYCODE_ENTER`（侧边触控单击）→ 切换 `pinned`：
  - 钉住：停止 ticker；右下显示 20 × 20 图钉图标（`PinIconView`，`GREEN_NORMAL` 40% alpha）；隐藏「单击钉住」文字；
  - 取消钉住：恢复 ticker（从当前位置）；显示「单击钉住」14 px `GREEN_40`。
- **与官方的差异（有意）**：官方 pin = `sendNotAutoExitToService(true)`（服务侧不自动退出）；EDITH 没有服务侧自动退出，因此把 pin 映射为「停止/恢复 ticker」，保留佩戴者的阅读控制。该差异写入本规格与 `DECISIONS.md`。

### 5.3 P5：STOP 与唤醒应答（U11/U12）

#### 5.3.1 眼镜 BACK 语义

- `KEYCODE_BACK`（侧边触控双击产生的按键）：
  - **忙碌**（`busyState.any(now)` 为真）：发送 `STOP` 给手机，**不退出**；手机收到后取消当前回合/主动请求并广播 `BUSY=false`；眼镜继续显示对话。
  - **空闲**：`finish()` 退出眼镜 Activity（回到系统/launcher）。
- 若当前没有已建立的会话身份（`GlassHintController` 无 session/generation），BACK 直接退出。
- 仅处理 `ACTION_DOWN` 并消费；避免系统返回把 Activity 再退一次。

#### 5.3.2 手机 STOP 处理

- `HintWireCodec` 新增 `HintCommand.Stop(sessionId, generation)`；手机 `CxrHintLink.onInbound` 识别 `STOP`：
  - 校验 `sessionId/generation` 与已建立会话一致；不一致拒绝并记 `P3_CXR stop refused`；
  - 一致则调用 `onStopRequest` 回调（由 `HostCompositionRoot` 设置），返回 true；
  - 不需要 ACK；重复 STOP 幂等。
- `HostCompositionRoot.requestStop()`：与 `requestHelp()` 同构，读取当前 `host.currentIdentity()`，发 `UserAction.Action.Stop`；无活动会话返回 false 并记日志。
- 插件 `SmartAssistantPlugin.stopAll()`：
  - 现有逻辑取消 wake turn / 标记 proactive hint cancelled / `wakeBusy=false` / `detach`；
  - **补一条**：在 `stopAll` 的锁内同时 `proactiveInFlight = false`，让 `publishBusy()` 立即广播 `BUSY=false`（U11 要求）；迟到的主动结果仍由 `hint.cancelled` 丢弃；
  - 既有 `Stop` 测试与 `SmartProactiveTurnTest` 追加「STOP 后 busy=false、迟到 hint 不显示」。
- 眼镜收到 `BUSY=false` 后停止思考/聆听状态与 ticker 对应状态；`busyState` 仍保留 60 s 上限兜底。

#### 5.3.3 线缆契约（STOP）

| 项 | 值 |
|---|---|
| 命令名 | `STOP` |
| `wireVersion` | `1`（不变） |
| 字段顺序 | `wireVersion`, `command`, `sessionId`, `generation` |
| 载荷 | `{"wireVersion":1,"command":"STOP","sessionId":"...","generation":N}` |
| 序号/ACK | **无**；STOP 是事件，不是可确认的显示请求；重复幂等 |
| 旧解码器 | 未知 `command` → `null`（安全失败）；旧手机忽略 STOP，眼镜不因此退出 |
| 旧眼镜 APK | 收到 STOP 会 `undecodable`；涉及 STOP 的验证两端同一次构建（D63） |
| 回退 | 删除 STOP 编解码/回调即可；wireVersion 不变，无数据迁移 |

- 该变更在 P0 规格中预先写明，P5 实施时按此执行；若 P5 实施中发现必须改字段/语义，需重新获业主批准（CONTRACTS §7）。
- `CONTRACTS.md` 在 P5 实现提交中更新 §4.1；P0 不改写当前契约。

#### 5.3.4 唤醒应答（U12/U6）

- **删除** `WakeAcknowledgement`（固定短语「在的」）及 `speakWakeAcknowledgement` 调用；不构造 `Assistance`，不产生提示/会话条目，不走 TTS。
- 新增 `WakeChime` 纯逻辑 + Android sink：
  - `DEBOUNCE_MILLIS = 800`；
  - `onWake(nowNanos, enabled): Boolean`：`enabled=false` → false；距上次播放 < 800 ms → false；否则 true 并记住本次时间；
  - 去抖按 **monotonic nanoseconds**，不读墙钟；
  - sink 抛异常不传播；播放失败只记一条计数日志，不影响唤醒本身。
- Android sink：平台 `ToneGenerator`（`STREAM_MUSIC`）短提示音（约 100–150 ms），**不引用厂商 FX 34**；`ToneGenerator` 在 composition `close()` 释放；不新增权限/依赖。
- **开关**：唤醒时读取 `speechOn.value`（「语音朗读」持久开关）；关闭时完全不响；开启时即使 TTS 引擎不可用，短提示音仍可响。开关文案从「唤醒后的「在的」也受这个开关控制」改为「唤醒后的短提示音也受这个开关控制」。
- 不产生 `Assistance` / `ConversationLog` 条目；测试用源码断言/删除旧测试钉住。

#### 5.3.5 测试与设备证据

- JVM：`HintWireCodecTest` 追加 STOP 往返/缺字段/版本/大小写/旧解码；`CxrHintLinkTest` 追加 STOP 回调/会话不匹配/无会话；`SmartAssistantPluginTest` 追加 STOP 后 busy=false 与迟到 hint 抑制；`WakeChimeTest` 追加关闭/首次/800 ms 边界/异常 sink；`WakeAcknowledgementTest` 删除。

## 6. 状态、缓存与生命周期

### 6.1 眼镜窗口缓存

| 事件 | 手机 `ConversationLog` | 眼镜 `ConversationLog` | 眼镜显示 |
|---|---|---|---|
| 会话开始（新 `HELLO`） | 保留（进程内完整会话记录） | **清空两条路由**，回 `WAKE`、未钉住 | 空 |
| 一次会话内 `SAID` | 追加对应路由 | 追加对应路由（若当前路由则显示） | 不切换 |
| 一次会话内 `SHOW` | 追加对应路由 | 追加对应路由，并切到该路由 | 显示该路由 |
| 一次会话内 `BUSY` | 记录/广播 | 更新忙碌电平，不切路由 | 状态行/球 |
| 手机「停止」 | **不变**（保留本次会话完整记录） | **不主动清空**；窗口仍打开则保留最后内容 | 最后内容 |
| 眼镜 Activity 销毁 | 不变 | 清空两条路由 | 窗口结束 |
| 新会话 `HELLO` | 不变 | 清空两条路由 | 新窗口 |

- 眼镜缓存**只在内存**，不落盘；`ConversationLog` 有界（现有 40 条/字符上限）。
- 手机 `ConversationLog` 是会话完整记录；本版不改其生命周期（P0 裁决 3）。
- 不新增会话结束线缆命令；如果业主后续要求「手机停止即清空眼镜」，需要新决策与新命令，不在 0.23 范围。

### 6.2 忙碌电平

- `HintCommand.Busy` 仍是电平；眼镜 `BusyState` 60 s 上限；STOP 后手机广播 false；眼镜本地不因 STOP 直接清空缓存。
- 忙碌状态影响：思考行/聆听行/球状态、左下提示文案（打断/退出）、BACK 语义。

### 6.3 唤醒与主动辅助隔离

- 两条路由的 `ConversationStore`、`ConversationLog`、`ContextManager` 均独立（现有 D74/D111 不破坏）。
- 主动辅助 `SHOW` 只切到 `PROACTIVE` 路由；唤醒内容不属于该路由，眼镜不显示（U7/U8）。
- 手机助手页手动切换只影响显示，不影响运行中的会话（现有 copy 保留）。

### 9.2 阶段纪律

- 上一阶段未验收，不自动进入下一阶段；每阶段独立走完整 Superpowers 流程（brainstorming 仅在范围变化时重开；计划由 P0 一次给出）。
- P1–P6 的实施可无人值守连续执行；审阅门只在 P0 规格/计划、P5 契约变化（若偏离本规格）和 P6 主观项停下。

- 每个阶段一个提交（或按计划拆分），提交信息写 `feat(0.23-Pn)`/`test(0.23-Pn)`/`docs(0.23-Pn)`；**不 push / 不打 tag / 不合并**。

### 9.3 设备与安装

- 手机：K40 `2696813b`，MIUI / Android 13 / API 33；新包 `com.sheen.rokid.phone` 首装可能被 MIUI 安装确认页拦下。
  - P1/P6 先启用/验证 `edith.phone.a11yprobe` 无障碍服务，预置 `CLICK_NOW` + `labels=继续安装,安装`，再执行 `adb -s 2696813b install -r <apk>`；探针点击成功则继续；失败再尝试 ADB/MIUI 可脚本设置（读现值后改、记录 `settings get/put` 证据）；仍失败才记 `NotMeasured`，并在 P6 末尾请业主手动确认一次。

- 眼镜：`1901092544027662`，固件 `1.26.011`；`adb -s 1901092544027662 install -r <apk>`；如签名不一致需 `uninstall`，先记录并确认不影响邻居工作线。
- 两端同一次构建（D63）：涉及提示/STOP 的验证必须同一提交构建的 APK。

### 9.4 无人值守与人工项

- **Agent 自动完成**：代码、JVM 测试、构建、安装尝试、截图、按键注入、日志、设备走查、文档。
