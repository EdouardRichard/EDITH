## 1. 目标与非目标

### 1.1 目标

把 EDITH 从「一次工具调用」的助手，变成「一个回合内连续观察—动作—验证、跨 App 把事办成」的手机内 Agent。衡量标准：

1. **任务成功率**：7 条固定语料的整组通过率；
2. **模型往返次数**：每条任务的模型调用次数相对 0.21 基线下降；
3. **不卡死**：重复/轮询/乒乓/全局断路器能终止并给出可解释结果；
4. **上下文稳定**：长任务不爆窗口；旧观察/旧图片按规则降级；
5. **用户体验**（R-15/R-20）：关键节点有反馈；不可逆动作双通道确认；STOP 可随时取消。

### 1.2 非目标（本版不做）

1. **锁屏/息屏解锁**：移出 0.25，下版本按 D6 配方做「工具执行时触发解锁 + 防误触」（D7）。本版只加任务期间**保持亮屏**的临时保护，不做解锁。
2. **安全锁屏**（密码/图案/指纹）：不支持；`isKeyguardSecure()==true` 时设备类工具不可用。
3. **AUDIO 输入**：本版只做 TEXT+IMAGE（R-04）；`InputPart.Audio` 保留但不在要求内。
4. **on-demand 工具路由**：工具面只有 6 个，不做首步路由。
5. **batch/job、读并行、replay、root、多设备、多会话并行**：后续版本。
6. **不改写 0.21/0.23/0.24 的任何验收行、证据或判词**；M2/AC-13/16 只做并列复测。

### 1.3 成功判据

- JVM：契约/规则/适配器测试全绿，新增测试覆盖本 spec 的每条规则。
- 设备：7 条语料各 3 次（T8 三子例各 3 次，共 27 次运行），从「已解锁 + 亮屏」起跑；整组通过率 + `capCalls` + 不卡死。
- 旧验收：产出 `M2-RETEST` / `AC-13-RETEST` / `AC-16-RETEST` 新行；旧判词不动。
- 证据：只记计数/id/哈希/状态；未测写 `NotMeasured`。

## 4. 架构设计

### 4.1 分层

```
Plugin / 模型侧
  └─ 语义工具层（device / shell / open / dial / notify_user / load_skill）
       └─ Agent Runtime（Loop 保护、预算、确认、上下文、执行器）
            └─ DeviceControl 内核（唯一持有设备状态与通道）
                 ├─ Accessibility 通道（树/节点动作/手势/文本/截图/窗口/事件）
                 └─ Shell 通道（Shizuku shell UID；命令/状态/截图）
```

原则：模型永远不知道「这是 a11y 还是 shell」；通道细节收在 DeviceControl；结果语义化；失败可解释。

### 4.2 模块与依赖

- 新增 **`:phone-app:assistant:device-control`**（纯 JVM，包 `com.sheen.rokid.device`）：
  - 依赖：`common/contracts/plugin-api`（仅类型）+ Kotlin 标准库；不依赖 Android；
  - 内容：Observation、RefRegistry、Revision/Generation、DeviceKernel、ActionPlanner、ResultEnvelope、ChannelHealth、ShellCommandClassifier、错误码；
  - 端口：`AccessibilityPort`、`ShellPort`、`ScreenshotPort`、`Clock`、`ArtifactStore`（fake 可注入）。
- `phone-app/app` 保留：`EdithAccessibilityService`（薄适配器）、Shizuku 绑定、`Unlock`（本版不做）、`HostCompositionRoot` 装配。
- `agent-runtime` 保留：Loop、ToolRegistry、ToolProtocol、策略、上下文；新增并发执行器与 envelope 投影。
- `model-runtime`：Responses/Chat Completions 图片编码、工具历史、usage。
- `plugin-smart-helper`：提示词、工具面描述、确认 UX、store 记录。
- 依赖方向：`apps → 本端模块 → common`；`device-control` 不依赖 `app`；`app` 依赖 `device-control`。

### 4.3 DeviceControl 内核

**状态**：

- `generation`：每次写动作 +1；
- `revision`：每次成功观察 +1；
- 最新快照缓存；前台/窗口/IME/旋转/电量状态；
- 通道健康：a11y（bound/connected/gesture/screenshot/window/events）、shell（ready/binder/rebind）。

**`ensureReady(kind)`（本版，不做解锁）**：

1. `isInteractive`：false → `DEVICE_SCREEN_OFF`（告诉用户「请点亮手机」）；不尝试唤醒/解锁。
2. `isKeyguardLocked`：true → `DEVICE_LOCKED`；`isKeyguardSecure` true → `DEVICE_LOCKED_SECURE`。
3. 需要 a11y 时检查绑定；需要 shell 时检查 Shizuku ready；失败给 `CHANNEL_UNAVAILABLE`。
4. **保持亮屏**：任务开始时获取有界亮屏锁（见 §4.12），任务结束释放；不获取 `ACQUIRE_CAUSES_WAKEUP`（不唤醒息屏设备）。

**并发**：

- 写路径单一 FIFO 串行；每个写动作后 bump generation 并自动观察；
- 读路径可并行但带 generation 屏障；读期间发生写则标记 `stale` 或重读（本版只允许不同通道的只读并行，上限 3）；
- 每个操作独立超时；a11y 调用用线程池 + Future 超时；turn 取消传到队列与在途操作。

### 4.4 观察模型

**节点字段**：

- role/className、text、contentDescription、viewIdResourceName、bounds、states（clickable/longClickable/editable/scrollable/checkable/checked/selected/enabled/focused）、actions（`getActionList()`）、collection/range、hint、paneTitle、tooltip、drawingOrder；
- 多窗口：`getWindows()`（需 `flagRetrieveInteractiveWindows`）；IME/悬浮窗单独成段；
- 截断：`truncated=true` 时**不得**声称 removed；只报告可见部分。

**ref**：

- 稳定 identity：viewId + className + text/desc + 结构路径 + bounds 指纹；
- 首次观察分配 `#n<id>`；同一 identity 在后续观察中尽量复用；
- 跨 revision 的 ref：默认 `NODE_STALE`；允许最多 2 次按 identity 自动重定位（e2e 做法），失败即 stale；
- ref 只用于定位；不暴露通道/坐标参数（D84）。

**渲染**：

- 首屏全量；后续 diff（added/updated/removed）；diff 超过 60 行或 >50% 变化回全量；
- 节点行示例：`#n16 button "Wi-Fi" id=android:id/title bounds=[..] states=[clickable,focused] actions=[click,long_click]`；
- 观察预算：文本 ≤16KB/400 行，截断到行边界并说明；被取代的旧树在上下文中降级（§4.9）。

**settle**：

- tap/double_tap/long_press：changeWait 2000ms；scroll：500ms；type：800ms；open：1500ms；held-still 上限 1000ms；
- 以事件 + 有界轮询兜底；静默判定约 508ms（S1 实测）；不固定 sleep。

### 4.5 动作模型

- **语义优先**：节点 `ACTION_CLICK`/`ACTION_LONG_CLICK`/`ACTION_SET_TEXT`/`ACTION_SCROLL_*`/`ACTION_EXPAND`/`ACTION_SELECT`；
- **手势兜底**：`dispatchGesture`（长按/滑动/多击/坐标）；需 `canPerformGestures`；
- **shell 兜底**：`input keyevent`（按键）、`wm`/`settings` 等；
- **坐标**：只作内部/视觉兜底；模型不传坐标参数；结果里可带 `via=visual` 诊断（不是模型参数）；
- **动作后自动观察**：所有 mutating 动作成功/失败都回当前观察（diff）；
- **三级语义**：`accepted`（平台受理）→ `applied`（独立观察有变化）→ `verified`（期望后置条件成立）；`applied=true` 只在独立观察后返回；Intent fire-and-forget 降级为 `accepted_only`；
- 失败动作也回当前观察，错误码分层（§7）。

### 4.6 结果 envelope

工具结果统一为 JSON（文本），图片以 artifact 引用：

```json
{
  "ok": true,
  "tool": "device",
  "action": "act",
  "channel": "accessibility",
  "accepted": true,
  "applied": true,
  "verified": {"kind": "screen_change", "rev": 42},
  "data": {
    "screen": {
      "rev": 42,
      "app": "com.android.settings",
      "activity": ".Settings",
      "ime": false,
      "truncated": false,
      "changes": {"mode": "diff", "added": [], "updated": [], "removed": []}
    }
  },
  "images": [{"artifactId": "img-20261019-...", "mime": "image/jpeg", "width": 768, "height": 1664}],
  "timing": {"actMs": 22, "observeMs": 47, "totalMs": 84},
  "error": null
}
```

- `detail`（旧 `ActionResult.detail`）保留为一行摘要，不塞 JSON；
- 大输出写 artifact + 分页；二进制只回 artifact id；
- 文本 ≤16KB/400 行；Shizuku 回包目标 ≤64K 字符（实测上限 520,187，留 8× 余量）。

### 4.7 工具面

**6 个工具**（按能力门控广告）：

| 工具 | 用途 | 主要参数 | 通道 | 风险/确认 |
|---|---|---|---|---|
| `device` | 观察/动作/截图/等待/状态 | `action`(observe/act/screenshot/wait/status)；observe: filter/window/since_rev；act: kind/ref/text/value/direction/from/to/duration_ms/key；screenshot: region/annotate；wait: text/foreground/idle/timeout_ms；status: — | a11y→shell | L1/L2；不确认（UI 层破坏性无法分类，见 §4.12） |

### 4.8 Agent Loop

| 机制 | 规则 |
|---|---|
| `generic_repeat` | 同 tool+args 重复 3 次 warning、5 次 critical；warning 以合成 tool result + 跳过该次调用返回，不额外模型往返 |
| `poll_no_progress` | 同观察指纹连续 3/5 次 |
| `ping_pong` | 两个工具交替 2/3 个周期无进展 |
| `global_circuit_breaker` | 全局 8 warning / 12 critical |
| 连续错误 | 相同错误 3 次终止；错误分类提示（ref/snapshot 失败→重新观察或视觉兜底） |
| 运行态提示 | 每轮注入非持久 `RUNTIME_STATE`（前台/待验证/已输入未发送/最后 revision），不写 store |
| 文本计划续跑 | 无 tool call 且文本像「接下来…」→ nudge 先观察再操作，最多 3 次；闲聊/问答不触发 |
| 工具超时 | 默认 30s；长工具单独配置；超时返回 `ACTION_TIMEOUT` + 是否可能已生效 |
| 步数/观察预算 | `countsTowardStepLimit` 只读工具可免计步；`maxObservations` 另设；`maxSteps` 只做挂死保护 |
| 取消 | `cancel()` 传到 executor/DeviceControl/队列/在途操作 |
| 指标 | 每轮 model/tool/observe 耗时、model calls、usage、nudge/overflow/images 计数；新增 `P3_METRIC`，不改旧日志形状 |

**多 tool call**：

- 只读、不同通道、`ActionDescriptor.readOnly` 标记为 true 的可并行（上限 3）；同通道与所有写串行；
- 结果按调用索引回填；
- `ProgressGuard` 改看观察状态指纹（只喂写；读轮询归 poll detector；stale generation 不算进展）。

### 4.9 上下文

**预算**：保持 D81 单一统一窗口预算；**不引入 per-category 预算**。在 D97 的 ① 之前插入 ⓪，作为对 D81 的**显式扩展**：

| 步骤 | 规则 |
|---|---|
| ⓪ 类型感知省略 | 旧 UI 树 → header + 「已压缩」；旧图片 → 文字摘要；超长工具结果 → 头尾 + 标记；**最后一条工具结果不被上下文裁剪（工具自身的 16KB 上限仍生效）** |
| ① 旧整回合 | 保持 D97；本轮工具轮 pin + 最近 N=2 轮/2 条 assistant 锚 |
| ② 记忆 | 保持 D97；带回合组时通常 no-op |
| ③ 压缩 | 保持 D97 的欠账语义；overflow 恢复见下 |

**图片**：

- 历史只保留最近 K=3 张完整图；更早降级为文字摘要；
- 长边 768 为初值；DeepSeek 会按尺寸重采样，**单图 ≤1024 tokens**（官方口径）；最终 K/尺寸按真实档案实测校准；
- artifact 缺失 → 可见文字占位，不静默丢；
- `ConversationStore` 只存 ImageRef + metadata，不存字节。

**overflow 恢复**：

- 本地 `ConfigurationRejected` 与 provider `CONTEXT_OVERFLOW` 两条检测；
- 最多 2 次确定性恢复：压缩 → 硬截断 → `CONTEXT_OVERFLOW`；
- 不用 LLM 摘要救当前请求（D100）；
- `ContextPlanner` 生产未接线，删除，避免第二套裁剪器。

**bootstrap/skills**：保留现有；`load_skill` 按需；不做 always skills 全文注入。

### 4.10 模型协议

**目标模型**：DeepSeek `deepseek-flash`（IMAGE+TEXT 输入、TEXT 输出）；档案 `inputs` 必须含 `IMAGE`，`outputs` 为 `TEXT`；AUDIO 不要求。

**Responses（权威）**：

- 工具历史：`function_call` / `function_call_output`（已支持）；
- 图片：`input_image`（data URL / 外部 URL / `file_id`），可出现在 user/developer 消息**以及 `function_call_output` / `custom_tool_call_output` 的输出里**；
- system/assistant 消息里的图片返回 400；
- 图片参数：`detail` = low/high/original/auto；单图约 ≤1024 tokens；
- 适配器把 `ToolOutput.images` 编码进 `function_call_output.output` 的内容项数组；D9 用 OpenAI OpenAPI + 公开 gpt-5.5 真实请求证实该数组可含 `input_image`，DeepSeek 官方示例同形状；4o/4.1 无公开实测。

**Chat Completions（兼容）**：

- 工具历史：`assistant.tool_calls` + `role: "tool"` + `tool_call_id`（本版修复）；
- 图片：仅 user 消息（OpenAI OpenAPI 明确 `role:"tool"` 只允许 string/text part；LangChainJS 对真实 OpenAI 实测 tool 图片返回 400）；工具结果图片用**兼容 workaround**：tool 结果只回文本，随后追加一条 user 消息带 `image_url`（`data:` URL）；DeepSeek 的 Chat 文档自相矛盾（API reference 称 tool content 可含 image_url，Vision 指南称仅 user 消息），**必须用真实 DeepSeek 档案实测后才可宣称可用**；
- `image_url.url` 用 base64 data URL；`detail` 可选；
- 保持 `input_audio` 代码但不在本版要求内。

**档案门控**：

- `ModelProfile.inputs` 缺 `IMAGE` → `PROFILE_MODEL_NOT_MULTIMODAL`，会话启动拒绝并提示更换模型；
- 现有纯文本档案（含默认 Responses）不静默降级；UI 明确提示；
- debug QwenOmni（TEXT+AUDIO）删除或迁移为 IMAGE+TEXT 调试档案；
- `InputPart.Image(localRef)` 通过新增 `MediaSource.resolveImage` 解析为字节/格式；不内联进 store。

**图片 token 记账**：

- DeepSeek 按尺寸折算，单图 ≤1024 tokens；`ContextBudgeter` 按该口径计成本；
- Chat Completions 兼容路径的 user 图片消息同样计入；
- 不做 OpenAI 28px tile 公式（只作参考，不写入 EDITH 预算）。

### 4.11 应用目录与 `open`

- 目录：`shell pm list packages -3` / `cmd package resolve-activity --brief` + label 解析；不依赖 App UID 的 `PackageManager` 可见性（修 M2/AC-13/16）；
- `open(target)`：
  1. URL（`http(s)://`）→ `am start -a VIEW -d`；
  2. 设置页（白名单）→ `am start -a <settings action>`；
  3. 其余 → 名称/包名解析：精确 label → 唯一/多候选；`APP_AMBIGUOUS` 返回候选（不 `done`）；`APP_NOT_FOUND` 明确未安装；
  4. 启动：`cmd package resolve-activity` + `am start -W -n <component>`；后台情况用 shell；判据是 UI 真的起来（AC-16）；
- `open(list=true)` 返回 `label (package)` 列表，截断标记；不静默选一个。

### 4.12 确认、风险与 UX

**确认闸门（R-03/R-18/R-20）**：

- 覆盖：数据不可逆（卸载/清数据/覆盖删除）与花钱；`dial`/`device`/`open` 永不确认；
- `shell` 分类器：
  - 只读放行：`pm list`、`dumpsys`、`settings get`、`getprop`、`ls`/`stat`、`am start` 等；
  - 不可逆确认：`pm clear`、`pm uninstall`、`rm`、`mv`、`dd`、`format`、`content delete` 等；
  - 复合命令逐段；未知/无法解析/`sh -c`/变量/编码混淆 → 确认（fail-closed）；
  - 可逆（`am force-stop`、`pm disable`、`settings put`）不确认；
- 确认在**执行前**由 host 闸门完成；`summary` 给佩戴者；
- 双通道：眼镜 TTS 念摘要 + 手机弹窗；手机点按或眼镜按键确认/拒绝；
- 键映射（spec 定）：确认态下 ENTER=允许、BACK=拒绝、超时（120s，D47）=拒绝；确认态暂停 pin 语义；
- 人时不计入回合预算（D49），等待顺延 deadline；
- **残余风险**：UI 层点击（App 内「删除/支付」）无法在工具层分类；`shell` 分类器可被混淆绕过；这两条在验收/文档中不得写成「已防护」。

**进度 UX（R-15）**：

- 开始：一句 TTS「好的，我来…」；
- 每工具一行（眼镜面板，现有 tool row）；
- 确认/失败/完成：TTS 一句；**不逐条念中间步骤**；
- 失败：一句人话 + 已完成的部分；错误码只进证据；
- STOP：立即取消，释放亮屏锁。

**亮屏（临时，R-10）**：

- 任务期间获取**有界亮屏锁**（`SCREEN_DIM_WAKE_LOCK` 或等价，**不带 `ACQUIRE_CAUSES_WAKEUP`**），释放于任务结束/取消；
- Activity 可见时用 `FLAG_KEEP_SCREEN_ON`；
- 不唤醒息屏设备、不解锁；`isInteractive=false` 时工具返回 `DEVICE_SCREEN_OFF`。

### 4.13 日志、证据与指标

- 只记计数/id/哈希/状态；不记正文（D117）；
- 新 `P3_METRIC`：model calls、tool calls、model/tool/observe ms、prompt/completion tokens、images、nudges、overflows；
- 不改 `P3_TURN`/`P3_TOOL` 的既有形状；
- 证据文件不可改写；原始日志/截图落 `.local/0.25-corpus/<date>/`（gitignored）。

| 层级 | 错误码 | 恢复建议 |

2. **Chat Completions 工具结果图片**：OpenAI OpenAPI 明确 tool 消息只支持 text；真实 OpenAI 实测 400；workaround（tool 文本 + 后续 user 图片）需真实 provider 验证；DeepSeek Chat 文档矛盾，必须实测。
3. **图片 token/K/768**：DeepSeek 官方单图 ≤1024 tokens；K=3/768 是初值，需实测。
4. **延迟**：observe/tap+observe/shell 的 p50/p95 未测；报告中所有延迟目标都是「目标/未测」。
5. **生产 a11y/Shizuku**：当前设备只启用探针；启用/绑定/rebind 需实测。
6. **屏幕超时**：仅亮屏锁临时保护；无解锁；`isInteractive=false` 时明确失败。
7. **确认 UX**：眼镜 ENTER/BACK 与 pin/BACK 语义关系需实测；TTS 可听性未测。
8. **UI 层破坏性动作/支付**：工具层无法分类；残余风险如实记录。
9. **M2/AC-13/16**：修复应用目录不保证整组通过；旧失败可能仍有平台因素。
10. **锁屏**：本版不做；D5/D6 证据与 D7 决定保留，下版本 pickup。
11. **Android 14+**：FSI 限制、`ACQUIRE_CAUSES_WAKEUP` 未来行为；K40 API 33 之外需重测。
12. **`TokenBudget` per-category**：D3 报告其仍驱动压缩；需复核并对齐 D81，未完成前不得声称上下文已统一。
