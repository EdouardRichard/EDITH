### 1.1 逐条澄清后的确切口径

- **U1/U2/U3/U4 都在手机 App**，不在眼镜端。眼镜端没有这四个页签。
- **U2 只约束手机端**：手机助手页 AI 左、用户右。
- **U9 约束眼镜端**：用户与 AI 都左对齐；用户行 14px `green_normal_70`，AI 行 16px `green_normal`；与官方 `recycler_item_page_ai.xml` 一致。
- **U8**：眼镜端去掉路由标签、去掉左右键切路由；`SHOW` 带哪条路由就显示哪条；两条记录仍可在本地缓存，但佩戴者没有切换入口；`SAID` 不切换视图。
- **U10**：眼镜端不再用"先停 1.5 s，再按 1.4 s/行滑"的阅读节奏；改为官方 `ValueAnimator` + 每帧 1px（前 3 帧跳过）。这会明确取代 2026-10-15 的业主裁决，需在新决策中写明取代关系。
- **U11**：STOP 是眼镜→手机的加法式命令；手机收到后发 `UserAction.Action.Stop`，由插件 `stopAll()` 取消当前回合/主动请求并广播 busy=false。线缆版本仍为 1；旧解码器对未知命令返回 null，属安全失败。
- **U12**：代码中的固定短语其实是「在的」（不是「好的」）；两者都删除。官方 `aiWakeSound` 是短音效 + 800 ms 去抖，不是语音。厂商 FX 音效 34 不可达，用平台合成音作等价替代；音效可听性需真机人手验证。

## 4. 仍未决 / 需要下一阶段确认的问题（不阻塞阶段划分）

1. **手机路由切换是否自动跟随**：当前手机助手页是手动「唤醒 / 主动辅助」切换；主动辅助到达时是否要自动切到主动页？业主未明确。
2. **技能/记忆详情交互**：点击 vs 长按；模态对话框 vs 全屏页；删除按钮是否保留在列表行。当前候选实现是"点击 + 模态对话框 + 删除留在行尾"。
3. **眼镜端"当前路由"缓存**：U8 已定"只显示当前路由"，但未定另一条路由的本地缓存是否保留到下次激活。候选实现保留缓存；若业主希望"激活即清掉另一条本机显示记录"，需在 P4 明确。
4. **提示 TTL 与 ticker 的关系**：`HintReadingBudget` 仍按旧阅读速度估算提示有效期（偏保守、更长）；是否要按官方 ticker 重算 TTL，属 P5/P6 的独立决策。
5. **手机新包安装**：K40 上 MIUI 以 `INSTALL_FAILED_USER_RESTRICTED` 拒绝首装；需要业主决定是否在设备上手动确认一次，或本版本手机端设备验收记 `NotMeasured`。
6. **真机人手项**：眼镜端侧边触控（单击钉住、四向翻页、BACK 打断/退出）、提示音可听性、佩戴可读性、功耗/存活，均需业主参与或明确接受 `NotMeasured`。

## 5. 实施阶段划分（每阶段独立走完整 Superpowers 流程）

> **规则**：每个阶段开始前，先 `skill` 加载并使用 `brainstorming`；需要规格的阶段写 spec 并请业主审阅；实施前用 `writing-plans` 写计划；编码用 `test-driven-development`；完成前用 `verification-before-completion`；文档按 `AGENTS.md` 更新。**上一阶段未验收，不自动进入下一阶段。**

### P0 —— 需求冻结与规格/计划（下一会话启动）

- **目标**：把本文 §1–§4 的澄清结论转成 0.23 的批准规格与实施计划；不写产品代码。
- **输入**：本文、官方归档、0.21 基线规格、`STATUS.md`、候选实现（仅作参考）。
- **Superpowers**：`brainstorming`（逐项确认 §4 未决问题）→ 写 `docs/superpowers/specs/2026-10-17-edith-0.23-*`（批准版）→ 业主审阅 → `writing-plans`。
- **出口**：业主批准 0.23 规格；计划中的任务、验收行、回退策略明确；候选实现的去留已裁决。
- **不做**：任何 UI/协议/测试代码修改。

### P1 —— 手机助手对话页（U1/U2）

- **范围**：`PhoneScreen.kt` 的 `AssistantTab`；固定标题/切换/聊天框，只有 `LazyColumn` 滚动；刷新图标在聊天框右上；AI 左、用户右气泡。
- **依赖**：P0 批准。
- **验收**：JVM 纯逻辑测试（对齐/路由标题/刷新描述）；手机设备截图（固定头不随滚动移动、左右气泡）；若 MIUI 仍拒装，设备半边 `NotMeasured`。
- **Superpowers**：brainstorming（是否自动跟随路由、气泡样式）→ spec/plan（若定 architectural）→ TDD → device verification。
- **不做**：技能/记忆页、眼镜端。

### P2 —— 手机技能与记忆页（U3/U4）

- **范围**：`SkillDirectoryView.read` 安全读取 + 技能内容对话框；`MemoryLogView.preview` + 记忆详情对话框；删除逻辑不变。
- **验收**：JVM 测试（路径白名单、未授权、空文件、缩略截断/code point、全文不丢）；设备渲染。
- **依赖**：P1（同一手机 UI 壳）可并行，但建议串行以保持验收清晰。
- **Superpowers**：brainstorming（交互形态确认）→ spec/plan（bounded 可在会话内设计，但业主指定完整流程则写 spec）→ TDD → device verification。

### P3 —— 眼镜官方视觉底座（U5 视觉 + U9）

- **范围**：官方 480×640/240dpi、底部 380px 黑面板、绿阶、px 字号、语音球、聆听/思考行、合规标识、上下 30px 遮罩；对话行**都左对齐**（用户 14px/70% 绿、AI 16px 全亮绿）。
- **不做**：滚动/按键/STOP/单路由切换逻辑（P4/P5）。
- **验收**：JVM 常量/文案/对齐纯函数；眼镜设备截图（空态/思考/聆听/多轮）；佩戴可读性 `NotMeasured`。
- **依赖**：P0；与 P1/P2 无代码依赖，可并行。
- **Superpowers**：brainstorming（视觉取舍/资产策略，不引入 libpag）→ spec/plan → TDD → device screenshots。

### P4 —— 眼镜单路由与官方滚动/钉住（U8/U10）

- **范围**：去掉路由标签与左右切路由；`SHOW` 决定当前路由；`SAID` 不切换；四向键翻页；1px/帧 ticker（前 3 帧跳过）；单击钉住/停 ticker；忙碌提示文案切换的前置状态（不含 STOP）。
- **验收**：JVM 纯函数（路由只显示当前、ticker 常量/跳过帧、钉住状态、提示文案）；眼镜设备截图（长内容滚动、钉住图标）；按键真机人手项 `NotMeasured` 或由业主实测。
- **依赖**：P3。
- **Superpowers**：brainstorming（U8 缓存保留/清空、ticker 起点/停止条件）→ spec/plan → TDD → device verification。

### P5 —— STOP 打断与唤醒应答（U11/U12）

- **范围**：
  - `HintCommand.Stop` + codec 往返/校验；`CxrHintLink` 回调；`HostCompositionRoot.requestStop()` → `UserAction.Action.Stop` → 插件 `stopAll()`；眼镜 BACK 忙碌发 STOP、空闲退出；提示文案「双击打断 / 双击退出」。
  - 删除 TTS「在的」；`WakeChime` 短提示音 + 800ms 去抖 + 语音朗读开关；不产生 `Assistance`/会话条目。
- **验收**：JVM codec/link/chime 测试；手机端 stop 事件测试或既有插件 Stop 测试；真机听感/打断因果 `NotMeasured` 或业主实测。
- **依赖**：P4（BACK 语义）；线缆契约变更需业主批准（U11 已批准方向，P0/P5 spec 仍要写清字段与回退）。
- **Superpowers**：brainstorming（STOP 字段、ACK 与否、旧解码器兼容）→ spec/plan → TDD → device verification。

### P6 —— 路由独立回归、端到端验收与文档收口

- **范围**：主动辅助不显示唤醒内容的回归（两端）；全量 JVM；两端同构建安装；眼镜/手机设备走查；`DECISIONS`/`CONTRACTS`/`ACCEPTANCE`/`STATUS`/evidence 更新。
- **验收**：全量 JVM 0 failures（计数从 XML）；两端设备证据；所有未测项逐条 `NotMeasured`；不把 `NotMeasured` 读成通过。
- **依赖**：P1–P5。
- **Superpowers**：verification-before-completion → 文档收口；review 可用 `requesting-code-review`。
