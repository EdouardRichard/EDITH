## 1. 背景、范围与判定

### 1.1 产品定义

EDITH（伊迪丝）是**眼镜 + 手机 + 云端 LLM 的端云协同 Agent**，核心命题是：

> 人工智能助手应全时感知用户周边的一切，适时向用户提供辅助。

由于当前技术边界，产品拆成两条链路：

- **唤醒词唤醒**：用户唤醒后，识别意图、感知设备、全自主执行述求。
- **主动辅助**：全时收音，感知环境，合适时主动上屏静默提醒/辅助；具备持续对话能力，能基于最新输入输出最新提醒，或接受用户指令并执行述求。

0.3 的 Harness 优化必须服务这两条链路的**共同机制**，而不是给其中一条打补丁。

### 1.2 0.3 范围（业主 2026-10-20 批准）

0.3 = **全栈 Harness**：

1. 系统提示词体系（资源化、版本化、静态/动态分离、设备画像、动态时间、路由姿态）；
2. 上下文布局与 KV/提示词缓存（稳定前缀、尾部动态块、记忆/感知/技能正文尾置、命中遥测）；
3. profile-driven 预算与四层压缩（不使用任何固定 4096/8192 尺寸）；
4. 感知层（完整性优先、紧凑快照、ref 生命周期、动作后强制快照、视觉兜底）；
5. 主动辅助链路（可续听 + 可执行）；
6. 工具面延迟优先与规范整治（atomic 工具重新接线为默认 fast path、umbrella 工具保留、默认 24 个、两档路由；不退役；硬编码提示词、死代码、字节当 token 等）。

### 1.3 非目标

- 不新增硬件、眼镜固件、CXR 传输协议或厂商 API；眼镜↔手机互联仍按官方 demo/样本（D41/D44）。
- 不做独立 VLM 供应商/凭证；视觉复用用户配置的主模型多模态能力。
- 不做全时摄像头/录像；感知仍以屏幕、通知、媒体、日历、声学、设备状态为主。
- 不做云端长期记忆/跨用户共享；长期记忆仍在本机加密命名空间。
- 不恢复面试助手（P4，D57 搁置）、声纹注册、SELF/OTHER/UNKNOWN 归因。
- 不重写 0.25/0.26 的验收判词；旧语料只按最新 amendment 重跑，结果并列。
- 不把 JVM 通过、模型自述或盲问答对当成设备行为通过。

### 1.4 与 0.27 报告的关系

[`0.27-PERCEPTION-OPTIMIZATION.md`](../../project/0.27-PERCEPTION-OPTIMIZATION.md) 是 0.3 的**感知输入**，不是独立版本：

- 其 P0（紧凑快照、ref 生命周期、变更后观察/验证、模型可见状态、截图/VLM 兜底）进入 0.3 §7；
- 其 P1（perception matrix、失败分类）进入 0.3 §10 验收；
- 其 P2（工具结果压缩、预算/步骤/循环可配置、过程可观测）进入 0.3 §5–§6；
- 其“明确不做什么”保留：不复制 X-OmniClaw 代码、不把盲问答对当感知通过、不把模型自述当副作用证据、不为通过语料放宽判据。

## 2. 决策与取代关系

以下决策由 2026-10-20 头脑风暴逐项确认；**编号为 proposed，待 implementation plan 写入 `DECISIONS.md` 时定稿**。旧判词与旧证据不改。

| ID | 决定 | 理由/边界 | 取代关系 |
|---|---|---|---|
| **D175** | 0.3 采用 **A′：机制归基础层，内容/策略归插件层**；基础层不得出现 EDITH 业务字面量 | 统一 harness 但不模糊分层；用架构测试钉住 | 无 |
| **D176** | 系统提示词资源化、版本化；静态段进 system，动态块进请求尾部；提示词版本按会话钉住 | DeepSeek 前缀缓存以 system 为前缀，system 变化会让历史全 miss；DSH 的 runtime-context 也是尾部独立快照 | 取代 `SmartPrompts` 硬编码、`ContextManager` 重复选择 |
| **D177** | 预算完全由用户配置的 `ModelProfile` 派生；删除固定 `TokenBudget(4096)` 与 8192/1024 预填；统一 `TokenMeter` | 业主明确“不允许写死”；1M/256K 只是示例，不是常量 | 取代插件固定预算；D81 的统一窗口预算保留 |
| **D178** | 缓存布局：system（静态）→ history（append-only）→ 动态尾部（时间/设备/感知/记忆/技能正文）→ 用户话语；压缩点之外不改前缀 | 记忆/感知/技能正文尾置是最大缓存收益；压缩是唯一允许重写前缀的时点 | **supersede D99 的“记忆/感知线上折进首条 user 消息”部分**；摘要头部落位保留；D72 的“不进 system/不写 store”保留 |
| **D179** | 感知完整性优先：屏幕/通知/媒体/日历/剪贴板/声学/设备/眼镜内容进入模型上下文；**凭证也不做内容级例外**；日志/证据仍零正文；只发配置的模型服务 | 业主 2026-10-20 裁决：感知层核心目标是让模型感知到需要感知的一切，不因隐私/安全漏内容 | **supersede 通知 category-only 口径、任何“status 不返回用户正文”口径**；D53 的会话同意覆盖感知内容，D117 只约束日志/证据 |
| **D180** | 视觉复用主模型多模态；profile 声明 `IMAGE` 且会话运行即默认可用，用户可关；不做独立 VLM 供应商 | 完整性优先；复用 D53 同意与现有 `InputPart.Image` 链路 | 取代“默认无截图/VLM”的 0.27 现状 |
| **D181** | 主动辅助支持“提示后无需唤醒词续听 + 接话后执行”；两条路由仍独立；唤醒抢占 FOLLOWUP_TURN | 产品定义要求主动辅助具备持续对话与执行能力 | **supersede D167 的“持续对话只属于 WAKE”**；D167 的路由隔离保留 |
| **D182** | 工具面**延迟优先**：0.3 **不退役**；旧 atomic 工具（a11y 5、Intent 5、Shizuku 5、launch 2、system_action 1）重新接线为默认 fast path；umbrella（`device`/`open`/`shell`/`dial`）保留；默认 24 个（+ 主动提示 `propose_hint`）；两档路由；工具集按 App 版本/会话固定，不按轮过滤；L3/L4 永不免确认 | 业主 2026-10-20 裁决“先不退役，保延迟”：atomic 工具可能更快、少一层 planner/settle/envelope；能力也更大 | **supersede 本 spec 早先的“只合并重复/退役”口径**；**supersede D83（0.3 重新启用 Intent 通道；后续版本再评估收敛）**；D121 工具面收敛延后，等延迟矩阵证明不回归再议 |
| **D183** | 压缩采用四层：类型感知裁剪 → 工具结果清理 → 整回合淘汰+记忆写入 → 结构化异步摘要；soft/hard 阈值由 profile 派生 | 1M 窗口不等于不压缩；context rot/延迟/成本需要高信号上下文；压缩点之外保持 append-only | D97 的裁剪顺序保留；D100 的压缩门保留；插件固定预算被 D177 取代 |

**风险接受**：D179 意味着密码/OTP/支付卡号等屏幕内容可能被发送到用户配置的模型服务。业主已明确选择“严格完整、不做凭证例外”。本 spec 不重复劝阻，但要求 §7.8 的记录边界、输出纪律与设置页风险说明必须实现。

## 3. 分层与模块契约（A′）

### 3.1 Ownership

```kotlin
    val terminalToolName: String?,           // propose_hint / notify_user 等
    val followUp: FollowUpPolicy,            // NONE / LISTEN / EXECUTE
    val maxOutputTokens: Int?,               // 每回合输出上限，默认 profile
)

data class ContextPolicy(
    val hardInputLimit: Int,                 // 由 profile 派生
    val softLimit: Int,
    val hardLimit: Int,
    val compressionThreshold: Double,        // 策略比例，可配置
    val hardMargin: Int?,
    val keepRecentTurns: Int,                // 策略，可配置
    val summaryMaxTokens: Int,               // 由 profile 派生，可配置
    val toolResultRetention: Int,            // 策略，可配置
)

data class PerceptionPolicy(
    val elementLimit: Int,                   // 由动态预算派生/可配置
    val notificationLimit: Int,              // 可配置
    val refTtlMillis: Long,                  // 可配置
    val includeClipboard: Boolean,           // 可配置
    val includeVision: Boolean,              // profile IMAGE + 用户设置
)
```

`RequestLayout` 负责：

- 校验 system 段必须来自静态来源（`INSTRUCTIONS`/`SKILL`/`MEMORY_POLICY`）；
- 规定 flow 顺序：`TRANSCRIPT/SUMMARY` → 动态块（`PERCEPTION`/`MEMORY_EVIDENCE`/`SKILL_BODY`/`RUNTIME_STATE`）→ `USER_INPUT`；
- 计算 `PrefixHash`（system + tool specs + history prefix）；
- 拒绝把动态段放进 system，拒绝动态内容改写 history 头。

`SegmentOrigin` 增加 `SKILL_BODY`（trusted，会话流，位于 `USER_INPUT` 之前）：`load_skill` 拉到的正文作为本轮动态段，不再进 system；`ModelClientGateway.frameToTranscript` 把 `MEMORY_EVIDENCE`/`PERCEPTION`/`SKILL_BODY`/`RUNTIME_STATE` 渲染到请求 `input` 的用户话语之前，而不是折进 `history[0]`。`SUMMARY` 仍留在 history 头（压缩点才变），因此 `D99` 只 supersede 记忆/感知部分，摘要的头部落位保留。

`ContextPolicy.from(profile)` 与 `TokenMeter` 的细节见 §5；`TurnPolicy` 由插件构造，基础层不认识 `WAKE`/`PROACTIVE`。

## 4. 提示词体系

### 4.1 资源、清单、加载、渲染

```text
plugin-smart-helper/src/main/resources/prompts/
  manifest.tsv                 # id \t file \t kind \t version \t description
  core/00-identity.md
  core/10-operating.md
  core/20-tools.md
  core/30-safety.md
  core/40-output.md
  core/50-memory-policy.md
  route/wake.md
  route/proactive-hint.md
  route/proactive-followup.md
  context/device-profile.md    # SESSION_STATIC，占位符只允许 DeviceProfile 字段
  context/runtime-state.md     # DYNAMIC 模板，每请求刷新
  loop/retry.md                # base 层通用循环机制（在 agent-runtime 资源）
  loop/plan-nudge.md
  summarizer.md
  proactive-gate.md            # PINNED，Laya 微调问句
```

- **格式**：UTF-8 Markdown，无 front matter；清单用 TSV（不引入 YAML 解析器）。`manifest.tsv` 列：`id`、`file`、`kind`、`version`、`description`。插件是 JVM 模块，`src/main/resources` 随 jar 进 APK；用 `ClassLoader.getResourceAsStream` 读取，不依赖 Android resources。
- **kind**：
  - `STATIC`：进 system，不含任何占位符；改动必须更新版本与 golden hash。
  - `SESSION_STATIC`：进 system，只允许 `DeviceProfile` 的会话内稳定字段；每会话渲染一次。
  - `DYNAMIC`：进请求尾部，按请求渲染；允许 `DeviceState`/`PerceptionSnapshot`/记忆/SKILL 正文槽。
  - `PINNED`：内容受外部约束（例如 Laya 微调问句），不得随文案优化顺手改；它可以作为 system 段，也可以作为 gate/独立调用的固定 prompt。改动必须重新标定。
- **渲染**：`PromptRenderer` 只支持 `{{name}}` 严格替换；缺失/多余/未解析一律抛错。`SESSION_STATIC` 不允许动态槽；`DYNAMIC` 不允许静态槽混入。值做控制字符清理与长度截断；不得把用户内容直接插进 system。
- **版本**：`PromptCatalog.VERSION` 是 semver；`PromptPlan.hash` = 静态段顺序拼接后的 SHA-256。每次请求记 `P3_PROMPT version=… hash=… staticChars=… dynamicChars=… route=…`（只记计数/哈希，不记正文）。
- **会话钉住**：`activate` 时加载一次 `PromptPlan`；会话中途不换版本。要换提示词 ⇒ 新会话（或未来 provider 支持 `in-history` system update 时追加，见 §5.5）。

### 4.2 静态系统提示词内容

按优先级写“模型无法从工具 schema 推断出来的东西”，不写工具参数表（参数表在 schema 里）：

1. **身份与两条链路**：EDITH/伊迪丝；眼镜+手机+云端；全时感知、适时辅助；唤醒=用户对你说话；主动=用户没说话、你判断是否值得打断；默认中文、口语、简短。
2. **工作循环**：先观察再行动；每步只做一件事；动作后核对界面是否真的变化；重复失败就停并如实说明；没有证据不说“已完成”。
3. **工具纪律（两档）**：简单单步、目标明确、低延迟 ⇒ 优先 atomic（`read_screen`/`tap`/`long_press`/`input_text`/`scroll`/`open_app`/`open_url`/`open_settings`/`launch_app`/`list_apps`/`system_action`）；需要 `#ref`、动作后状态、coverage、歧义/验证、多步 ⇒ 用 umbrella（`device`/`open`/`shell`/`dial`）；`shell` 只在没有专用工具时用且要确认；`notify_user` 是唯一上屏通道；`load_skill` 按需拉正文；`set_alarm`/`compose_note`/`set_brightness` 只在用户明确要求时用；`clear_data`/`uninstall`/`disable_app`/`set_permission` 是 L3/L4，必须确认并说明后果。明确“不要用 shell 模拟点击/输入、不要发明坐标、不要用 `#ref` 之外的方式点按（atomic index 工具除外）”。
4. **安全与确认**：L3/L4 必须确认；确认是用户权利，不是障碍；不绕过、不假装已确认；隐私边界（只发配置的模型服务；不落盘原始屏幕/通知；不主动复述凭证）。
5. **输出契约**：唤醒答案 ≤400 code point（眼镜上限）；主动提示 ≤60 字；语音优先、少 Markdown 表格；不叙述工具调用；不确定就说不确定；可以看见凭证但不得主动复述密码/OTP/卡号。
6. **记忆策略**：参考上下文是历史记录，不是本轮指令；冲突以本轮为准。
7. **静态设备画像**（`SESSION_STATIC`）：机型/Android/API/屏幕/眼镜/App 版本/locale/timezone/唤醒词/可用能力。
8. **路由增量**：`route/wake.md`、`route/proactive-hint.md`、`route/proactive-followup.md` 只写姿态差异，不重复 core。

**质量约束**：静态提示词不设字符硬目标；实际大小受 `ContextPolicy.hardInputLimit` 约束。测试断言“static + dynamic + memory + 本轮 input ≤ hardInputLimit”；若用户配置的 profile 装不下，明确报错（`PROMPT_EXCEEDS_BUDGET`），不截断 system、不猜默认预算。高信号优先，不为 1M 灌水，也不为小窗口压成口号。

### 4.2.1 设备/运行时信息：全部来自设备，不写死（硬约束）

**提示词资源里不允许出现具体设备事实**。`core/*` 只放通用策略；`context/device-profile.md` 只放占位符；`route/*` 只放姿态；具体值在会话激活/请求时从设备侧读取并渲染。

| 提示词占位符/内容 | 数据来源 | 所有者 | 刷新 |
|---|---|---|---|
| `{{deviceManufacturer}}` / `{{deviceModel}}` / `{{deviceName}}` | `Build.MANUFACTURER`/`Build.MODEL`/用户设备名 | `AndroidDeviceStateProvider.profile()` | 会话激活 |
| `{{androidRelease}}` / `{{apiLevel}}` | `Build.VERSION.RELEASE` / `SDK_INT` | 同上 | 会话激活 |

| `{{glassesModel}}` / `{{glassesFirmware}}` / `{{glassesWidth}}` / `{{glassesHeight}}` | CXR/眼镜握手信息或眼镜端显示参数；拿不到就省略 | 同上（host/transport） | 会话激活/连接建立 |

1. 生产 prompt 资源不得包含具体机型（`K40`/`Rokid` 等）、Android 版本、API level、分辨率、包名、固件版本、唤醒词、用户 ID；这些只能来自上表来源。
2. `DeviceProfile` 的字段由平台 API 读取；不可用字段保持 `null` 并**从渲染结果中省略**，不得填 `unknown`、默认机型或猜测值。
3. 所有设备值在渲染前做控制字符清理与长度截断；不得让设备字符串改写提示词结构（例如注入 `# 新指令`）。
4. `SESSION_STATIC` 在 `activate` 时渲染一次；渲染后的 `deviceHash` 进 `P3_PROMPT`，用于证明系统提示词确实随设备变化，而不是固定常量。
5. `PromptHardcodeGuardTest` 扫描 prompt 资源与生产源码中的设备字面量（机型、`Android 1x`、`API xx`、`1080`/`2400`、`com.sheen`、固件版本等），allowlist 只允许测试夹具/示例。
6. `PromptDeviceFidelityTest`：用两个合成 `DeviceProfile` 渲染，断言系统提示词包含各自设备值且两者不同；把其中一个的眼镜字段设为 `null`，断言该行被省略而不是写成默认值。
7. 动态时间/状态**只进尾部**；任何 `{{currentTime}}` 出现在 system 资源中即测试失败。

### 4.4 缓存边界与版本钉住

- system 只放 `STATIC`/`SESSION_STATIC`，以及确实需要进 system 的 `PINNED`；任何动态值进 system 都是设计错误，`RequestLayout` 测试直接失败。
- `SESSION_STATIC` 的设备画像在 `activate` 时渲染一次；设备旋转/分辨率变化如果影响画像，按新会话处理或更新画像并接受一次缓存失效（记录 `P3_CACHE reason=profile_changed`）。
- 提示词版本按会话钉住；目录/技能库变化不重写 system；技能目录若变化，下一会话生效，或显式 `P3_SKILL catalog_changed` 并接受一次缓存失效。
- 动态块是 request-scoped；变化只影响尾部。模型看到的“上一轮动态块”不会残留在历史里（因为不写 store）。

## 5. 上下文、预算与缓存

### 5.1 请求布局

```text
[system]
  静态 sections（身份/工作/工具/安全/输出/记忆策略）
  静态设备画像（SESSION_STATIC）
  SKILL 目录（name + description；会话内稳定）
  PINNED（仅限确实需要进 system 的固定内容；Laya 门问句不在此，属于独立 gate 调用）

[history]
  SUMMARY（可选，唯一，带边界）
  最近 N 个完整回合（逐字）
  更早回合（压缩后只剩摘要）

[dynamic tail]
  RUNTIME_STATE / PERCEPTION / MEMORY_EVIDENCE / SKILL_BODY
  （按 §4.3 模板渲染；request-scoped；不写 store）

[user input]
  本轮用户话语（最后）
```

- **SKILL 正文尾置**：目录在 system；`load_skill` 拉到的正文进动态尾部（`SKILL_BODY` 段或标注块），不再进 system。这样一次 pull 只改变尾部，不改 system/history 前缀。
- **记忆/感知尾置**：`MEMORY_EVIDENCE`/`PERCEPTION` 从 `history[0]` 移到动态尾部；`frameToTranscript` 不再把它们折进首条 user 消息。
- **摘要留在 history 头**：摘要变化只在压缩点，属于可接受的一次性前缀变化。
- **动态块不写 store**：不进入 `ConversationStore`、不进入 `AgentRun.transcript`、不进入工具结果。
- **`USER_INPUT` 仍最后**：动态块在它之前；`RequestFrame` 的“one USER_INPUT last”不变量保留。

### 5.2 预算：完全 profile-driven

**唯一来源**：`ModelProfile`（用户配置/供应商能力）。代码里不得出现 4096/8192/1M/256K 这类预算常量。

```text
hardInputLimit = min(
    profile.inputBudgetTokens,
    profile.usableWindowTokens - profile.maxOutputTokens - profile.safetyTokens
)
```

- `inputBudgetTokens`、`usableWindowTokens`、`maxOutputTokens`、`safetyTokens` 由用户配置；缺失/为 0/窗口不足 ⇒ `PROFILE_INVALID`/`PROFILE_TOO_SMALL`，拒绝回合，不猜默认值。
- `TokenMeter`：CJK 1 字≈1 token、ASCII≈4 字符≈1 token、其他脚本按比例；加安全余量。`ContextBudgeter`、`TurnTrimmer`、插件估算共用同一实现；不再 bytes 当 tokens。
- `historyBudget = hardInputLimit - measured(system) - measured(dynamic) - measured(memory) - measured(input)`；不再按固定百分比切。
- `ContextPolicy` 校验：`0 < softLimit <= hardLimit <= hardInputLimit`；`compressionThreshold` 在 `(0,1)`；`keepRecentTurns >= 1`；`summaryMaxTokens > 0`；任一不满足即配置错误，不静默夹取。
- 静态/动态/记忆/工具结果的占用是**实测值**；超出时按 `ContextPolicy` 裁剪或拒绝，不静默改写 system。
- `TurnPolicy.maxOutputTokens` 显式进入 `ModelRequest.maxOutputTokens`；压缩摘要、主动提示、短答各自声明；profile 的 `maxOutputTokens` 只是窗口预留上限。两个适配器（`DeepSeekResponsesAdapter`/`OpenAiChatCompletionsAdapter`）必须使用 `request.maxOutputTokens ?: profile.maxOutputTokens`，并加测试。
- `ProfileForm` 不再静默预填 8192/1024；可以从显式模型目录/供应商能力预填，但必须展示来源并让用户确认；没有来源时要求用户填写；保存时做窗口/输出/安全预算校验。
- 真实用量以 provider `usage` 为准；`P3_METRIC` 记 estimated/actual 对照（计数，不记正文）。

### 5.3 缓存布局与遥测

- `PrefixHash` = SHA-256(systemText + tool specs + history prefix)；`P3_PROMPT` 记版本/hash/`deviceHash`；`P3_CACHE` 记 `cachedTokens`/`missTokens`/`inputTokens`/`systemChars`/`dynamicChars`。
- `ModelUsage` 新字段由适配器解析：
  - DeepSeek `prompt_cache_hit_tokens`/`prompt_cache_miss_tokens`；
  - OpenAI `prompt_tokens_details.cached_tokens`；
  - 其他协议可空，不编造。
- 不改变旧 `P3_METRIC` 形状；新增 `P3_CACHE`/`P3_PROMPT` 行，旧解析器不受影响。
- 测试：
  - 同一会话两次请求，时间/前台/记忆/感知变化 ⇒ system/history prefix hash 不变；
  - 压缩点 ⇒ prefix hash 变化一次，之后恢复稳定；
  - 提示词版本变化 ⇒ 新会话或显式 `profile_changed` 缓存失效；
  - 动态块不写 store。
- 设备读数：在最终 APK 上记录 cache hit 率；无读数记 `NotMeasured`，不写“缓存已优化”。

### 5.4 DSH 对照与未来升级

DSH 的做法是：稳定 `SystemPrompt.section` + 独立 `runtime-context` user 消息（变化时替换上一条）；支持 `in-history` 的 provider 可把变化后的 system prompt 追加到缓存历史之后。EDITH 0.3 采用等价语义：

- system 稳定、动态块在 input 尾部、不写 store；
- 提示词版本按会话钉住，不在会话中途改 system；
- 若未来 provider 明确支持 `in-history` system update，可把“技能目录/提示词版本变化”改为追加 system 消息，而不是新会话；0.3 不依赖该能力。

## 6. 压缩机制

### 6.1 目标

1. **不超窗**：任何请求都不超过 `hardInputLimit`。
2. **高信号**：不因 1M 窗口把无关旧内容全塞进去；压缩针对 relevance/context rot，不只针对容量。
3. **不丢当前回合**：本轮 `USER_INPUT` 与本轮工具轮次永不被裁。
4. **可缓存**：压缩点之外 append-only；压缩是唯一允许重写前缀的时点。
5. **不编造**：摘要只总结已发生的对话/动作；失败降级为截断。
6. **可审计**：只记计数/原因/哈希，不记正文。

### 6.2 四层

| 层 | 做什么 | 是否调模型 | 何时 |
|---|---|---|---|
| 0. 类型感知裁剪 | 旧 UI 树、旧图片、超长非最后工具结果 → header/摘要；保留最近观察 | 否 | 每次发送前（`TurnTrimmer` 已有，改用 `TokenMeter`） |
| 1. 工具结果清理 | 旧 tool output → 一行占位符，保留 call id/tool/状态；调用记录不丢 | 否 | 压缩点批量做；单条超大结果在当回合尾部处理 |
| 2. 整回合淘汰 + 记忆写入 | 从最旧整回合开始删；删前按现有 D87/D89 规则写长期记忆 | 否 | 超 softLimit 后、压缩点 |
| 3. 结构化异步摘要 | 被淘汰回合成结构化摘要，落 SUMMARY 头 | 是（同 profile，无工具） | 回合结束时异步；只影响下一回合 |
| 4. 硬兜底 | 摘要失败/未就绪 ⇒ 同步截断，记 `summary=none` | 否 | 发送前超 hardLimit |

层 0 是发送前的安全网，但**正常路径应尽量 no-op**：类型感知裁剪必须确定性、单调（只裁超过 age/turn 阈值的内容，已裁集合不缩小），否则每回合移动裁剪边界会让前缀缓存反复失效。层 0 真正裁掉内容时记 `P3_CACHE reason=type_elision`；若同一会话连续多次触发，应把该内容纳入下一次压缩点，而不是每回合重裁。层 1 的工具结果清理只在压缩点批量做，避免每回合改写中段。

### 6.3 阈值

```text
softLimit = policy.compressionThreshold × hardInputLimit   // 可配置比例
hardLimit = hardInputLimit - policy.hardMargin              // 可配置余量
```

- 回合结束实测超 `softLimit` ⇒ 启动异步压缩。
- 发送前仍超 `hardLimit` ⇒ 同步裁剪/清理，保证不超窗。
- `softLimit`/`hardLimit` 必须满足 §5.2 的 `ContextPolicy` 校验；不合法即拒绝，不夹取。
- 不按固定“每 N 回合”或固定 token 数压缩；阈值/保留回合数/摘要预算都由 `ContextPolicy` 从 profile 派生或由用户显式配置。
- 压缩不救当前请求；它只影响下一回合（保留 D100 的语义）。

### 6.4 结构化摘要模板

`prompts/summarizer.md` 要求输出以下结构，中文、纯文本、无工具、无提问：

1. **当前目标与约束**：用户明确要求、不能违背的限制。
2. **已确认事实与偏好**：用户说过的、已确认的。
3. **已执行动作与结果**：成功/失败/未验证；只写动作与结果，不复述敏感正文。
4. **关键实体**：应用/页面/文件/ID；不含凭证。
5. **未完成事项与下一步**：待办、阻塞、待确认。
6. **禁止**：编造、补充建议、提问、调用工具；不要输出分析过程。

摘要预算 `summaryMaxTokens` 由 `ContextPolicy` 从 profile 派生/用户配置；摘要请求用 `ModelRequest.maxOutputTokens = summaryMaxTokens`。摘要替换旧摘要，不重复写长期记忆；摘要正文不进日志。

### 6.5 缓存行为

- 压缩点之前：history append-only；system 不变；只有动态尾部变化。
- 压缩点：SUMMARY 头替换旧回合，前缀一次性变化；之后重新稳定。
- 工具结果清理只在压缩点批量做，避免每回合改写中段；单条超大结果在当回合尾部处理。
- 压缩后记 `P3_COMPACT beforeTokens/afterTokens/droppedTurns/summary=ok|none/reason/ms`，并与 `P3_CACHE` 对照；缓存命中率异常下降时调整阈值，而不是静默接受。

### 6.6 不变量与测试

- 本轮 `USER_INPUT` 永不被裁；最近 N 个完整回合逐字保留（N 可配置）。
- 动态尾部（`PERCEPTION`/`MEMORY_EVIDENCE`/`SKILL_BODY`/`RUNTIME_STATE`）是请求级上下文，不参与历史淘汰；超预算时按来源截断/清理并标 `truncated`，不整段静默丢弃。
- 工具调用/结果整对淘汰，不产生孤儿。
- 摘要只以 `SUMMARY` origin + 边界进入；不冒充用户发言、不进 system。
- 摘要失败只降级为截断，不改变回合终态。
- 两条路由各自独立压缩，不共享摘要。
- 测试：
  - `ContextPolicyTest`：不同 profile（例如 8K/128K/1M 的用户配置）各派生一套预算，断言无固定常量、硬上限正确、装不下时拒绝；
  - `TokenMeterTest`：CJK/ASCII/emoji/混合；
  - `CompressionTest`：soft/hard 触发、摘要落头、最近回合保留、工具对完整、失败降级、当前轮不丢；
  - `CacheLayoutTest`：压缩点之外 prefix 稳定；压缩点只变一次；
  - 设备长会话：合成多轮 + 工具结果，读 `P3_COMPACT`/`P3_CACHE`，不记录正文。

## 7. 感知层（完整性优先）

### 7.1 原则

1. **模型应看到用户能看到的一切**：屏幕文本、通知标题/正文、媒体元数据、日历、声学标签、设备状态、眼镜状态、剪贴板（可读时）；只按噪声/尺寸过滤，不按内容类别过滤。
2. **缺失必须显式**：每个来源都有 `coverage`（`ok`/`truncated`/`unavailable(reason)`）；模型必须知道“我没看到”，不能把缺失当“没有”。
3. **内容只进模型上下文，不进日志/证据**：日志只记来源、计数、字符数、ID、哈希；不记标题/正文/屏幕文本。
4. **只发往用户配置的模型服务**：会话运行即同意（D53）；不新增第三方上传；不持久化原始屏幕/通知内容。
5. **凭证也不做内容级例外**（业主 2026-10-20 裁决）：屏幕/通知中出现的密码、OTP、支付卡号等，只要用户能看到，就进入模型上下文；输出纪律要求模型不主动复述，除非用户明确要求。
6. **设置页风险说明**：不增加额外同意开关（保持 D53 零旋钮），但设置页/首次使用需说明“感知完整性模式会把屏幕/通知内容（含可能出现的凭证）发送给所配置的模型服务”。

### 7.2 感知来源

| 来源 | 内容 | 缺失时 |
|---|---|---|
| 屏幕 | 前台包+Activity、窗口/IME/浮层、锁屏状态、屏幕尺寸、**全部可见文本**（消息、邮件、网页、列表、输入框内容）、可交互节点、选中/勾选/滚动位置 | `screen=unavailable(reason)`；不造空屏 |
| 通知 | 最近 N 条的 package/app、title、text、subText、bigText、category、postedAt、ongoing、action 标签 | `notifications=unavailable(no_access)`；不降级成“只有 category” |
| 媒体 | state、title、artist、album、progress、duration | `media=unavailable(no_session)`；保留 `audioActive` |
| 日历 | 今日事件标题 | 无权限/空 ⇒ `unavailable`/`empty`，区分开 |
| 声学 | VAD/语音/音乐/噪声标签（现有 `AcousticEvent`） | `acoustic=unavailable` |
| 设备 | 时间/日期/星期/时区、电量/充电、网络、亮度、音量、屏幕开关、锁屏、IME | 单项缺键 + coverage |
| 眼镜 | 连接、佩戴、面板可见、屏幕状态（宿主事件） | `glasses=unavailable` |
| 剪贴板 | 当前剪贴板文本（Android 10+ 仅前台/默认 IME 可读；能读就读） | `clipboard=unavailable(background_restricted)` |
| 视觉 | 截图（a11y 文本不足：canvas、播放器、滑块、搜索建议、广告遮挡、WebView） | `vision=disabled` / `vision=unavailable(no_image_profile)` |

通知来源改掉 `NotificationCategorySource` 的 category-only：`NotificationContentSource` 在用户已授予通知访问时保留 title/text/subText/bigText/action 标签；最多 N 条（N 由 `PerceptionPolicy.notificationLimit` 配置）；没有授权就明确 `unavailable`。

### 7.3 快照格式

以下示例中的通知/消息文本均为**合成内容**，只用于说明格式；验收证据不得使用真实用户正文。

```text
[Perception snapshot snap=17 at=2026-10-20T18:23:11+08:00]
coverage: screen=ok notifications=ok media=ok calendar=empty acoustic=speech glasses=ok clipboard=unavailable(background_restricted) vision=ok device=ok
foreground: com.miui.player/.PlayerActivity (QQMusic) | screen=on unlocked | ime=false | panel=hidden
screen: 1080x2400, elements=42/120 truncated=false
#n12 button "搜索" center=(540,320) [clickable]
#n13 text "稻香 - 周杰伦" center=(540,180)
#n14 seekbar "播放进度" center=(540,470) value=01:04/03:43 [editable]
...
notifications (last 3):
- com.tencent.mm | 微信 | 张三: 晚上一起吃饭吗？ | actions=回复,标记已读 | posted=18:21
- com.android.mms | 信息 | 李四: 文件收到了 | posted=18:18
media: PLAYING title=稻香 artist=周杰伦 album=魔杰座 progress=01:04/03:43
calendar: 19:30 项目评审
acoustic: speech (energy=medium)
device: battery=76% charging | network=wifi | brightness=50 | volume=40%
glasses: connected wearing panel=hidden screen=off
```

- 只过滤噪声：systemui/status bar/nav bar/不可见/零尺寸/重复节点；不过滤消息、邮件、网页、输入框、通知正文、媒体元数据。
- 尺寸上限是“可截断的完整性”：屏幕节点、单条文本、通知条数有上限；超限标 `truncated=true`，模型可 `device.observe(include=["screen"], filter=all)` 或 `include=["notifications"], limit=N` 继续读。截断不是隐私省略。
- `coverage` 必须渲染；模型知道哪个来源不可用/被截断。
- `bounds` 只在证据/调试结构化字段中出现；模型默认只给 `center`，避免坐标点击（D84 仍禁止模型传坐标）。

### 7.4 ref 生命周期

- `RefRegistry` 增加 `snapshotId`、`issuedAt`、前台 package/activity 绑定；TTL 策略（默认 20 s，可配置）；页面/包名变化即失效。
- `assign` 登记 ref；`resolve` 校验：snapshot 是否当前、年龄是否超 TTL、前台是否变化、ref 是否属于本 registry。
- 过期/跨快照 ref ⇒ `STALE_REF` + **一份新快照**；不可静默点到旧位置。
- `device.act` 接受 `#n12`/`n12`；先 resolve 再执行。
- registry 按会话/任务 reset，避免无限增长；ref 编号单调，旧 ref 不会误指新节点。
- 快照元素上限/ref TTL/通知条数都是 `PerceptionPolicy` 的可配置策略，不是硬编码常量。

### 7.5 注入时机

| 时机 | 内容 |
|---|---|
| 唤醒回合首个请求 | 完整感知快照（屏幕+通知+媒体+日历+声学+设备+眼镜+剪贴板+vision 状态） |
| 主动提示回合 | 完整感知快照（“值不值得打断”需要完整上下文） |
| 同一回合后续请求 | ambient state + 最近一次工具结果携带的感知更新；不重复整份快照 |
| `device.observe` | 按 `include` 返回最新快照（screen/notifications/media/all），带 `snap`/`coverage` |
| `device.act` 之后 | **强制**返回动作后快照/差分 + `applied` + `changed`/`NO_SCREEN_CHANGE` + 前台 + coverage |
| `device.status` | 设备状态 + coverage + 最近通知摘要（标题/正文可含，由 include 控制）；不重复整棵屏幕树 |
| `device.screenshot` | profile 支持 IMAGE 且视觉开启时，图片随主模型请求；关闭时返回 `VISION_DISABLED` |
| `device.notifications`（或 `observe(include=["notifications"])`） | 最近 N 条完整内容；模型需要回复/总结时用 |

- **强制复察落在工具层**：`device.act` 自带 post-action 快照/差分与 `applied`；没有 fingerprint 时 `RUNTIME_STATE` 标 `writeUnverified=yes`，提示先 observe 再写。`ProgressGuard` 继续用 fingerprint。
- **初始快照与 `device.observe` 共用 refs/`snap`**：模型可以直接用快照里的 `#n12` 行动，不需要先调 observe；ref TTL/页面切换/包名变化会让旧 ref 返回 `STALE_REF` + 新快照。

### 7.6 动作后验证与 `open` 验证

- `device.act`：返回 `applied`（界面真的变了）+ post-action 快照/差分 + `changed`/`NO_SCREEN_CHANGE` + 前台；失败/无变化时附一行“先观察再决定”的提示；`ActionResult.fingerprint` 继续供 `ProgressGuard`。
- `open`：前台 package/Activity 与 a11y 根一致性作为 `verified` 判据；返回 `resolvedPackage`/`foreground`/`verified` 结构化字段；日志只记类别/计数。
- 写未验证：`writeUnverified=yes` 进 `RUNTIME_STATE`；提示词要求先 observe；不把“没有 fingerprint”报成成功。
- 超时/取消：沿用现有 `ACTION_TIMEOUT`/`CANCELLED`/`uncertain` 语义，不新增静默重试。

### 7.7 视觉

- 视觉是完整性兜底，不是独立供应商：profile 声明 `IMAGE` 时，`device.screenshot` 的图片作为工具结果随主模型请求发送。
- 默认策略：profile 支持 `IMAGE` 且会话运行 ⇒ 默认可用，用户可在设置里关；关闭时 `vision=disabled`，模型明确知道。
- 关闭/不可用时返回 `VISION_DISABLED`/`VISION_UNAVAILABLE`，不静默用文字猜画面。
- 隐私：图片只进模型请求；日志只记 artifact id/数量/尺寸；不落盘仓库；验收用合成数据/本地截图。
- 成本：每张图计 token；`P3_PERCEPTION` 记 `images=`。

### 7.8 记录边界与风险接受

- **模型上下文**：完整感知内容（D179），包括凭证；只发用户配置的模型服务；会话运行即同意（D53）。
- **日志/证据**：只记来源、计数、字符数、ID、哈希、coverage；不记 title/text/bigText/屏幕文本/剪贴板/凭证；不落盘原始截图/通知。
- **输出纪律**：模型可以看见凭证，但不得主动复述密码/OTP/卡号；上屏/语音仍按产品长度裁剪；除非用户明确要求，不把敏感内容写进回答。
- **持久化**：不写 `ConversationStore` 的原始感知；长期记忆仍走现有 MemoryModule 规则，不因感知完整性额外落盘。
- **风险接受**：凭证可能被发送到模型服务；用户已明确选择严格完整性。设置页风险说明、日志扫描测试、证据合成数据是必须的缓解措施，不是可选项。
- **第三方**：不新增供应商/凭证/云上传；模型服务由用户配置。

### 7.9 验收

- 感知矩阵：
  - 盲问：回合结束后不调工具直接问“现在前台是什么/看到了什么”；记录模型答案 vs 实际截图/系统状态。
  - observe 后问：要求 `device.observe` 后再问；记录是否主动观察、ref 是否正确。
  - 动作后验证：`device.act` 后是否带回新快照、`applied` 是否与系统状态一致、是否出现 stale ref。
- 指标（只记计数，不记正文）：`foregroundCorrect`、`observed`、`staleRef`、`actVerified`、`snapshotTokens`、`images`、`coverageHonest`。
- 内容完整性用例：通知正文、屏幕消息/邮件、媒体标题、日历、剪贴板、声学标签；不可用来源必须回答“看不到/不可用”，不得编造。
- JVM：快照格式/过滤/截断、ref TTL/跨页失效/`STALE_REF`、act post-state、`open` verified、无坐标暴露、coverage 渲染。
- 设备：T7（盲问前台/媒体）、T2/T4/T7（多步 + 前台核对）、T6（视觉开启时）、T8a（歧义）按新布局重跑；旧判词不改。
- 日志扫描：用合成敏感串跑一轮，确认日志/证据文件 0 命中；命中即 FAIL。

## 8. 主动辅助链路

### 8.1 状态机

```text
IDLE
  → 感知事件（ASR final / 环境变化 / 定时）
  → GATE（Laya，用完整感知快照判断“值不值得打断”）
      ├─ 不值得 → IDLE（不调模型）
      └─ 值得 → HINT_TURN（同一 AgentLoop，TurnPolicy 只暴露 propose_hint）
                  → HINT_DISPLAYED
                      → FOLLOWUP_LISTENING（有界窗口，无需唤醒词）
                          ├─ 用户说话 → FOLLOWUP_TURN（同一 AgentLoop，正常工具面）
                          │              → 上屏/执行/确认 → 结束或继续
                          └─ 无输入 → 关闭窗口，保留提示到 TTL
```

- **GATE 不调大模型**：仍是 Laya 的 `ask(state, question)`；state 用完整感知快照。
- **HINT_TURN 不执行设备动作**：`TurnPolicy.tools = [propose_hint]`，`terminalTool=propose_hint`，`maxSteps=1`；模型只能给一句提示。
- **FOLLOWUP_TURN 是完整 AgentLoop**：用户接话后工具面恢复正常；L3/L4 仍走确认；STOP/BACK 仍按 D145/D173。
- **有界续听**：复用 `ConversationCycle` 的 10 s/120 s 语义；提示显示后开窗，用户无需再说唤醒词；无输入则关窗。
- **唤醒优先**：显式唤醒到来时取消未完成的 FOLLOWUP_TURN（不取消已上屏提示），记 `WAKE_PREEMPTED`；WAKE 路由照常打开。两条路由仍独立；D167 的“持续对话只属 WAKE”被 supersede，路由隔离保留。

### 8.2 提示词分叉

- `route/proactive-hint.md`：用户没说话；只有确信值得打断才调 `propose_hint`；一句 ≤60 字；不执行任何设备动作；不值得就什么都不做。
- `route/proactive-followup.md`：用户已经接话；这是正常任务回合；可以观察、执行、确认；按用户最新输入修正之前的提醒。
- 两段只写姿态差异，共享 core 的身份/工具/安全/输出/记忆策略。

### 8.3 与现有代码的接法

- `SmartAssistantPlugin` 的 proactive 路径从“一次 `gateway.turn` + 手工解析 `propose_hint`”改为 **HINT_TURN（AgentLoop + terminal tool）**；`propose_hint` 由插件自己的 `ActionExecutor` 实现，结果就是提示文本，不执行设备动作。
- 提示上屏后调用 `ConversationCycle.onWake(AssistantRoute.PROACTIVE, followupTurnId)` 开续听窗口；ASR final 进入 `SmartTurn(route=PROACTIVE)`，用同一 `ContextManager`/`ConversationStore` 装配请求。
- `propose_hint` 的 60 字上限、TTL、去重、cooldown、sensitivity 保留；`ProactiveAdmission`/`ProactiveGate` 不推翻。
- `ConversationDisplay` 的 `panelOpen/state/userFinal/assistantFinal` 继续按 PROACTIVE route 上报；眼镜仍只显示当前 route。
- 唤醒抢占、STOP、deactivate、断连都走现有取消路径；新增 `WAKE_PREEMPTED` 计数。

### 8.4 验收

- gate 拒绝时 **0 次模型调用**；
- hint 只出现一句、≤60 字、无设备副作用；`propose_hint` 不执行；
- 提示后不说话 → 窗口关闭、提示按 TTL 消失；
- 提示后直接说话（无唤醒词）→ ASR final 被接受、FOLLOWUP_TURN 执行、答案落在 PROACTIVE route；
- 唤醒抢占 → 不产生双回合/双上屏；
- L3/L4 在 FOLLOWUP_TURN 仍弹确认；
- 旧 0.24 的 WAKE 持续对话/TTS/STOP 行不回归。

## 9. 工具面与规范整治

### 9.1 工具面：延迟优先，atomic + umbrella 双档（D182）

**先纠正口径**：21 个是旧 `ExecutionRouter` 的历史，不是当前生产。0.25 Task 10 起，生产 `Capability.Actions` 是 `ToolCatalog`（`device`/`shell`/`open`/`dial`）；插件再加 `notify_user`/`load_skill`，合计 **6 个**。

**业主 2026-10-20 裁决：0.3 不退役，保延迟。** 旧 atomic 工具重新接线为默认 fast path；umbrella 工具保留；默认面约 **24 个**；D121 工具面收敛延后。

| 档 | 工具 | 通道/条件 | 说明 |
|---|---|---|---|
| atomic 感知/操作（5） | `read_screen`、`tap`、`long_press`、`scroll`、`input_text` | a11y | 快速 index 快照 + 动作；简单单步 |
| atomic 打开（5） | `open_app`、`open_url`、`open_settings`、`set_alarm`、`compose_note` | Intent | 直接 Intent，低延迟；Shizuku 掉线仍可用 |
| atomic 特权/设置（5） | `set_brightness`、`clear_data`、`uninstall`、`disable_app`、`set_permission` | Shizuku | 直接动作；L2–L4 |
| atomic 应用（2） | `launch_app`、`list_apps` | Shizuku | 直连 launch/list |
| atomic 系统键（1） | `system_action` | Shizuku | back/home/recents/notifications，lean |
| umbrella（4） | `device`、`open`、`shell`、`dial` | a11y/shell/call | 结构化感知/ref/验证/歧义/list/命令 |
| 交付（2） | `notify_user`、`load_skill` | plugin | 上屏/技能 |
| 主动提示（1） | `propose_hint` | plugin | 仅在 `PROACTIVE_HINT` 的 `TurnPolicy` 中广告 |

- **总数**：atomic 18 + umbrella 4 + 交付 2 = **24 个默认工具**；主动提示回合再加 `propose_hint`。历史 21 的“drift”现在变成**有意的延迟优先设计**，不再以收敛为目标。
- **名称唯一**：`dial` 只保留 `ToolCatalog` 的 `DialTool`（含权限/解锁门禁）；`IntentActionExecutor` 的 `dial` 不接线。组合根必须保证没有第二个同名 descriptor。
- **两档路由**：atomic 用于单步、目标明确、低延迟；umbrella 用于需要 `#ref`、动作后状态、覆盖/coverage、歧义、验证的多步任务。提示词与工具描述必须写清“什么时候用哪档”，否则 24 个工具会选错。
- **能力**：atomic 回归后，Shizuku 掉线仍有 `open_app`/`open_url`/`open_settings`；a11y 掉线仍有 `system_action`。之前那三个 fallback 不再是“能力必需”，只作为 umbrella 的优化项。
- **工具集生命周期**：按 **App 版本 + 会话开始时能力** 固定；不按轮过滤/增删。a11y/Shizuku/通话权限掉线时，保留广告并返回 `CHANNEL_UNAVAILABLE`（或按会话边界重算），不静默从 `tools` 删除；能力恢复在下一会话或显式刷新时接回。缓存前缀稳定。
- **缓存口径**：24 个 schema 固定，不按轮变化；前缀更大但稳定。工具面收敛/延迟对照不以牺牲缓存稳定性为代价。
- **延迟验收**：必须做 K40 延迟矩阵（atomic vs umbrella，单工具 p50/p95 + 回合总延迟）；如果某类任务 atomic 明显更快，提示词/描述应默认引导 atomic；如果 umbrella 更慢且没有省往返，优化 umbrella 或让 atomic 成为该类默认。没有矩阵就不声称“保延迟”。
- **`ExecutionRouter`**：可以重新接线其 atomic 后端，但必须通过组合根统一注册、名称去重；不能与 `ToolCatalog` 形成两个 `Capability.Actions` provider。

### 9.2 工具描述

- `ActionDescriptor` 增加 `description: String = title`；`ToolSpec.description` 取它。
- 每个工具写清“什么时候用/什么时候不用/失败怎么办/参数关键约束”，并明确 **atomic vs umbrella** 的选择：
  - **atomic 快速路径**：
    - `read_screen`：快速读屏/拿 index；不需要 `#ref`/覆盖/验证时用；需要紧凑 ref 快照时用 `device.observe`。
    - `tap`/`long_press`/`input_text`/`scroll`：基于最近一次 `read_screen` 的 index；简单单步用；多步/需要动作后状态时用 `device.act`。
    - `open_app`/`open_url`/`open_settings`：目标明确时直接 Intent；Shizuku 掉线时优先；需要名称歧义/系统应用/list/验证时用 `open`。
    - `launch_app`/`list_apps`：直连 Shizuku 的快速路径；需要统一验证/歧义/list 时用 `open`。
    - `system_action`：lean global key；不需要动作后状态时用；需要覆盖/coverage/复察时用 `device.act`。
    - `set_alarm`/`compose_note`/`set_brightness`/`clear_data`/`uninstall`/`disable_app`/`set_permission`：用户明确要求时；L3/L4 必须确认并说明后果。
  - **umbrella 验证路径**：
    - `device`：需要 `#ref`、post-action 快照/差分、coverage、跨多步验证时用；先 observe 再 act；`status` 不替代 observe。
    - `open`：需要名称解析/歧义/list/系统应用/前台验证时用；类别词保持原词。
    - `shell`：没有专用工具时才用；命令必须可解释；确认由用户做。
    - `dial`：用户明确要打电话时；号码校验/权限缺失如实返回。
  - **交付/主动**：`notify_user` 唯一上屏、最终答案、不在工具调用中叙述；`load_skill` 只拉目录里有的技能；`propose_hint` 只在主动提示回合、一句 ≤60 字、不值得就不调。
- `ToolContractTest`：描述非空、非标题复读、覆盖所有 24 个默认工具、提示词不引用未广告工具、每对 atomic/umbrella 都有“何时用哪档”的描述。
- `ToolRoutingTest`：给定典型单步/多步/歧义/掉线场景，断言提示词/描述引导到正确的档（JVM 决策测试；设备延迟由 §10.2 矩阵验证）。

### 9.3 硬编码提示词迁移

见 §4.5；额外要求：

- `SmartPrompts` 对象删除或只保留资源加载入口，不再含提示词正文。
- `ContextManager.baseInstructions` 删除，统一 `PromptCatalog`。
- `AgentLoop` 的 `RETRY_INSTRUCTION`/`PLAN_NUDGE_INSTRUCTION` 改为 base 层资源；`withoutRetryScaffolding` 按资源常量匹配，测试保持。
- `ProactiveGate` 的问句/选项迁移到 `PINNED` 资源；改文案必须重新标定，不能当作普通提示词优化。
- `DiagnosticTextPlugin` 的固定句迁移到插件资源；它不参与生产助手提示词，但同样受硬编码扫描约束。
- 用户可见文案（`ToolLabelMap`/确认摘要）与模型提示词分开管理；前者可本地化，后者影响模型行为。

### 9.4 其他规范问题

1. **预算/单位**：删除 `TokenBudget(4096)`；`ContextBudgeter`/`TurnTrimmer`/插件统一 `TokenMeter`；`ModelProfile` 字段按 tokens 解释；`ProfileForm` 去掉 8192/1024 预填，缺失/非法即拒绝。
2. **死代码**：`AgentLoop` 内构造的 `TurnRunner` 在 frame 路径上是死代码；删除或让 `TurnRunner` 成为正式装配 owner（二选一，不能两套）。
3. **activity**：`ScreenProjector.activity` 恒 null；用 `AccessibilityPort.foreground` 补前台 Activity，`open`/`device.status` 才能核对。
4. **通知**：`NotificationCategorySource` → `NotificationContentSource`；日志只记 category/count；模型上下文完整（D179）。
5. **日志**：新增 `P3_PROMPT`/`P3_CACHE`/`P3_PERCEPTION`/`P3_COMPACT`，只记计数/哈希/coverage；不改旧 `P3_METRIC` 形状。
6. **缓存遥测**：`ModelUsage` 缓存字段 + 适配器解析；没有 usage 的协议不编造。
7. **工具面口径**：把“历史 21 / 生产 6 / 验收 9”统一写成“atomic 18 + umbrella 4 + 交付 2 = 24 默认工具 + 主动提示 `propose_hint`；两档路由；不退役”，更新 `ACCEPTANCE.md`、`CONTRACTS.md`、基线规格、`STATUS.md`；旧判词不改。`ToolCatalog` 的 “exactly six” KDoc/测试、`ExecutionRouter` 的 “retired” 注释必须同步；组合根只保留一个 `Capability.Actions` provider，`dial` 单 owner。
8. **架构测试**：§3.6 的 6 条必须进 CI/JVM 测试；硬编码扫描必须覆盖新资源目录之外的源码。

## 12. 风险与未验证项

1. **严格感知完整性的安全风险**：凭证/OTP/卡号可能进入模型服务；已由业主接受。缓解：只发配置服务、日志零正文、设置页说明、输出纪律、证据合成数据。仍无法消除模型服务侧留存风险。
2. **1M 上下文成本/延迟/context rot**：profile-driven 不写死，但大窗口可能鼓励灌满；压缩/工具结果清理/高信号提示词是约束，不是保证。
3. **主动续听可能打扰用户**：有界窗口、提示 TTL、唤醒抢占、STOP；实际体验仍需设备测量。
4. **24 工具面的选择负担与 L3/L4 默认可见风险**：atomic + umbrella 并存会让模型选错档；`clear_data`/`uninstall`/`disable_app`/`set_permission` 默认可见。缓解：两档路由描述 + `ToolRoutingTest` + K40 延迟矩阵 + `WhitelistActionPolicy` 永不免确认 + 确认 UI 可感知 + 审计只记动作不记参数。旧语料若引用 atomic 工具可直接运行；若引用已不存在的工具才按业主 amendment 改，不能静默改判据或把 `NotMeasured` 读成通过。
5. **通知/媒体/剪贴板权限**：不可用时必须 coverage 诚实；不能把缺权限读成“没有内容”。
6. **视觉默认开**：成本/隐私/延迟上升；用户可关；关闭时模型必须知道 `vision=disabled`。
7. **快照/ref TTL 默认值**：20 s 是策略起点，不是实测最优；需要设备校准；校准前不声称“永不误点”。
8. **TokenMeter 估算误差**：与 provider tokenizer 有差距；用 usage 校准，保守余量；不声称精确。
9. **Provider 对 mid-session system prompt update 的支持**：0.3 不依赖；提示词版本按会话钉住；未来可升级。
10. **0.26 checkpoint 未在本提交中重验**：提交是工作树快照，0.26 的既有证据仍是来源；不把提交读成新验证。
11. **DSH 语义对照**：本 spec 用其“稳定 system + 尾部 runtime-context”思想；EDITH 的线缆形状不同，独立实现；不复制代码。
