## 1. 背景与问题

0.5 交付了纯手机模式的重命名、悬浮球、气泡、TTS 运行期开关/最终回答朗读和回声半双工。独立审查确认核心链路和 JVM 计数是真实的，但发现：

- **三个契约级缺陷**：旧消息透明度没有按「整卡 = 0.42 × 气泡透明度」渲染；球的透明度没有作用到白底/阴影；听写 owner 隔离没有实现（球会停掉 composer 的听写）。
- **TTS 回声生命周期漏洞**：`AndroidSpeechPlayer.close()` 不关闭 echo 窗口；唤醒 ack 与 player 双重 open；`setSpeechEnabled(false)` 与 `play()` 竞态；TTS `onStop` 未处理。当前 120s 看门狗掩盖了它们；业主已要求移除看门狗，必须先修所有权/关闭路径，否则会永久静音。
- **运行时/生命周期缺口**：权限运行中撤销不停 overlay；回答朗读中长按被回声静音吞掉；本地 Notice 永不过期；实际拖拽的 delta 与手势机/测试不一致；球靠顶部时气泡被裁；lifecycle 2.10.0/1.4.0 升级未记录、ViewTree owner 仍反射安装。
- **流程违规**：0.5 证据文件被原地改写（APK 哈希、K8/K9/K10、拖拽判词），旧负面读数只在 git 历史；共享无障碍探针被修改，违反 0.5 spec §10.2；计划承诺的运行时测试缺失。
- **业主新增**：气泡最多 2 条；整泡（卡片+文字）透明度都随滑块变化；给 Agent 的屏幕读取提示词增加 EDITH 悬浮球/气泡归属说明，避免 AI 误判。

## 3. 详细需求

### 3.1 重命名（C1）

- 用户可见字符串：`DetachUi.SWITCH_TITLE`、`DetachUi.PROACTIVE_DETACHED_NOTE`、`MainActivity` 两处长提示、`PhoneOnlyOverlayService` 的通知 channel 名称与通知标题、README/README.zh-CN、STATUS/ACCEPTANCE/DECISIONS/spec/plan/evidence 的当前称法。
- 测试：`DetachUiTest`/`SmartSettingsFormTest` 断言「纯手机模式」；`DetachGateTest`/`SmartSettingsStoreTest` 的内部标识断言保持原样。
- 不修改：`DetachGate`、`glassesDetached`、JSON 键、`P4_DETACH` 等日志事件名、通知 channel id `phone_only_overlay`。
- 旧证据不改写；新称法在新增证据/文档中记录。

### 3.2 纯手机模式的 10s 续聊（C2）

- 新增一个**只影响回答后续聊**的 seam：`SmartAssistantPlugin` 增加 `continueAfterAnswer: () -> Boolean = continueDialogue`（默认保持旧行为）；`ConversationCycle` 的 `onAnswerDone`/`onSpeechFinished` 后决定是否续聊时使用 `continueAfterAnswer`；queued utterance/其他使用 `continueDialogue` 的路径保持不变。
- 生产 `SmartWiring` 传 `continueAfterAnswer = { settings.continueDialogue && !phoneOnly() }`；`phoneOnly` 用已有的实时 seam；眼镜模式 `phoneOnly=false`，行为字节级不变。
- 唤醒后的初始 10s 窗口（`onWake`/`armListening`）不动；`armContinueOffLocked`/`onContinueOffTimeout` 仍是关闭路径，约 1s 后 `TurnIdle`、关面板。
- 设置页「持续对话」开关保留和已存值（眼镜模式仍用），加说明「纯手机模式下不生效，下一句长按悬浮球」。
- 气泡在回答后约 4s 隐藏（3s idle 隐藏 + ~1s TurnIdle），这是取消 10s 窗口的直接结果；按业主「其余逻辑不变」不额外加 hold。
- 测试：phone-only 回答后不续聊；初始 10s 仍在；眼镜模式 `continueDialogue=true` 行为不变；queued utterance 路径不变；`TurnIdle`/面板关闭时序。

### 3.3 手动 ASR 与 owner 隔离（C3/C4）

- `DictationTarget` 保持 `COMPOSER`/`BALL`；`HostCompositionRoot.stopDictation()` 改为带 target 的 owner-aware 形式（或等价的 `stopDictation(BALL)`/`stopDictation(COMPOSER)`），只有当前 owner 匹配才停止/取消。
- `PhoneOnlyOverlayService.beginLongPress` 记录 **BALL lease 是否真正被接受**；`endLongPress` 只在本次 accepted 时停止 BALL；`startDictation(BALL)` 被 Busy/NoSession 拒绝时不触碰 composer 的 lease。
- `PhoneScreen` 的 final/state/refusal 过滤显式 BALL owner；`owner == null` 放行（0.4 host-owned composer/cleanup；null 只可能携带 composer/Idle，不可能 BALL；直接测试保留）；BALL 的 final 由 service/host 的 BALL 路径消费；`TypedInput` 的 Stop 只在 COMPOSER owner 时显示；BALL lease 时 composer mic 禁用；球自己的麦克风 overlay/提示只针对 BALL。
- 长按开始、且回答仍在朗读：`speechRouter.stopCurrent()` + `echoMute.clear()`（或等价）在 `startDictation(BALL)` 之前完成；取消时也清理。
- 无会话/被拒：3–4s Notice，文案引导打开 App 开始会话；不显示「听写中」麦克风状态。
- 测试：composer 听写中按球不截断 composer；BALL 被拒不影响 composer；BALL accepted 后松手只停 BALL；页面/服务 owner 过滤；长按打断朗读。

### 3.4 回声与看门狗（C5）

- **先修所有权/关闭路径**（顺序不可颠倒）：
  - `AndroidSpeechPlayer.close()` 关闭 `echoMute` 并复位 active；`onStop`/cancel 也关闭；`setSpeechEnabled(false)` 停止当前朗读并清除。
  - `SpeechPlayerRouter` 用原子 owner 跟踪当前 handle，修 `target.get()` 与 `active.set(handle)` 之间被 off/close 穿透的竞态；stop 时取消并清除。
  - 唤醒 ack 不再「手动 open + player onStart 再 open」双重打开；ack 使用统一所有权，只 open 一次；ack 与普通播放的窗口生命周期不互相覆盖。
- `EchoMuteWindow`：删除 `watchdogNanos`/120s 时间上限；`open()` 不计算 `now + watchdog`（避免删除后 `Long.MAX` 推算式溢出）；新增显式 `clear()`；`close()` 仍保留混响尾（150ms）。
- 显式 `clear()` 的调用点：手动 BALL 听写开始、`setSpeechEnabled(false)`、会话停止、长按打断；player close/cancel 用 `close()` 保留 150ms 混响尾（不是 clear）；ack 的结束/取消由 ack 的 player 自己关闭，不在显式 clear 列表。
- 丢失 TTS 结束回调时，麦克风最多静音到下一次手动长按/关闭朗读/停止会话；**不会永久静音**，也不再依赖 120s 时间兜底。
- 已知边界（wake ack）：wake ack 由 `wakeAckPlayer.speakText` 直接播放，没有 router cancellation handle；长按/手动 BALL 的 clear 只解除半双工窗口，不停止 ack，ack 仍可听，BALL ASR 可能捕获。T12 设备 case 验证并记录；T11 final review 决定是否补 ack stop。
- 保留最终回答只在纯手机模式朗读；眼镜模式 HUD-only 不变。
- 测试：无结束回调 + `close()`/`clear()`；ack 双重 open 不再存在；off/play 竞态；`setSpeechEnabled` 创建/安装/释放/能力同步/持久化失败；`EchoMuteWindow` 不再有 120s 断言（改为 clear/close 断言）。

### 3.5 气泡：最多 2 条与整泡透明度（C6/C7/C10）

- `BubbleStackModel.MAX_VISIBLE = 2`；新的到达时：
  - 原最新 → 旧（开始 2s 保持 + 250ms 淡出，随后移除）；
  - 原旧 → 立即移除（按业主「其余逻辑不变」，不补 200ms 加速淡出）；
  - 最新只有一条，带尾巴；旧消息无尾巴。
- 整泡 alpha：
  - 最新：`Modifier.alpha(appearance.bubbleAlpha)` 包住卡片、文字、尾巴、阴影；卡片底色 `surface`（层内不透明）；渲染后卡片+文字都等于气泡透明度（75% 默认 / 30% 最低）。
  - 旧：`Modifier.alpha(appearance.oldMessageAlpha × fadeFactor)`；`appearance.oldMessageAlpha = bubbleAlpha × 0.42`；`fadeFactor = model.relativeAlpha / 0.42`（或模型直接暴露 0..1 的 fade）；渲染后卡片+文字都等于 0.42 × 气泡透明度（再乘 fade）。
  - `PhoneOnlyAppearance.oldMessageAlpha` 必须被 UI 实际使用；`PhoneOnlyAppearanceTest` 与 UI 的渲染数学测试同源；设置页文案不再说「文字不淡」。
- Notice：`BubbleStackModel` 给 Notice 一个 `dismissAfter`（3–4s），`purgeExpired` 到点移除；不依赖 `TurnIdle`；本地提示不占旧/新气泡的 2s 规则（或明确使用同一规则）。
- 旧消息 2s、250ms 淡出、3s idle 隐藏、最新尾巴、系统字体/颜色不变。
- 测试：2 条上限、第 3 条即时移除旧条、最新/旧 alpha 数学、Notice 过期、旧 2s、尾巴只在最新。

### 3.6 Agent 屏幕观察提示词（C8）

- 在 `plugin-smart-helper` 的 prompt catalog 增加一个稳定的 phone-only section（建议新 asset `prompts/phone-only/overlay.md`，manifest 增加条目；或 catalog 内置常量）：
  ```
  纯手机模式屏幕观察注意事项：屏幕截图/无障碍树中可能包含 EDITH 自己的悬浮球和消息气泡（半透明卡片）。它们是 EDITH 的界面，不是目标 App 的内容。不要把它们识别成目标 App 的控件、文本或状态，也不要点击悬浮球或气泡区域；需要读取目标 App 时，以目标 App 的窗口为准。
  ```
- `PromptCatalog.plan(route, profile, phoneOnly: Boolean = false)` 增加可选参数；phoneOnly=true 时追加该 `PromptKind.STATIC` section；`SmartAssistantPlugin` 的默认 catalog/active plans 使用 `phoneOnly()`；眼镜模式 `false`，计划/hash 不变。
- 提示词不含用户正文/截图内容；只描述 EDITH 自身的 overlay。
- 测试：phone-only 计划的 section/systemText/hash 含该文本；眼镜模式不含；`PromptPlan` 的既有不变量（无 DYNAMIC、无 slot、hash 随文本变化）保持；`P3_PROMPT` 哈希能区分两种模式。
- 这是缓解措施，不保证 AI 一定不误判；验收时用 prompt 测试 + 一轮带 overlay 的设备回合检查模型回复，行为层面的误判仍记为 NM/需业主判断。

### 3.7 悬浮球与 overlay（C9/C11/C12/C13/C14/C15）

- **球透明度**：一个 `graphicsLayer { alpha = ballAlpha }` 包住 shadow + 白圆 + 图标 + 麦克风 scrim；思考光环在层外；20% 时整颗球（包括白底/阴影）一起淡。
