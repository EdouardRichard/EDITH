## 1. 目标与判定

### 1.1 本阶段目标

Phase 3 必须同时做到两件事，缺一不可：

1. **主动辅助链路可运行、可验证**：gate 拒绝时 0 次模型调用；gate 通过时只产生一条 ≤60 字提示；提示上屏后无需唤醒词即可续听；用户接话后是完整任务回合（可观察、执行、确认）；唤醒可抢占未完成的 follow-up；两条路由仍独立。
2. **关闭或明确接受 Phase 2.2 残留**：R-07 failed-open 设备路径、P-08 完整 probe 窗口、设备 on-wire envelope/tri-state、设备 `status`/`wait`/`dial` 观察、设备 uncertain、loop timeout/throw 图片、`open`/`shell` 观察刷新与 250 ms、物理最高亮度、逐调用图片归属、0.25 冻结 27 行，以及 M1–M7。

### 1.2 判定规则

- JVM 通过只写 `Verified (JVM)`；设备未测写 `NotMeasured`；设备只覆盖一部分写 `Partial`。只有 **JVM 与设备证据都实际满足**的行才可写 `Verified`（纯设备行的口径见 §9.3）。
- `Partial` 不得写成 pass；`NotMeasured` 不得读成通过；有效失败不得改写成未测。
- 设备结论只来自 K40 `2696813b` + 眼镜 `1901092544027662`，显式 `adb -s`；不使用 `gradlew installDebug`；人工 UI 只用 `edith.phone.a11yprobe`。
- 日志/证据只记计数、稳定码、布尔、哈希、coverage、尺寸；正文/图片/标题/包名/号码/命令不入仓库。
- 旧 0.21/0.25/0.26 判词与 0.25 冻结 27 行旧读数不改；Phase 3 的新读数另列。

### 1.3 非目标

- 不做 Phase 4：atomic 工具重新接线、24 工具面、两档路由、硬编码提示词迁移、K40 延迟矩阵、旧语料全量重判。
- 不新增硬件、厂商 API、CXR 传输协议、第三方 VLM 供应商或新依赖。
- 不改 D53 同意口径、不落盘原始音频/声纹/感知正文、不新增上传。

## 4. 主动辅助链路架构

### 4.1 状态机

```text
IDLE
  → 候选（ASR final / ContextChanged / debug final）
  → 便宜准入（SmartProactive：DISARMED/BUSY/NOISY/VAGUE/COOLDOWN/DEDUP）
  → GATE（Laya，4-key 微调 state；不值得 → IDLE，0 次云模型调用）
  → HINT_TURN（AgentLoop；唯一工具 propose_hint；完整感知尾部）
      ├─ 模型不调用 → 静默，IDLE
      └─ 调用 → 校验 ≤60 字 → submitProactiveHint
                  → Displayed ACK
                  → FOLLOWUP_LISTENING（PROACTIVE route，有界窗口）
                      ├─ 用户说话 → FOLLOWUP_TURN（完整 AgentLoop，正常工具面）
                      │              → 上屏/执行/确认
                      │              → continueDialogue on → 新的 FOLLOWUP_LISTENING
                      │              → 可继续多轮，直到关闭/超时/STOP
                      └─ 无输入/超时/关闭 → 窗口结束，提示按 TTL 消失
  → WAKE 到来：取消未完成的 FOLLOWUP_TURN，记 WAKE_PREEMPTED；WAKE 回合照常
```

**关键语义**：主动路径不是“提示上屏就结束”。提示后的接话、执行、确认、**持续对话**与 WAKE 路由复用同一套 `ConversationCycle`/`SmartTurn`/`AgentLoop` **机制/代码**，但**不是同一条会话**：各自 route、store、turn 槽、摘要、显示与生命周期；差别在 system prompt（`PROACTIVE_HINT`/`PROACTIVE_FOLLOWUP`）与路由/存储。多轮续听走与 WAKE 相同的 `onAnswerDone` → `openContinuation` **机制**，但只在 PROACTIVE route 内；不能把 WAKE 的 turn/store 当作主动会话继续。

### 4.2 HINT_TURN

- **入口**：`runProactive(trigger)` 在通过 `activeGate()` 后不再直接 `gateway.turn`，而是：
  1. `perception.beginTurn()`（真实快照；失败/不可用不阻断，`PERCEPTION` 缺失由 coverage 表达）；
  2. 组装 `AgentRequest`：
     - `turnId = "proactive-<uuid>"`（hint identity 另用 `hint-<uuid>`）；
     - `utterance = proactiveMessage(trigger)`（只含“用户没说话”+ 最近转写 + 声学标签；前台/媒体/通知等由 PERCEPTION 尾部提供，避免重复）；
     - `instructions = promptPlan(PROACTIVE_HINT).systemText`（会话钉住）；
     - `history = PROACTIVE store.history()`；
     - `frameFor = frameBuilderFor(store, PROACTIVE, message, prompt, [propose_hint])`；
     - `allowPlanNudge = false`；
     - `perception = { renderer.render(snapshot, full = true) }`；
     - `onRequestBuilt = { logPromptRequest(PROACTIVE_HINT, it) }`；
     - `observationSource = null`（提示回合不执行屏幕工具）。
  3. 工具表只含 `ProposeHintTool`；`AgentLoop(maxSteps = 1)`；`policy = WhitelistActionPolicy`（L0，无需确认）。
  4. run 结束：
     - `COMPLETED` 且 `finalText` 非空、≤60 code point → `ProactiveHint` 上屏；
     - 其他终态/空文本/超长 → `P3_PROACTIVE silence reason=…`，不上屏；
     - 不论结果，`perception.endTurn()`、`endSkillTurn()`、清 `proactiveInFlight`。
- **ProposeHintTool**：
  - 名字 `propose_hint`；`scope = SCOPE_TERMINAL`；`risk = L0`；`requiresConfirmation = false`；`countsTowardStepLimit = true`；`timeoutMillis` 短（建议 5 s）；`screenObservation = false`；`idempotent = true`。
  - `execute` 解析 `{"text": string}`；非空、≤60 code point；返回 `ActionResult(Done, detail = text, execution = ToolExecution(Done, accepted = true), observation = null)`；非法参数返回 `Refused` + `PROPOSE_HINT_INVALID`（`accepted=false/applied=false`）。
  - **不执行设备动作**；`data` 只是文本，`AgentRun.finalText` 直接取它。
- **提示上屏**：复用现有 `submitProactiveHint`/`ProactiveHint` 的 submit/ACK/TTL 逻辑；`route=PROACTIVE`、`hintId`、`turnId` 不变。

### 4.3 FOLLOWUP_LISTENING

- **开窗时机**：`submitProactiveHint` 收到 `OutputStatus.Displayed`（`acceptProactiveDisplayed`）后，且 hint 未过期：
  1. 生成 `followupTurnId = "followup-<uuid>"`；
  2. 记录 `proactiveFollowup = FollowupWindow(hint, followupTurnId, openedNanos)`；
  3. `conversationCycle.onWake(AssistantRoute.PROACTIVE, followupTurnId)`；
  4. `P3_PROACTIVE followup open turn=<id> hint=<hintId>`。
- **窗口语义**：复用 `ConversationCycle` 的 10 s listening / pin 后 120 s close；`onPanelShown(PROACTIVE)` 正常处理；`onAsr(PROACTIVE)` 只对**可用** final 调用；空白/仅唤醒词的 revision 不取消窗口（显式偏差，Q4=A 已确认，见 P3-3）。
- **关闭**：`onListenTimeout`/`onClose`/`onStop` 对 PROACTIVE 调用插件回调，清 `proactiveFollowup` 与 `followupTurn`，记 `P3_PROACTIVE followup close reason=<timeout|ui_closed|stop|pinned_timeout>`；不取消已上屏提示（提示按自身 TTL 消失）。
- **接话**：`handle(TranscriptEvent)` 在 WAKE `acceptTranscript` 之前检查：
  - 若 `proactiveFollowup != null`、窗口未关闭、`revision.final && usable && !confirmation.onTranscript(...)`，则取消 cycle 窗口、清 `proactiveFollowup`，启动 FOLLOWUP_TURN；
  - 否则按现有 WAKE/主动候选逻辑处理。
- **唤醒优先**：`WakeDetected` 先取消 FOLLOWUP_TURN（若在跑）并清 `proactiveFollowup`，记 `WAKE_PREEMPTED`，再走 `openTurn`/`conversationCycle.onWake(WAKE, …)`。
- **持续对话（不是一次性提示）**：FOLLOWUP_TURN 的答案上屏后，按 WAKE 同样的 `conversationCycle.onAnswerDone(PROACTIVE, displayed, speech, answerVisibleUntilNanos)` 结算；`continueDialogue` 开时由 `openContinuation(PROACTIVE)` 开下一轮 10 s 窗口，下一句 ASR final 再次进入 FOLLOWUP_TURN，可继续多轮，直到关闭/超时/STOP。提示 TTL 只约束提示文本，不结束对话。`P3_CONV continue/close route=PROACTIVE` 与 WAKE 同形。

### 4.4 FOLLOWUP_TURN

- **回合引擎**：复用 `AgentLoop` + `SmartTurn` 的显示/取消/上屏路径；`SmartTurn` 增加 `route: AssistantRoute = WAKE` 与 `promptRoute: PromptRoute = WAKE`（默认保持 WAKE 行为）。新增 `followupTurn: SmartTurn?` 槽位，与 WAKE 的 `turn` 分开。
- **请求**：
  - `utterance = 用户接话文本`；
  - `instructions = promptPlan(PROACTIVE_FOLLOWUP).systemText`；
  - `history/frameFor` 用 PROACTIVE store；
  - 工具表 = 生产六工具（`device`/`open`/`shell`/`dial` + `notify_user`/`load_skill`）；
  - `allowPlanNudge = true`；
  - `perception = full snapshot`；
  - `runtimeState` 照常；
  - `onTextDelta`/`onToolStatus` 用 PROACTIVE route 发布；
  - `observationSource` 照常注入（M4 修复后的 source）。
- **显示/结束**：
  - `emit`/`settleDisplayedAnswer`/`settleNoDisplayAnswer`/`onSpeechFinished`/`acceptDisplayed` 按 route 分派；
  - `openContinuationTurn` 改为 route-aware：PROACTIVE 的答案结算后，`continueDialogue` 开则创建下一轮 `SmartTurn`（同一 PROACTIVE route），走同一 `onAnswerDone`/`openContinuation` 语义；`P3_CONV continue route=PROACTIVE`；
  - 上屏 route=PROACTIVE；`P3_CONV`/`ConversationDisplay` 的 `route` 为 PROACTIVE；
  - `Stop` 取消 WAKE 与 follow-up；`deactivate` 清理两者；
  - 不把 follow-up 的答案写进 WAKE store；两条路由各自压缩/摘要。
- **确认**：L3/L4 仍走 `ConfirmationGate`；确认等待不计入回合预算（D49）；证据用 a11yprobe 拒绝/允许。

### 4.5 路由隔离与存储（硬约束）

- `ContextRoute.PROACTIVE` 的 store/摘要只服务主动链；WAKE 不读取、不写入。
- **会话独立**：主动辅助与唤醒词唤醒是**两条独立会话**；复用 AgentLoop/ConversationCycle/SmartTurn/确认/显示是复用**机制**，不是复用会话、状态或存储。两条路由各有自己的 `ConversationStore`、`SmartTurn` 槽、cycle route state、摘要、prompt plan、显示 route 与生命周期；不得把一条路由的 history/摘要/turn 注入另一条。
- **ASR final 归属优先级**：WAKE `AwaitingTranscript` 的 turn 先消费 final；只有没有 WAKE turn 等待/运行时，PROACTIVE follow-up 窗口才消费 final。WAKE 回合进行中到达的 final 属于 WAKE，不进入主动会话；反之，主动 follow-up 的 final 不进入 WAKE。
- **续听/抢占不跨路由**：WAKE 的答案结算只开 WAKE 下一轮；PROACTIVE 的答案结算只开 PROACTIVE 下一轮；`WAKE_PREEMPTED` 只取消主动 follow-up，不改写 WAKE 的 turn；`Stop`/`deactivate` 可以同时清理两条，但不能把一条的 turn 当成另一条的。
- **显示/遥测**：`P3_CONV`/`ConversationDisplay`/`P3_PROMPT`/`P3_PERCEPTION` 都带 route；不得把 PROACTIVE 的答案/提示写成 WAKE，反之亦然。
- **测试**：并发 WAKE + PROACTIVE 时，final/answer 不串路由；WAKE 答案不打开 PROACTIVE 窗口；PROACTIVE 答案不继续 WAKE；两条 store 互不读取。
- `proactiveInFlight` 语义扩展为“HINT_TURN 或 FOLLOWUP_TURN 在飞”；`wakeBusy` 仍只表示 WAKE。`publishBusy()` 的 PROACTIVE 电平由两者合并，但 busy 电平不等于共享会话。
- `SmartProactive.admit` 的 `busy` 继续包含 WAKE 与主动链；避免同一窗口双请求。

## 7. 遥测与设备验收

### 7.1 新增 count-only 遥测

**`P3_TOOLRESULT`**（每次工具调用一行，由 `AgentLoop` 在 `observedFailure` 之后、`appendToolOutput` 之前发出）：

```text
P3_TOOLRESULT turn=<id> call=<id> tool=<name> outcome=<done|refused|failed|timeout|uncertain|cancelled>
  code=<stable|-> recoverable=<bool> accepted=<true|false|-> applied=<t|f|-> verified=<t|f|->
  changed=<t|f|-> uncertain=<bool> partial=<bool> observation=<none|text|image>
  vision=<ok|disabled|unavailable|not_requested> screenChars=<n|-> images=<n> shape=<8hex>
```

- `shape = ToolResultEnvelope.shapeDigest(result.payload)`；算法见 §7.2。
- `images` 是**该调用**的图片数（不是 run 合计）；`P3_METRIC images=` 仍是 run 级 distinct 计数。
- 不记 screen/正文/包名/标题/命令/号码；`code` 是稳定机器码。

**`P3_OBSERVE`**：

```text
P3_OBSERVE source=tool tool=<name> observeMs=<n> captureMs=<n> result=<ok|unavailable|disabled>
P3_OBSERVE source=loop ms=<n> timeout=<bool> images=<n> reason=<stable|-> 
```

- `source=tool` 由 `ToolCatalog`/`OpenTool` 在每次真实 observe/capture 后发出；`source=loop` 由 `PerceptionObservationSource` 发出。
- 计数/毫秒/布尔/reason；不含内容。

### 7.2 结构哈希

`ToolResultEnvelope.shapeDigest(payload: String): String?`：

1. 解析 payload JSON；
2. 递归替换所有字符串值为 `""`、所有数值为 `0`；布尔与 null 保留；对象键序保留；
3. 紧凑序列化（无空格）；
4. SHA-256；取前 8 位小写 hex；解析失败返回 `null`。

- 同一 envelope 形状（键、nullness、tri-state 类型）得到同一 digest；不同形状不同。
- JVM 测试固定 done/failed/uncertain/pure-tool 四种 digest；设备 `P3_TOOLRESULT shape=` 与 JVM 期望对照，证明运行期 envelope 不是旧 detail 字符串。

## 10. 风险与开放项

1. **gate 真实接受不确定**：Laya 是模型判断，同一语境也可能拒绝；A-02/A-04 的真实 gate 轮可能 `NotMeasured`。强制 gate 的对照轮只能证明链路，不能证明 gate 判断。
2. **提示模型可能静默**：HINT_TURN 的模型可能不调用 `propose_hint`；这是合法沉默，不能为了通过而改提示/放宽判据。
3. **回合引擎 route 化回归**：把 `SmartTurn`/`emit`/`settle` 参数化可能影响 WAKE 的 TTS/STOP/续听；用 WAKE 既有 JVM 套件 + 设备既有证据守住，不重跑 0.24 判词。
4. **250 ms 观察预算可能经常超时**：`refresh()` 在真实 a11y 上可能 >250 ms；超时就 `unavailable(observation_timeout)`，如实记录，不写“合规”。
5. **不新增 debug fault（Q3=最简）**：loop throw/timeout 图的设备行只能 `NotMeasured`，以 JVM + 既有 WAKE 证据为准；这是明确接受的边界，不用 debug seam 凑数。
6. **物理亮度（Q2=A0 已确认）**：无光度计，物理最高亮度只能 `NotMeasured`；不做专门改动，只记录设备实际 settings/mode/前台/亮屏，由模型识别；设置值/平台最大值不是物理亮度。
7. **27 行（Q7=C 已确认）**：Phase 3 不重跑；旧读数与旧判词原样保留，Phase 3 记 `NotMeasured`/deferred。后续版本若重跑，仍按冻结规则记录，不重判旧行。
8. **日志体积**：`P3_TOOLRESULT` 每次工具一行，长回合会增加 logcat 行数；只记计数/码/哈希，不记正文。
9. **gate state 不扩展（Q1=A0 已确认）**：主动 gate 看不到完整屏幕树；D1/D2/D3 是已知 drift，Phase 3 只记录、不修。这是 fine-tune 契约、256-token 窗口与范围纪律的取舍；业主 2026-10-21 确认接受。
