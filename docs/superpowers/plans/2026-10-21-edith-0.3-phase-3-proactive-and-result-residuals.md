# EDITH 0.3 Phase 3 — Proactive Chain + Result Residuals Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** Approved — owner selected **subagent-driven** execution on 2026-10-21. Not yet implemented.

**Goal:** Make the proactive chain (gate → one-sentence hint → no-wake-word follow-up listening → full task turn → wake preemption) work and verifiable on the K40, and close or explicitly accept the Phase 2.2 result-contract residuals (R-07, P-08, on-wire/tri-state, status/wait/dial, uncertain, loop images, refresh/250 ms, brightness, per-call images, 0.25 corpus, M1–M7).

**Architecture:** The proactive hint turn becomes an `AgentLoop` run whose only tool is a terminal `propose_hint`; the follow-up turn reuses the same loop with the normal six-tool face and a PROACTIVE-scoped `SmartTurn`. `ConversationCycle` gains a PROACTIVE follow-up window after the hint's `Displayed` ACK; a usable ASR final starts the follow-up turn, and a wake preempts it. The Phase 2.2 residuals are repaired in the existing result path, the loop observation source becomes a bounded real refresh with an image channel, and count-only `P3_TOOLRESULT`/`P3_OBSERVE` lines plus a content-free envelope shape digest make the device path auditable.

**Tech Stack:** Kotlin, kotlinx.serialization JSON, existing `agent-runtime`/`plugin-api`/`plugin-smart-helper`/Android accessibility + perception provider, Powershell device harness under gitignored `.local/`.

**Spec:** `docs/superpowers/specs/2026-10-21-edith-0.3-phase-3-proactive-and-result-residuals-design.md`

## Review Focus

- **Proactive route isolation:** a follow-up must never write the WAKE store, a wake must never consume the follow-up window, and STOP/close must cancel only the turn it names.
- **Gate honesty:** A-01 must prove zero cloud-model calls on a real gate refusal; there is no forced-gate run, and a gate that does not accept means A-02/A-04 are `NotMeasured`.
- **No duplicate shared tests:** AgentLoop/context/display/confirmation are WAKE-shared; only proactive-specific deltas get new tests/device evidence.
- **Session independence:** proactive and wake are separate sessions; tests must prove no final/answer/store/continuation crosses routes even when both are active.
- **Bounded listening:** blank/echo ASR must not make the follow-up window unbounded; the 10 s/120 s semantics must still close it.
- **Result-contract tri-state:** a post-dispatch throw must be `Uncertain`, never a pre-dispatch `Refused`; `null` stays unknown, never `false`.
- **Loop observation:** a 250 ms timeout is an explicit `observation_timeout`, not a silent cache read; a failure image must not enter store/transcript.
- **Device evidence:** P-08 scans the T7 probe window **before** `logcat -c`; physical brightness stays `NotMeasured`; per-call image counts must add up to the run metric, not replace it.
