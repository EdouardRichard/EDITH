# EDITH 0.3 Phase 2 — Perception Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the model actually perceive the phone — foreground app/activity, screen text, notifications, media, calendar, clipboard, acoustic/glasses state, and device state — with honest coverage, TTL-bound refs, forced post-action re-observation, and vision fallback, while closing the Phase 1 telemetry/trim gaps.

**Architecture:** `plugin-api` gains the additive perception contracts and `Capability.Perception`; `phone-app` implements `AndroidPerceptionProvider` over the existing accessibility port, notification listener, calendar/media/clipboard sources, and `DeviceStateProvider`; `agent-runtime` injects one request-scoped `PERCEPTION` segment before `USER_INPUT`; `plugin-smart-helper` renders the perception slots of `context/runtime-state.md` and logs counts only. Memory/SKILL bodies keep their dedicated tail segments (0.3 §5.1), so the system slot and history prefix stay byte-stable.

**Tech Stack:** Kotlin/JVM, Gradle, kotlin.test/JUnit5, kotlinx.serialization; Android APIs only in `phone-app`; accessiblity channel (`EdithAccessibilityService`), `NotificationListenerService`, `MediaSessionManager`, `CalendarContract`, `ClipboardManager`.

**Spec:** `docs/superpowers/specs/2026-10-20-edith-0.3-harness-design.md` — read §3.2, §4.3, §5.1–§5.3, §6.2–§6.6, §7 (all), §9.4, §10, §11. Phase 2 is the perception layer **only**; §8 (proactive chain) is Phase 3 and §9 (24-tool surface/norms) is Phase 4. Do not implement them here.

**Phase boundary and baseline:** branch `feat/0.3-harness`, HEAD `2850dc70`, Phase 1 closed at `8f40d4e1`/JVM gate 271/2662. Do not redo Phase 1. The old 0.25/0.26 verdicts, evidence files and input hashes are unchanged. Any device reading that is not actually taken is `NotMeasured`, never "pass".

## Review Focus

These are the failure modes most likely to bite a user; each gets a test in the task that owns the code:

1. **Content leaks into logs/evidence** — a synthetic notification title/screen text/clipboard string must produce `0` hits in logcat/evidence; logs carry only counts/ids/hashes/coverage.
2. **Missing source rendered as empty** — revoked notification access, no media session, no calendar permission, background-restricted clipboard, unbound a11y must each say `unavailable(reason)`, never "there is nothing".
3. **Stale ref silently clicks an old node** — refs older than the TTL, from a previous snapshot, or from a changed foreground package/activity return `STALE_REF` plus a fresh snapshot; they never resolve to a new node.
4. **Perception changes rewrite the cache prefix** — two requests in one session with different time/foreground/media/perception must keep `systemText` and history prefix hash identical and change only the tail.
5. **HARD trim silently drops perception/memory/skill** — on overflow the dynamic tail is truncated per source with a visible `truncated` marker (and, if still over, cleaned with a recorded origin), not dropped whole without a trace.
6. **Vision overclaims** — vision off/unsupported returns `VISION_DISABLED`/`VISION_UNAVAILABLE`; no text guess is presented as a screenshot.

    private val notifications: NotificationContentSource,
    private val calendar: CalendarSource,
    private val media: MediaSessionSource,
    private val deviceState: DeviceStateProvider,

- `beginTurn()`: `accessibility.observe(ScreenFilter.ALL)` (wrapped; on failure snapshot has `screen=unavailable(reason)` but still returns other sources), `registry.beginSnapshot(UUID, now, foreground.packageName, foreground.activity)`, build and cache the initial snapshot. Screen dimensions come from `deviceState.profile().screenWidthPx/screenHeightPx` (a platform fact, not a guess).
- `snapshot(include, filter, limit)`: rebuild from cached observation + live notifications/media/device/calendar/clipboard/acoustic/glasses, filter elements by `PerceptionFilter` (`INTERACTIVE` = actions or interaction states; `TEXT` = text/description/hint; `ALL` = all visible). Always drop `visibleToUser=false`, zero-size, duplicate, and systemui/status/nav-bar nodes; never drop messages, mail, web or input-box text. Cap at `min(limit ?: policy.elementLimit, policy.elementLimit)`, and mark `truncated` when the cap or the observation was truncated.
