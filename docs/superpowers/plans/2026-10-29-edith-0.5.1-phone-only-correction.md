# EDITH 0.5.1 纯手机模式更正实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按已批准的 [0.5.1 更正 spec](../specs/2026-10-29-edith-0.5.1-phone-only-correction-design.md) 修复 0.5 交付的 13 个 Important、业主四项更正、气泡最多 2 条/整泡透明度、AI 屏幕提示词；用 TDD、独立复审、全量 JVM 和 K40/眼镜验证恢复可信交付。

**Architecture:** 先把 TTS echo 的所有权/关闭路径修好，再移除 120s 看门狗；把「回答后续聊」与「queued utterance」拆成两个 seam；听写按 owner 隔离；气泡栈改为 2 条并让整泡（卡片+文字）统一 alpha；overlay 增加权限撤销/运行状态/启动失败可见；Agent prompt 增加 phone-only 的 EDITH overlay 归属说明；共享探针回退、证据 append-only、独立复审后收口。

**Tech Stack:** Android/Kotlin、Jetpack Compose Material3、`TYPE_APPLICATION_OVERLAY` + `specialUse` 前台服务、`android.speech.tts`、JUnit 4/JUnit 5、Gradle 9.4.1、K40 API 33。

**Spec:** `docs/superpowers/specs/2026-10-29-edith-0.5.1-phone-only-correction-design.md`

## Review Focus

以下五类输入/失败模式最容易在真实使用中咬人；每个都在对应任务里有测试，另在 T12 设备验证：

1. **composer 听写进行中长按球**：球被 Busy 拒绝后松手不得停掉 composer 的 lease，也不得吞掉 composer 的 final/草稿（T3）。
2. **回答仍在朗读时长按球**：必须停止当前朗读、清除 echo 窗口并进入 BALL 听写，不能 `NoSpeech`/被回声静音吞掉（T2/T3）。
3. **TTS 丢失结束回调 + 看门狗已删**：手动 BALL 开始、关闭朗读、停止会话、player close/cancel 都能清 echo；不得永久静音；`open()` 不得用 `Long.MAX` 推算式溢出（T1/T2）。
4. **纯手机模式 vs 眼镜/queued**：回答后无 10s 续聊、初始化 10s 仍在、queued utterance 与眼镜 `continueDialogue=true` 行为不变（T5）。
5. **运行中撤销 overlay 权限 / service 启动失败**：窗口/服务停止，设置页显示真实运行状态，不再只看 `canDrawOverlays`（T8）。
6. **Agent 屏幕读取里出现 EDITH overlay**：整泡半透明 + phone-only prompt 说明归属；AI 行为不保证，验收记录实际表现（T6/T9/T12）。
