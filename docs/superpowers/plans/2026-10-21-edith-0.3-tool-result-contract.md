# EDITH 0.3 Phase 2.2 — Tool Result Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make every tool result — success, failure, timeout, uncertain, throw, partial, refusal — carry enough structured execution facts and post-call observation (text + optional compressed image) for the model to decide what to do next.

**Architecture:** A canonical `{execution, observation|null, data}` envelope replaces the per-tool detail string on the model-facing tool output. `ActionResult`/`ToolResult` gain structured execution/observation fields; `ToolRegistry`/`AgentLoop` fill timeout/throw/refusal cases through an injected `ToolObservationSource`; `device/open/shell/dial` best-effort observe after every screen attempt; `notify_user/load_skill` carry only execution facts. Images continue over `ToolResult.images`/`ImageRef`; observation content remains non-persistent (C2).

**Tech Stack:** Kotlin, kotlinx.serialization JSON, existing `PluginApi`/`agent-runtime`/`model-runtime`/Android accessibility + perception provider.

**Spec:** `docs/superpowers/specs/2026-10-21-edith-0.3-tool-result-contract-design.md`

## Global Constraints

- Envelope exactly `{execution, observation|null, data}`; `data` holds tool-specific output; no observation duplication.
- `execution.applied/verified/changed` are `true|false|null`; null means unknown. Never use false for unknown.
- `device/open/shell/dial` are screen tools; `notify_user/load_skill` have `observation=null`.
- Image policy: screen read/write results (observe/act/scroll/open, including failure/timeout/uncertain/alreadyForeground) best-effort attach; `device.status/wait` success text-only (`vision=not_requested`), failure image; pure argument rejection observation-text only; `open list`/unknown action no image.
- Uncertain: best-effort observation with a short bounded deadline (proposed 250 ms); `uncertain=true`, `applied=null`, `changed=null`; never present a mid-flight frame as stable.
- No `next=retry/reobserve/...` hints; facts only.
- `observation`/`data` content is non-persistent: no `ConversationStore`/`AgentRun.transcript`/log/evidence content; C2 redaction extends to all observation-bearing tools.
- `ImageBudget.UNITS_PER_IMAGE=1024` and `TurnTrimmer.IMAGE_KEEP=3` semantics unchanged; failure images count and may be elided.
- No new dependency; no Phase 3/4; old 0.21/0.25/0.26 verdicts unchanged; no push/tag/merge.
- Full JVM gate command:
  ```powershell
  .\gradlew.bat --rerun-tasks :common:contracts:plugin-api:test :phone-app:assistant:host-runtime:test :phone-app:assistant:device-control:test :phone-app:assistant:agent-runtime:test :phone-app:assistant:model-runtime:test :common:presentation:output-runtime:test :phone-app:plugins:plugin-smart-helper:test :phone-app:app:testDebugUnitTest
  ```

## Review Focus

- **Timeout/uncertain observation race:** a still-running tool may change the screen while observation is taken; tests must pin `uncertain=true`, `applied/changed=null`, and no false stable claim.
- **Success envelope migration:** every tool success shape changes; tests/prompt goldens must prove no duplicate observation or lost tool-specific data.
- **Pure tools:** `notify_user`/`load_skill` must return `observation=null` and execution facts, never a fake screen.
- **C2/privacy:** observation screen/notifications/clipboard/calendar/shell output must not reach store/transcript/logs; redaction must survive the envelope.
- **Screen-tool boundary:** `open list`/unknown action and pure arg rejection must not silently gain expensive captures; `shell/dial` must have a real observation source, not a fabricated one.

**Interfaces:**
- Produces:
  ```kotlin
  enum class ToolOutcome { Done, Refused, Failed, Timeout, Uncertain, Cancelled }
  enum class ToolVision { Ok, Disabled, Unavailable, NotRequested }
  data class ToolExecution(
      val outcome: ToolOutcome,
      val code: String? = null,
      val message: String? = null,
      val recoverable: Boolean = false,
      val accepted: Boolean? = null,
      val applied: Boolean? = null,
      val verified: Boolean? = null,
      val changed: Boolean? = null,
      val uncertain: Boolean = false,
      val partial: Boolean = false,
  )
  data class ToolObservation(
      val snapshotId: String? = null,
      val capturedAtEpochMillis: Long? = null,
      val foregroundPackage: String? = null,
      val foregroundActivity: String? = null,
      val rootPackage: String? = null,
      val coverage: String? = null,
      val screen: String? = null,
      val truncated: Boolean = false,
      val vision: ToolVision = ToolVision.NotRequested,
      val visionReason: String? = null,
  )
  object ToolResultEnvelope {
      fun encode(execution: ToolExecution, observation: ToolObservation?, data: String): String
  }
  ```
- Produces: `ToolResultEnvelope.encode(...)` emits stable JSON with keys `execution`, `observation`, `data`; `data` is parsed as JSON when possible, otherwise a JSON string; absent observation is `null`.
- `ToolExecution.accepted/applied/verified/changed` null must be emitted as JSON `null`, not omitted.

### Task 3: Timeout, Uncertain, Throw, Policy/Confirmation Enrichment

**Files:**
- Create: `phone-app/assistant/agent-runtime/src/main/kotlin/com/sheen/rokid/agent/ToolObservationSource.kt`
- Modify: `common/contracts/plugin-api/src/main/kotlin/com/sheen/rokid/plugin/Actions.kt` (`ActionDescriptor.screenObservation: Boolean = false`)
- Modify: `AgentLoop.kt` (`AgentRunRequest`, `runTool`, policy/confirmation paths)
- Modify: `ToolRegistry.kt` (`TOOL_THREW` path)
- Test: `AgentLoopTest.kt`, `ToolRegistryTest.kt`

**Interfaces:**
- `ActionDescriptor` adds `val screenObservation: Boolean = false`; only `device/open/shell/dial` set it true (Tasks 4-6); plugin tools keep false.
- `fun interface ToolObservationSource { fun observe(deadlineMillis: Long): ToolObservation? }`.
- `AgentRunRequest` adds `val observationSource: ToolObservationSource? = null`.
- On any non-done result for a descriptor with `screenObservation=true`, if the result has no observation, AgentLoop calls `observe(250)`; null/throw => `ToolObservation(vision=ToolVision.Unavailable, visionReason="no_source"|"observation_timeout")`, never a silent null. Pure tools (`screenObservation=false`) keep `observation=null`.
- Timeout confirmed → `ToolOutcome.Timeout`, `uncertain=false`; uncertain → `ToolOutcome.Uncertain`, `uncertain=true`, `applied=null`, `changed=null`; both try `observe(250)`.
- **Screen tools never silently return `observation=null`**: if the source is missing/unavailable or times out, synthesize `ToolObservation(vision=ToolVision.Unavailable, visionReason="no_source"|"observation_timeout")`; only pure tools (notify/load) use null observation. A null observation is reserved for non-screen tools or "not attempted" (document which).
- `TOOL_THREW` → `ToolOutcome.Uncertain` (or Failed+uncertain per spec; choose `Uncertain`), observation best-effort (Unavailable+reason if no source); no "no change" claim.
- Policy/confirmation refusal → accepted=false, applied=false, observation best-effort for screen tools; no image unless screen-failure policy.
- Cancellation: no model continuation; execution fact still represented in the result object if returned.
