# EDITH 0.3 Phase 4B — 权限、确认与“不拦截” Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 `maxLevel` 改为自动执行上限、实现全局持久“不拦截”模式、把确认交互做到不必进入 Edith，并修 shell 分类器；JVM 与 K40 设备矩阵按 spec 验收。

**Architecture:** `WhitelistActionPolicy` 增加 `PolicyMode`/live `noInterception` provider；`NORMAL` 下 >上限改 `RequireConfirmation`，L3/L4 仍必确认；`NO_INTERCEPTION` 恒 `Allow`、跳过 shell precheck。`SmartSettings` 持久化开关，宿主 live gate 注入插件；`ConfirmationPresenter` 增加可用性与眼镜开面板/重发；通知/语音/弹窗按优先级降级。

**Tech Stack:** Kotlin / Gradle / JUnit 4 / Android confirmation surfaces；设备阶段依赖 K40。

**Spec:** [2026-10-22-edith-0.3-phase-4-tool-face-and-permission-design.md](../../superpowers/specs/2026-10-22-edith-0.3-phase-4-tool-face-and-permission-design.md)

## Global Constraints

- 不重做 Phase 3；不改 0.21/0.25/0.26/Phase 3 旧判词；`Partial`/`NotMeasured` 不读成通过。
- 不 push / 不 tag / 不 merge；提交信息按 `feat(...)`/`docs(...)`。
- `noInterception`：全局、持久、默认 `false`；开启后 L0–L4 全部不确认并绕过 `maxLevel`；App 关闭/被杀/重启不重置，只有显式关闭才退出；保留审计/STOP/状态提示。
- `NORMAL`：`maxLevel` 是自动执行上限；>上限→`RequireConfirmation`；L3/L4 恒 `RequireConfirmation`；无可用通道→拒绝。
- 确认交互：眼镜自动开面板 + ENTER/BACK > 通知 action > 语音精确词 > Edith 弹窗兜底；不能出现“只能进 Edith”。
- 120 s（D47）只在确实需要确认时适用；不拦截模式不产生确认。
- 无新依赖、无 CXR wire 变化、无新权限；日志/证据零正文，只记计数/原因。
- 设备操作默认不执行；需业主授权后另行执行；`adb -s 2696813b`、禁用 `gradlew installDebug`、UI 只用 `edith.phone.a11yprobe`；设备证据必须声明 build/APK hash。
- 全量 JVM gate（八模块，同一命令，`--rerun-tasks`；计数只从 JUnit XML）：
  `.\gradlew :common:contracts:plugin-api:test :phone-app:assistant:host-runtime:test :phone-app:assistant:device-control:test :phone-app:assistant:agent-runtime:test :phone-app:assistant:model-runtime:test :common:presentation:output-runtime:test :phone-app:plugins:plugin-smart-helper:test :phone-app:app:testDebugUnitTest --rerun-tasks`
- 依赖：Task B8/B9 的 24 工具设备矩阵与延迟矩阵要求 Plan 4A 已完成；B1–B7 可在 4A 之前/并行，但 B8/B9 必须等 4A 的 24 工具与 `P4_TOOL` 解析器落地。

## Review Focus

1. **不拦截的持久/live 语义**：开关只在内存生效、App 重启回退、或回合中途改变已快照规则 —— 用户会以为已关闭/已开启；由 Task B2/B3 的 store/gate/decide 测试钉住。
2. **L3/L4 边界**：普通模式必须确认；不拦截模式必须 0 确认且绕过上限；由 Task B1/B3/B6 测试钉住。
3. **无可用确认通道**：present 恒成功导致只能 120 s 超时；由 Task B4 的 `available()`/AgentLoop 拒绝测试钉住。
4. **眼镜面板重开清空**：`PANEL_OPEN` → `resetForOpen` 清掉确认，顺序错误导致按键失效；由 Task B4 的 presenter/panel 测试钉住。
5. **shell 分类器反转**：`cmd package list packages` 误报、`pm disable`/`settings put`/`am force-stop` 静默放行；由 Task B6 测试钉住。

## 完成标准（Plan 4B）

- 普通模式：L3/L4 100% 确认；>上限确认；无通道拒绝；非 Edith 通道 allow/deny。
- 不拦截：L0–L4 0 确认、绕过上限、App 重启/force-stop 后保持、审计/STOP；关闭恢复。
- shell：良性命令不误报、高危命令确认、未知 fail-closed。
- 设备未授权/不可达的行一律 `NotMeasured`，不读成通过；旧判词不改。
