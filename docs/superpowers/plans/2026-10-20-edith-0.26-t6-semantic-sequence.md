# EDITH 0.26 T6 replacement — HTTP semantic ordered sequence

Owner decision (2026-10-20): **the old T6 `VISUAL-CANVAS` is replaced for 0.26.** It must no longer depend on opening a
local `/sdcard/.../canvas.html` file. The property to preserve is **strict ordered clicking**, not local-file or
canvas-coordinate capability.

Status: proposed replacement, not yet accepted as a PASS. The 0.25 frozen 27-row T6 remains historical and unchanged.

## Corpus

| 项 | 0.26 replacement |
|---|---|
| Setup | Debug-only loopback server on the phone (`T6PageServer`, debug source set), page `http://127.0.0.1:8765/`; a11y + Shizuku; no target app foreground |
| 问句 | “打开 http://127.0.0.1:8765/ ，按页面提示依次点击三次，完成红、绿、蓝的顺序即可。” |
| 页面 | One semantic **next-step** button whose label advances `第1步：红 → 第2步：绿 → 第3步：蓝 → 已完成`; a visible `sequence=...` status |
| 顺序规则 | Only the displayed next step advances; after the third click the page shows `EDITH_SEQUENCE_OK`; no submit is required |
| 通过判据 | (a) browser package is foreground and the page URL/status is visible; (b) after three next-step clicks the page shows `EDITH_SEQUENCE_OK`; (c) a negative run that skips a step cannot show the marker (pages expose only the next step); (d) no local `file://` is used |
| 上限 | provisional 14 calls / 14 steps / 120 s; not calibrated |
| 证据 | `page-opened` screenshot, final marker screenshot/tree, `P3_TOOLARG` tool shapes, `P3_TOOL` outcomes, `P3_TURN end` |

## Current diagnostic

- The debug page server returns HTTP 200 from the device (`GET /`).
- Production `open` accepts the URL, opens `com.android.browser`, and the page screenshot is
  `assets/2026-10-20-0.26-t6-semantic/page-opened.png`.
- The browser accessibility tree exposes `红/绿/蓝/提交` as `android.widget.Button` with `clickable=true`.
- A first real-model injection opened the page and called `device.observe`/`device.act`, but the model picked a
  non-clickable ref (`NODE_NOT_CLICKABLE`) and the page stayed `sequence=empty`
  (`assets/2026-10-20-0.26-t6-semantic/model-empty-sequence.png`). This is a **model ref-selection failure**, not a
  page/server failure.
- Therefore the replacement corpus is implemented but **not yet passing**; the next work is to make the model select
  the semantic button refs (or add a narrow deterministic direct-click helper for this test) and to run the three
  positive/negative rounds.
