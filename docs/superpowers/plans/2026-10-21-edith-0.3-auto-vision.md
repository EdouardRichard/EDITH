# EDITH 0.3 Auto Vision on Screen Operations + Screenshot Compression — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Return an aspect-preserved, compressed screenshot from every screen operation (`device.observe` with screen, `device.act` including `scroll_to_text`, and a verified `open`), then rerun the Phase 2 T7/T6 corpus and record the real effect.

**Architecture:** Capture stays on the existing `PerceptionProvider.screenshot()` → `ImageRef` → `ActionResult.images` → `ToolOutput.images` path. `DeviceTool`/`OpenTool` attach one image per result; `AndroidPerceptionProvider` gates by user vision setting **and** the selected profile's `IMAGE` capability. Compression happens once in `EdithAccessibilityService.screenshot()` using a pure, JVM-tested sizing function and built-in JPEG encoding. No new Gradle dependency and no image-budget change in this round.

**Tech Stack:** Kotlin, Android `Bitmap.createScaledBitmap`/`Bitmap.compress(JPEG)`, JUnit, existing accessibility/kernel/artifact-store path.

**Spec:** `docs/superpowers/specs/2026-10-21-edith-0.3-auto-vision-design.md`

## Global Constraints

- Scope: `device.observe` only when `include` contains `screen`; `device.act` including `scroll_to_text` and stale/refused acts; `open` only when `verified=true`. **No auto image** for `device.status`/`device.wait`.
- Compression: preserve native aspect ratio; `scale = min(1, 720/w, 1600/h)`; no crop, no upscale; JPEG quality 80; width/height/mime updated on `ImageRef`.
- **No new Gradle dependency**; no WebP/libwebp/Coil/Glide in this round.
- Gate: user `visionEnabled` **and** selected profile `inputs` contains `IMAGE`; otherwise no automatic capture, with `vision=disabled` or `vision=unavailable(no_image_profile)`. Explicit `device.screenshot` stays on its existing user-gated path; its profile-no-IMAGE residual is recorded, not fixed in this plan.
- `ImageBudget.UNITS_PER_IMAGE=1024` and `TurnTrimmer.IMAGE_KEEP=3` stay unchanged; measure whether they limit T7/T6.
- Images stay request-scoped: existing `nonPersistent`/C2 redaction keeps them out of `AgentRun.transcript` and `ConversationStore`; no image content in logcat/evidence/docs.
- No new upload consent; D53 ("session running = allowed") is unchanged.
- Only T7 and T6 are rerun; **do not rerun the 0.25 frozen 27-row corpus**, do not change old verdicts.
- Device rules: explicit `adb -s 2696813b`; never `gradlew installDebug`; no `adb shell input tap/text`; use `edith.phone.a11yprobe` for UI; read/append/verify a11y settings.
- Do not push/tag/merge; no Phase 3/4 work.
- Full JVM gate command:
  ```powershell
  .\gradlew.bat --rerun-tasks :common:contracts:plugin-api:test :phone-app:assistant:host-runtime:test :phone-app:assistant:device-control:test :phone-app:assistant:agent-runtime:test :phone-app:assistant:model-runtime:test :common:presentation:output-runtime:test :phone-app:plugins:plugin-smart-helper:test :phone-app:app:testDebugUnitTest
  ```

## Review Focus

- **No-IMAGE profile / vision off with every operation trying to capture:** no image may reach the request and no `CapabilityGate` failure; the tool result stays successful with a `vision` reason.
- **Screenshot failure/timeout:** the underlying observe/act/open outcome must not change; no stale image, no exception, explicit `vision=unavailable(reason)`.
- **Unusual aspect ratios and small screens:** no distortion/crop/upscale; output width≤720, long edge≤1600; tiny screens unchanged.
- **Repeated operations and image pressure:** one image per result, `scroll_to_text` one final image, no duplicate; newest images retained and older elided without breaking the request.
- **T6 cold start / page server:** no “page seen” or T6 pass claim when the page never loaded; T7 no pass without the correct track and `playing=true`.
