### 0.2 状态映射与路由隔离（P3/P4）

- `listeningVisible = busy && !live && route == WAKE && lastRole != USER`。
- `thinkingVisible = busy && !live && (route == PROACTIVE || lastRole == USER)`。
- `orbState`：`live → ANSWERING`；否则 listening → `LISTENING`；否则 thinking → `THINKING`；否则 `IDLE`。
- **本计划细化**：`busy` 取**当前显示路由自己的忙碌电平**（`BusyState.isBusy(order.selected(), now)`），不是 `any`：观看 WAKE 时不应因 PROACTIVE 在跑而显示聆听/思考（U8 单路由隔离）。左下提示与 BACK 语义仍取 `busyState.any(now)`（任何一路在工作都允许双击打断）。
- `lastRole` 取 `log.entries(order.selected()).lastOrNull()?.role`。

### 0.3 P4 ticker / 钉住 / 翻页（在 §5.2 内细化）

- ticker：`ValueAnimator` 每帧 +1 px，前 3 帧跳过；`offsetAfterFrames` 纯函数；到 `maxScroll`、钉住、`onPause`/`onDestroy` 停止。
- 新条目：**无论是否钉住**，先 `scrollTo` 新条目顶部（保证新答案可见）；未钉住才启动 ticker。新条目到达清除“用户手动翻页后暂停”标记。
- 用户手动翻页：停 ticker 并标记“本轮已读”；**下一条新内容到达才恢复**（官方 `isAutoScroll=false` 语义），不自动续滚抢读。
- 钉住：`ENTER` 切换；钉住停 ticker；取消钉住从当前位置恢复。新条目在钉住时只做首次定位，不连续滚。
- 四向键：`DPAD_DOWN/RIGHT` 向下翻页、`DPAD_UP/LEFT` 向上翻页；步长 `min(剩余, 视口×0.85)`；翻页前停 ticker；只处理 `ACTION_DOWN` 并消费。
- 窗口清空：新 `HELLO`（不同 session/generation）与 `onDestroy` 清空两条路由、回 WAKE、清 pin；`SHOW`/`SAID` 不清另一条路由；手机 `ConversationLog` 不变（D130）。

### 0.4 P5 BACK 的拦截点（实现细化）

- 官方在 `Dialog.onKeyUp` 处理 `KEYCODE_BACK`；EDITH 是普通 `Activity`，**`addOnUnhandledKeyEventListener` 收不到被 Activity 默认消费的 BACK**（DPAD/ENTER 能收到，BACK 会走 `onBackPressed`）。
- 因此：**BACK 在 `GlassesActivity.onKeyUp` 处理并返回 true**（仅这一处产生语义）；DPAD/ENTER 仍走 `installSideTouch` 的 unhandled listener。设备证据必须证明忙碌 BACK 不退出、空闲 BACK 退出。
- 忙碌且 `controller.currentIdentity()` 非空 → 发 `STOP`，不退出；忙碌但无身份 → 按“无会话”直接退出（§5.3.1）；空闲 → 退出。
- 仅处理一次：`ACTION_UP` 时判定；不重复触发 `finish()`。

### 0.5 P5 STOP 范围（业主确认 1，D145）

- `HintCommand.Stop(sessionId, generation)`：`wireVersion=1`、字段顺序 `wireVersion,command,sessionId,generation`、无 sequence/ACK、重复幂等、旧解码器 null。
- `CxrHintLink.onInbound`：校验已建立的 session+generation；匹配 → `onStopRequest()` 回调并返回 true；不匹配 → 诊断 `stop refused` 并返回 false；不抛到 SDK 线程。
- `HostCompositionRoot.requestStop()`：与 `requestHelp()` 同构；无活动会话返回 false；日志 `P3_CXR stop result=accepted|no_session`。
- `SmartAssistantPlugin.stopAll()`：
  - 现有：取消 wake turn、标记 proactive hint cancelled、`wakeBusy=false`、`detach`；
  - 新增：锁内 `proactiveInFlight=false`；**锁外对被取消的主动提示调用 `cancelOutputTurn(session, generation, hint.turnId)`**（停播+撤屏，D145）；随后 `publishBusy()` 立即广播 `BUSY=false`；
  - 迟到的主动结果仍由 `hint.cancelled` 丢弃；`OutputArbiter.cancelTurn` 的 `Rejected` 事件不得重新点亮。
- 眼镜收到 `BUSY=false`：思考/聆听/球回空闲，ticker 对应状态继续按现有规则（不影响已读内容）。

### 0.6 P5 唤醒证据方法（业主确认 3）

- 删除 `WakeAcknowledgement`（固定短语「在的」）与 `speakWakeAcknowledgement` 调用；`wakeEmit` 不再构造 `Assistance`/不写 `ConversationLog`。
- `WakeChime`：`DEBOUNCE_MILLIS=800`；`onWake(nowNanos, enabled)`；`play(nowNanos, enabled, sink)`；去抖按 monotonic nanos；sink 异常不传播。
- `ToneWakeChimeSink`：`ToneGenerator(AudioManager.STREAM_MUSIC, 80)` + `TONE_PROP_BEEP` 120 ms；`close()` release；播放结果记 `P5_CHIME state=played|debounced|disabled|failed`（只记状态）。
- 开关：唤醒时读 `speechOn.value`（「语音朗读」）；关闭不响；开启时即使 TTS 引擎缺失短提示音仍可响；开关说明改为「唤醒后的短提示音也受这个开关控制」。
- 设备证据：`DebugAudioInjector` 注入 `唤醒词-中文.wav` → 生产 KWS → `wakeEmit`；logcat 断言 `P5_CHIME state=played`、无 `P5_SPEECH`/「在的」；800 ms 内二次注入记录 `debounced`；关闭开关再注入记录 `disabled`。真实声学耦合与可听性 `NotMeasured`。

### 0.7 CXR 与设备边界（业主确认 4）

- 先尝试自动建立：手机授权页/信任/麦克风用 `edith.phone.a11yprobe` 处理；成功则做 STOP 跨设备因果（眼镜 BACK → 手机 `P3_CXR stop accepted` → 眼镜 `BUSY=false`）。
- 失败：P3/P4 的眼镜截图为 `Verified (Device)`（眼镜本地）；U-9 的跨设备因果、U-10 的声学唤醒与可听性 `NotMeasured`，不得用两端单端日志凑 device-pass。
- 眼镜 instrumentation 通过 `am instrument` 手动运行（不是 `connectedDebugAndroidTest`；后者会动手机 provision）；只在眼镜上安装 `app-debug` 与 `app-debug-androidTest`。
