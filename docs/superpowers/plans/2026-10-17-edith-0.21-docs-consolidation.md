# EDITH 0.21 文档基线重构实施计划

> **状态**：已执行完毕（2026-10-17）。本文件是过程记录，不是当前架构或当前计划；当前架构见 `docs/superpowers/specs/2026-10-17-edith-0.21-baseline-architecture-design.md`。

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 0.21 代码锚点上产出一套 5 份入口的权威文档，删除失效决策与旧文档，并在业主确认后清理约 12 GB 临时数据；全程零代码改动。

**Architecture:** 先做只读盘查（决策引用图、文档链接图、证据映射、代码引用图），产出逐项处置表并经业主确认；再按"代码是事实、生效决策是理由"起草基线架构规格与四份登记；最后过校验门、删旧文档、清理临时文件。中间产物只写 `.local/docs-consolidation/`，不进入仓库。

**Tech Stack:** Markdown、Git、PowerShell 7（只读盘查与校验脚本）、现有 JUnit XML（仅作基线引用，不重跑）。

**Spec:** `docs/superpowers/specs/2026-10-17-edith-0.21-docs-consolidation-design.md`

## Global Constraints

- **零代码改动**：`*.kt`、`*.kts`、`*.xml`、资源、Manifest、测试、构建脚本一律不改。以 Task 1 记录的全量代码文件 SHA-256 为基线；Task 14 必须逐字节一致。
- **不提交、不 push、不合并、不打 tag**：所有改动留在工作树供业主审阅。提交授权不继承。
- **锚点**：0.21，代码/工具基线 `f0eab5f`，结项标识 `edith-0.21-closed-20261017-01`。
- **统一判词**：`0.21 范围内未完全通过 / 不满足完整交付标准`。`STATUS.md` 与 `ACCEPTANCE.md` 必须逐字一致，不得软化为"通过"。
- **决策底线**：代码/测试引用的 ID（D33、D35、D41、D46、D47、D49、D53、D57、D60、D73）必须存在于活动登记，且与实际代码一致。
- **证据不可改写**：`docs/project/evidence/` 只做保留/删除，不改测量内容与数字。
- **临时文件**：按规格 §9.3 的"建议删除"类全删；§9.1/§9.2 的保留项一律不删。删除前逐路径清单展示。
- **语言**：权威文档用中文；代码标识符、路径、命令保持原样。
- **权威文档总大小目标**：5 份入口合计 < 200 KB（当前四份合计约 1.49 MB）。

## Review Focus

这五类失败最可能骗过"看起来完成"的检查，每个都由指定任务的步骤钉住：

1. **被删决策仍被代码引用** → Task 2 建引用图，Task 6 校验；代码引用的 10 个 ID 缺失即失败。
2. **旧架构口径从 `AGENTS.md` / `README.md` 回流**（蓝图、PROJECT_STATE、HANDOFF、旧上传同意、两插件范围、K70 目标）→ Task 10 逐词 grep，命中即失败。
3. **验收行丢证据仍写成通过** → Task 3 建映射，Task 8 链接校验；缺失证据的行必须降为 `NotMeasured`。
4. **临时清理误删构建/测试资产**（`probes/p0/vendor`、`audio-android/libs`、`.local/signing`、`.local/p3-kws-model`、`.local/models/embeddinggemma`）→ Task 13 保护清单 + 删除前后存在性检查。
5. **"0.21 未通过"被写成"通过"** → Task 8/9 判词逐字比对，Task 11 再查一次。
