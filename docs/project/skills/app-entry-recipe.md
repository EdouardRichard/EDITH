# 应用入口配方（模板）

## 这个示例是什么

这是一个**发现与验证应用入口的流程模板**，不是某个具体 App 的配方。它**没有在 K40 上验证过**，
正文里的配方字段也还没有填成实测值。直接把它当成可用配方执行，不会让你更快地打开任何应用，
还可能让你猜出一个错误的包名或 URI。

使用前必须用目标设备上实测通过的**具体配方**替换「配方字段」一节，并确认替换后的每一步都能
通过成功判据。替换完成之前，只能把本文件当作流程检查表：要进入应用内具体页面时，按「没有已验证
入口时」的 UI 路径执行，或者直接询问用户。不要声称这个模板已经可用，也不要把字段里的填写说明
当成真实的包名、URI 或参数。

## 使用顺序

1. **先查 SKILL 目录。** 系统提示里如果有 SKILL 目录段，先看有没有更匹配本任务的技能；有就先
   用 `load_skill` 读取它的正文，按它的步骤执行。本模板只在没有更具体配方时作为流程参考。
2. **确认配方已经替换。** 只有本文件的配方字段已经被替换成**已在目标设备验证过**的值，才可以
   使用 `deep_link`；没有替换就走 UI 路径，不要拿占位说明去试。
3. **核对字段齐全。** 本次任务需要的包名、URI、参数、成功判据缺一个，就先向用户问清楚，
   不要用看起来合理的值补齐。

## 配方字段（替换为实测值）

下表是模板要填的字段。把「填写要求」整段替换成实测值；没有实测值就写「未验证」，
不要填写猜测值。

| 字段 | 填写要求 |
| --- | --- |
| 目标应用包名 | 在目标设备上实测确认的包名，不能从应用名推断 |
| 入口类型 | 应用内页面、媒体会话、或只能走 UI |
| 深链 URI | 实测通过、且本次任务确定要用的 URI；没有就写「未验证」 |
| URI 参数 | 允许的取值和来源（用户话语还是已验证模板） |
| 成功判据 | 前台包名、页面标题或关键控件中至少一项可观测特征 |
| UI 兜底路径 | 从桌面或当前界面到目标页面的点击顺序 |
| 替代入口 | 另一个已验证入口；没有就写「无」 |

字段没有填完时不要调用 `deep_link`；需要用户决定填什么时，用 `notify_user` 带上
`awaiting_reply=true` 提问，然后结束本回合等回答。

## 选择入口

- **有已验证深链，且本次参数能确定**：用 `deep_link`，同时给出 `package` 和 `uri`。
  URI 只能来自本文件已验证的配方、用户明确给出的值，或工具返回的可证实候选；
  其余来源一律不用。自定义 scheme 的深链**必须**带 `package`；拿不到包名就不调用。
- **没有已验证深链，或参数不确定**：先用 `read_screen` 观察当前界面，再用 `tap`、
  `long_press`、`input_text`、`scroll` 一步步进入。这是默认路径，不是失败后的补救。
- **控制已有播放会话**：用 `media`；有多个会话而用户没有指定包名时，不要替用户选，
  先问清楚。
- **HTTP(S) 链接**：只有当用户明确给出、或已验证配方里写明时才用；不要自己拼。

## 不要这样做

- 不要自己拼接、补全或猜测 URI 与包名，也不要把用户说的应用名直接当包名。
- 不要使用本文件里的填写说明当值，也不要用从网上抄来、没在目标设备验证过的 scheme。
- 不要为了进入页面用 `shell` 模拟点击、输入或绕过锁屏。
- 不要在第一次没打开时重复同一个调用；同一个入口连续失败两次就换策略或问用户。
- 不要在没验证的情况下向用户说「已经打开了」「已经进入页面了」。

## 有交易后果的入口

支付、下单、改单、订单状态变化等会扣款或改变订单状态的页面，按「安全与确认」一节的
必确认集合处理：先说明将要打开什么、会有什么后果，得到用户确认后再打开；打开后仍要
按成功判据验证页面确实到了预期位置。用户拒绝或犹豫时停止这个入口，改为说明可选方案。

## 每一步都要验证

每次动作后用 `read_screen`、`device` 或工具返回的 observation 核对：前台包名、页面标题
或关键控件是否出现。没有变化就是没有成功，不要因为调用返回成功就宣称完成。

界面变化或滚动之后重新读屏；`index`/`ref` 只来自最近一次读取结果，不要复用旧引用。
收到 `STALE_REF` 就重新观察当前界面，不要用同一个引用再点一次。

## 入口找不到时的回退

按顺序尝试，每一步之后都验证界面：

1. 返回上一级，重新观察当前界面；
2. 用 `open` 给出候选让用户选择；
3. 用 `list_apps` 核对目标应用是否已安装、包名是什么；
4. 请用户指路，或如实说明无法进入该页面。

不要在同一个错误界面上反复点，也不要擅自换成一个没有被要求的目标。

## 验证状态

- 本文件是模板：**未在 K40 验证**，正文不含可直接执行的配方。
- 替换成具体配方后，必须在目标设备上实测包名、URI、成功判据都成立，才能记录为已验证；
  没有实测就如实记为未测量，不要写成可用。
