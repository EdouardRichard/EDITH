before the model request, by the perception snapshot + memory injection + prompt build:

| Run | gate → `P3_PROMPT` | `P3_HTTP` duration | model latency | silence at |
|---|---:|---:|---:|---:|
| G-P1 | 5.306 s | 461 ms | 1826 ms | 7422 ms (`NO_CALL`) |
| G-P2 | 6.616 s | 217 ms | 1031 ms | 8015 ms (`DEADLINE`) |
| G-P3 | 6.936 s | 242 ms | 751 ms | 8016 ms (`DEADLINE`) |

In two of three runs the model's response landed at/after the 8 s deadline, producing `DEADLINE`; in
the third it arrived in budget but was a text-only reply (`toolCalls=0`, 7 output tokens), which the
pinned design treats as silence. This is a latency/design boundary of the proactive hint turn on the
K40, not a production fix in this task; Task 12/final review should triage whether the 8 s budget must
exclude the pre-model snapshot. It is not claimed as a bug fix here and no production code was changed.
