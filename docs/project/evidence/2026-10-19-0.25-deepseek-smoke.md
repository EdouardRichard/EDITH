# 0.25 Task 14 — DeepSeek smoke evidence

- 日期：2026-10-19
- 分支 / 起点：`main` @ `a0493ae`（`docs(0.25): close task 13 and point handoff at task 14`）
- 目标：R79 — 用真实 DeepSeek 档案走**生产 consent/gate 路径**做两次 smoke（Responses：user 图片 + `function_call_output` 图片；Chat Completions：tool 文本 + 随后 user 图片 workaround，含 blank output + image），并记录 HTTP 状态、usage、图片是否被 provider 读到。
- 结论：**NotMeasured**（本地 key 被 provider 以 HTTP 401 拒绝；没有取得 200、没有模型回答、没有图片被读到的证据）。

## 环境与凭证

| 项 | 值 |
|---|---|
| Provider / base URL | `https://api.deepseek.com` |
| 模型 | `deepseek-flash` |
| 协议 | `DEEPSEEK_RESPONSES`、`OPENAI_CHAT_COMPLETIONS` |
| 档案 | 运行时合成的 `smoke-deepseek_responses` / `smoke-openai_chat_completions`（IMAGE+TEXT 输入、TEXT 输出、当前 revision 的 `TEXT_REQUEST`/`IMAGE_REQUEST` 由探针写入） |
| 凭证来源 | 仓库根目录本地、gitignored 的 `api_key.yaml`，由 `EDITH_SMOKE_KEYFILE` 路径传入测试进程；**未打印、未写入本文件、未入库** |
| 设备档案 | 不可用：本次任务禁止设备/ADB 操作，无法读取 on-device profile/credential |
| 运行时 | JVM（Gradle `:phone-app:app:testDebugUnitTest`，JDK 21），非设备 |

## 方法（生产路径，非测试专用宽松 seam）

临时 app 单测 harness（运行后已删除，未入库）：

1. `MemoryProfileRepository` + `MemorySecretResolver` 保存一个 IMAGE+TEXT 的 DeepSeek 档案（协议、model、base URL 见上表）；
2. `ProfileProbeGate.grant(...)` 后经 `ProfileProbeGate.test/testImage` → `ControlledProfileTester.testText/testImage` → `ControlledModelClient.probe`（`CapabilityGate(probe = true)`）发送固定合成文本探针与固定 32×32 PNG 图片探针；
3. 普通请求经 `ControlledModelClient.request` → `CapabilityGate(probe = false)`，consent 来自 `HostCompositionRoot.consentSource(ProfileProbeGate::requestConsent)`（生产合并：`text` 由运行中的会话给，`image` 由 profile 声明决定）；
4. 用 OkHttp interceptor **只记录响应状态码**（不读/不记 body），只累计 `TextDelta` 与 `Terminal.usage`/`safeCode`；不输出 key、prompt、response body。

## 结果

| 协议 | 文本探针 | 图片探针 | 普通请求（验证后） | 依据 |
|---|---|---|---|---|
| `DEEPSEEK_RESPONSES` | `FAILED / HTTP_AUTH`，HTTP 401 | `FAILED / HTTP_AUTH`，HTTP 401 | 未发送；`CapabilityMissing`（gate 拒绝） | TEXT_REQUEST=Failed，IMAGE_REQUEST=Failed |
| `OPENAI_CHAT_COMPLETIONS` | `FAILED / HTTP_AUTH`，HTTP 401 | `FAILED / HTTP_AUTH`，HTTP 401 | 未发送；`CapabilityMissing`（gate 拒绝） | TEXT_REQUEST=Failed，IMAGE_REQUEST=Failed |

失败链条：

- 两个协议、两次探针均收到 **HTTP 401**（`ControlledModelClient` 映射为 `HTTP_AUTH`），因此 `TEXT_REQUEST` / `IMAGE_REQUEST` 均记录为 `Failed`；
- 生产 `CapabilityGate` 随后拒绝同一 revision 的普通图片请求（`CapabilityMissing`），**请求未发出**——这证明 R76/R77 的门控在真实档案上生效，但不是 smoke 的成功证据；
- 由于探针失败，R79 的两条 wire shape（Responses `function_call_output` 图片；Chat tool 文本 + 后续 user 图片，blank output + image）**没有进入网络**。两者的 200/4xx 与图片可读性均为 **NotMeasured**。

## 未测项（如实记录，不写成通过）

- Responses：`function_call_output.output` 含 `input_image` 的 provider 接受性、user 图片、usage、图片被读到——**NotMeasured**。
- Chat Completions：tool 文本 + user 图片 workaround、blank tool output + image 的接受性、usage、图片被读到——**NotMeasured**。
- 真实 provider 的 HTTP 200、模型回显/答案、`input_tokens`/`output_tokens`——**NotMeasured**（未产生任何数字）。
- 请求形状本身由 `CapabilityGateImageTest` / `ProfileImageGateTest` / 既有 adapter 测试在 JVM 覆盖；它们不能替代真实 provider smoke。

## 为什么是 NotMeasured 而不是 FAIL/PASS

- 401 是凭证不可用（本地 key 被拒绝），不是 wire shape 错误；按 R79“没有可用 key/网络/额度 → NotMeasured，不得写成通过”。
- 没有发生 200，也没有模型回答或 `usage`，因此不能声称图片被 provider 读到；不引用未产生的数字。
- 未改用宽松 consent/gate seam、未伪造响应、未写入 key 或正文。
