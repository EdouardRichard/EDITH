## Final whole-branch fix — auto gate requires current-revision `IMAGE_REQUEST=Verified` (JVM only)

**Finding (Important I2).** `autoVisionProfileSupportsImage` checked only `ModelProfile.inputs.contains(IMAGE)`.
`CapabilityGate` instead admits an image only when the profile's latest `IMAGE_REQUEST` verification **for the same
profile revision** is `Verified`. A profile that declares `IMAGE` but has not passed the image probe could start a
text session; the first automatic image would then throw `ContractError.CapabilityMissing` and end the whole turn.

**Fix (no device build/install/run, no new dependency, no `ImageBudget`/`IMAGE_KEEP` change).**

- `AutoVisionProfile.kt`: the gate now requires both the declared `IMAGE` input and the latest current-revision
  `IMAGE_REQUEST=Verified` verification, using `CapabilityGate`'s selection rule (same `profileRevision` and
  `operation`, max `testedAtEpochMillis`, list index as the tie-break). Old revision, failed, unverified or absent
  records read `false`; null/throw still fail closed.
- `AndroidPerceptionProvider.profileSupportsImage` defaults to `{ false }` (an unwired provider never captures); the
  production composition still passes the resolver.
- `DeviceTool.captureVision()` wraps the provider's `screenshot()` in `runCatching`; a throw degrades the marker to
  `unavailable(SCREENSHOT_FAILED)` instead of failing the observe/act.
- Cheap minor: the unused `OpenTool.done(..., nonPersistent)` parameter is removed (behavior unchanged:
  `nonPersistent = images.isNotEmpty()`).
