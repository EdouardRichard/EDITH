## 2. 悬浮窗服务与权限

- 授予 `SYSTEM_ALERT_WINDOW`：`adb shell appops set com.sheen.rokid.phone SYSTEM_ALERT_WINDOW allow`。
- 启动 App 后（模式已在 0.4 的设置中为 on，`P4_DETACH state=on effective_proactive=false audio=phone_mic`）：
  - `P4_DETACH state=on effective_proactive=false audio=phone_mic`
  - `P5_PHONE_ONLY state=on`
  - `dumpsys activity services`：`ServiceRecord{.../.overlay.PhoneOnlyOverlayService}`，`startForegroundCount=1`（API 33 上 `specialUse` 清单类型 + 无类型 `startForeground` 路径可用）。
  - `dumpsys window windows`：两个 `com.sheen.rokid.phone` 的 `appop=SYSTEM_ALERT_WINDOW` 窗口（一个悬浮球小窗、一个全屏不可触气泡窗）。
- 冷启动/灭屏后唤醒：服务保持；截图见 [ball](0.5/2026-10-29-0.5-ball.png)。
- **模式切换（本轮设备发现并修复）**：`DebugDetachControl --ez on false` → `P5_PHONE_ONLY state=off`、overlay 窗口消失；`--ez on true` → **无需重启** `P5_PHONE_ONLY state=on`、球窗口 `(942,1284)(277x277)` 回来。
  - 修复前：gate 在 `enabled` 仍为旧值的时刻回调 `onDetachModeChanged` → `sync` 读 gate 得到 `false`，开启切换反而把服务停掉（首次启动因 `onResume` 读到时已为 true 而正常）。现在 `sync` 接收**请求值** `requestedEnabled`，服务 `onCreate` 时 gate 已更新；`onResume` 仍读 gate。设备日志：`P4_DETACH_DEBUG requested=true saved=true ... live=true` → `P5_PHONE_ONLY state=on`。
- **未测**：API 34 的 `FOREGROUND_SERVICE_TYPE_SPECIAL_USE` 类型、权限被拒/运行中撤销、进程被杀后恢复、旋转/分屏。服务是 `START_NOT_STICKY`，按设计不自动复活。

## 3. 悬浮球

- 外观：EDITH 启动器前景图（`R.mipmap.ic_launcher_foreground`）+ 白色圆形底，右边缘**半隐藏**停靠；半径 28dp、透明度默认 82%；绿色思考光影环由 `BallHalo` 驱动。
- 真实触摸（a11y 探针坐标臂，K40 1080×2400，悬浮球可见半区约 x=1050/y=1500）：
  - `A1CLICK_AT x=1050 y=1500 screenW=1080 screenH=2400 inScreen=true dialogBounds=none outsideDialog=none dispatched=true completed=true outcome=clicked`
  - `P5_BALL event=tap`（生产 `openApp` 路径）
- 截图：[ball](0.5/2026-10-29-0.5-ball.png)（球 + 半隐藏 + 白色圆底 + EDITH 头像）。
- **长按（本轮新增探针能力，已验证）**：给 `A11yClickActivity` 坐标臂加了 `holdMillis`（长按）与 `x2/y2`（拖动）参数，用同一个 `dispatchGesture` 注入真实触摸；探针用**已安装 APK 的 glasses debug 签名**重建，避免卸载共享仪器。
  - 有会话：`A1GESTURE_AT mode=hold ... dispatched=true completed=true` → `P5_BALL event=long_press edge=RIGHT` → `P4_DICTATION state=started chars=0 reason=user`；松手 `P4_DICTATION state=stopped`、`P5_BALL event=snap edge=RIGHT`、`event=long_press_end`。长按 → 生产手机麦听写的链路已实测（真实语音内容未注入，`chars=0`）。
  - 无会话：`P4_DICTATION state=refused chars=0 reason=no_session` → `P5_BUBBLE event=Notice route=WAKE visible=1` + `P5_BALL event=dictation_refused reason=NoSession`；截图 [no-session notice](0.5/2026-10-29-0.5-ball-no-session.png)（点球后的提示气泡）。
- **拖拽/吸附（短路径已验证）**：`A1GESTURE_AT mode=drag x=1050 y=1423 x2=980 y2=1423 holdMillis=600 dispatched=true completed=true` → `P5_BALL event=drag` 多次（x 从 1050 递减到 968）→ 松手 `P5_BALL event=snap edge=RIGHT x=1080 y=1423`（吸附右边缘、半隐藏）。说明生产 Compose 手势机、拖动窗口跟随与吸附链路在真实注入触摸下工作。
- **边界**：更长的探针路径（x2=200，终点在小球窗口外）同款注入 accepted/completed，但生产球未收到 `event=drag`（探针的手势目标/路径限制）；真实手指拖动时窗口随手指移动，未做长距离设备读数，记为 NM。点击球打开 App 的前台切换未单独读 `mResumedActivity`（截图时 App 已在前台；`P5_BALL event=tap` 是触摸链路证据）。

## 5. 语音朗读

### 5.1 运行期开关（无需重启）

```
P5_TTS state=off
P5_SPEECH_TOGGLE enabled=false speech=false
P5_TTS state=on player=created
P5_SPEECH_TOGGLE enabled=true speech=true
```

- `setSpeechEnabled` 现在创建/安装/释放 player 并同步 `speechPlayerHolder`/`SpeechPlayerRouter`/`SpeechOutput` 能力；关闭时停止当前朗读。无需重启。
- **未测**：引擎缺失（`player=unavailable`）路径、TTS 引擎切换/语言不支持、耳机/蓝牙路由。

### 5.2 最终回答被朗读（纯手机模型）

- 真实回合的最终回答：`P5_SPEECH state=start hintId=... chars=15` → `P5_SPEECH state=end`（约 3.7s）。
- 眼镜模式**保持 0.4**：最终回答仍只上 HUD，不额外朗读；`notify_user(voice/both)` 仍按原规则朗读。本轮已做眼镜模式日志级回归，见 5.4；`SmartAssistantPluginTest`/`NotifyFallbackTest` 在眼镜模式默认值下全绿。

### 5.3 回声半双工（本轮设备发现并修复）

- **修复前**（同一次真实回合，TTS 开启）：
  - `P5_SPEECH state=start ... chars=13` 于 12:22:27.471；
  - 播放期间 `P3_ASR revision=2/3 final=false`（12:22:29.97/30.29），`P3_ASR revision=4 final=true`（12:22:30.66），紧接着 `P3_CONV continue` + 新回合自答；
  - 即手机麦听到了回答自己的声音，ASR 把它当成用户句，持续对话路径继续自答——形成回声循环。
- **修复**：`AndroidSpeechPlayer` 对每次 `play` 在 `onStart` 打开 `EchoMuteWindow`、在 `onDone/onError/cancel` 关闭（原先只有脱离唤醒应答「我在」打开）；窗口内麦克风帧换零，ASR/VAD/KWS 不收回声。看门狗从 5s 放宽到 120s（与 `SpeechFinished` 活性上界一致），避免长回答播到一半解除静音。
- **修复后**（最终行为）：
  - 注入 `hello`：唯一 ASR final 是注入的 5 字符用户句；
  - `P5_SPEECH state=start/end` 完整播放；
  - 播放区间及结束后**没有**新的 `P3_ASR final=true` 自听转写；`P3_CONV continue` 仍会开下一听的窗口，但没有用户句就没有自答。
- **未测**：>5s 的长回答（源码已放宽到 120s 但未实测）、强噪声/免提外放音量变化、AEC 方案（本轮是半双工静音，不是回声消除）。

### 5.4 眼镜模式回归（本轮）

- `DebugDetachControl --ez on false`：`P4_DETACH_LINK state=reattached`、`P4_DETACH state=off ... audio=cxr`、`P5_PHONE_ONLY state=off`；`dumpsys window` 只剩 MainActivity，截图 [glasses mode](0.5/2026-10-29-0.5-glasses-mode.png)（无球、无气泡）。
- 启动会话：`P4_AUDIO state=armed source=cxr`，眼镜音频流建立；注入 `hello`（route=wake）：
  - `EdithHint: outbound: Answer`（流式）→ `EdithHint: outbound: Show sequence=1 syncId=... ttl=4998ms hintId=...` → `EdithHint: inbound: Ack` → `UI_CLOSED`；
  - `P3_CONV answer route=WAKE chars=15`，`P3_TURN end outcome=COMPLETED`；
  - **没有 `P5_SPEECH`**（最终回答未朗读）。
- 即眼镜模式保持 0.4 的 HUD-only 最终回答；眼镜屏幕本身未重新截图（0.4 的 D3/D7 设备判词保留）。
- 重新开启纯手机模型后：`P4_DETACH state=on ... live=true`、`P5_PHONE_ONLY state=on`、球窗口回来；截图 [final overlay](0.5/2026-10-29-0.5-overlay-final.png)。
