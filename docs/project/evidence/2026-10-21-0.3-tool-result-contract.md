## Observation refresh / 250 ms latency — NotMeasured

- `P3_METRIC observeMs` (`5806` for T7, `4689` for T6) is only a run-level subset of tool time for
  descriptors that declare the fingerprint `observation=true`; it is not a per-call 2.2 observation
  refresh time. The device kernel's `data.timing.observeMs` covers only `device` calls.
- There is **no per-call timing instrumentation** for `open`/`shell` observation refresh, so their
  refresh latency is **NotMeasured**.
- The loop passes `250` ms to `ToolObservationSource`, but the production
  `PerceptionObservationSource` is cache-only and documents the deadline as **advisory, not
  enforced** (it runs on the calling thread and cannot preempt a slow platform read). No measured
  duration exists, so 250 ms compliance is **NotMeasured**, not met.
- Loop-level timeout/throw images are **NotMeasured**: `ToolObservation` has no `ImageRef` channel;
  the observation carries screen text/vision reason only, and no loop-level failure image is claimed.
- `P3_METRIC images` means **distinct images produced by this run's tool calls, including images a
  terminal run never carried**; images merely carried in from previous-turn history are not counted.
  It is not a per-call image attribution.
