## Why the corpus turn could not open it

The frozen T6 setup places the page at:

```text
/sdcard/Download/edith-corpus/canvas.html
```

and the frozen question is “打开测试页，把画布上的三个颜色都点一遍，然后提交。” It gives no URL. The production `open`
tool accepts only `http(s)` URLs and the settings-page allowlist; `file://` and bare local paths are rejected as
`INVALID_URL` before any launch. There is no local HTTP server in the harness either.

Therefore the corpus asks the model to open a page whose only known form is a local file, while the product has no
supported local-page path. This is a **corpus/product capability mismatch** (P7), not an input-hash issue and not a
silent execution block. The page and gesture capability are proven; the missing piece is a product decision:

1. add a narrow local-page open path (with a strict allowlist/root), or
2. keep HTTP-only and change the T6 criterion to an HTTP page + semantic controls, or
3. serve the corpus page over localhost HTTP before the turn.

Option 2/3 would change the frozen T6 criterion or setup and therefore needs the owner's explicit decision. No
screenshot/gesture result here is promoted to T6 PASS.
