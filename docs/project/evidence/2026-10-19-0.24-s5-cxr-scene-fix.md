## 13. 后续修复（2026-10-19 09:37–10:00）——透明 scene 真正不遮挡 launcher

- **基线**：`main` @ `b4c089d`（上一节的透明 scene 提交）。
- **提交**：`fix(0.24-S5): keep the CXR scene invisible over the launcher`（产品代码 + androidTest + 本文件与截图同提交；commit only）。
- **触发**：上一节 §7/§10 如实记录的限制——scene window 自身 `fmt=TRANSLUCENT` 且只画 1×1 透明内容，但**整个 ActivityRecord 仍被系统当作全屏不透明**，面板隐藏时合成结果是黑屏、下面 launcher 被 stop，而不是透出。本任务要求：默认生产 scene 保持 RESUMED 与 `onGlassAppResume=true`，但面板隐藏时 launcher/上一个 app 必须可见；不得改 debug `EXTRA_HOST_PANEL` 的既有 host。

### 13.1 根因（实测，不是猜测）

在**修复前 APK（`b4c089d`）**上直接启动生产默认 `GlassesActivity`（先 force-stop，`adb -s 1901092544027662 shell am start -n com.sheen.rokid.glasses/.app.GlassesActivity`），唤醒屏幕后读平台状态：

```text
* Task{d74f7b8 #2718 type=standard A=10080:com.sheen.rokid.glasses ... translucent=false}
topResumedActivity=ActivityRecord{f7ed58 u0 com.sheen.rokid.glasses/.app.GlassesActivity t2718}
* Task{69895d8 #99 type=home A=1000:com.rokid.os.sprite.launcher ... visible=false visibleRequested=false}
mTopFullscreenOpaqueWindowState=Window{8245859 u0 com.sheen.rokid.glasses/...GlassesActivity}
```

同一时刻整屏截图全黑（`.local/task21followup/before-black*.png`，2595 B，全像素黑）。结论：`Window.setFormat(PixelFormat.TRANSLUCENT)` 只改**窗口表面**；ActivityManager 在**进程启动前**从 ActivityInfo 的 theme 读 `android:windowIsTranslucent` 来决定 ActivityRecord 是否透明、下层 activity 是否保留可见。`Theme.Material.NoActionBar` 没有该属性 ⇒ `translucent=false` ⇒ launcher 被置为 `visibleRequested=false` ⇒ 黑屏。因此修复必须落在 **manifest/theme**，运行期改 flag 不够。

修复前设备测试（同一失败断言，RED）见 §13.3：`windowIsTranslucent` 读回 `false`、launcher 中央文字带非黑像素 `0`（需 ≥800）。
