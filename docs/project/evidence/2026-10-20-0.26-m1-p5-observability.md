## M1 — privacy-safe argument shape

`ToolCatalog.execute` now emits one `P3_TOOLARG` line before any channel/unlock decision:

- `device`: action, kind, filter, `hasRef`, `textChars`;
- `shell`: a fixed command class (`input`/`activity`/`package`/`settings`/`diagnostics`/`window`/`identity`/`other`),
  character count, `hasStdin`, timeout;
- `open`: `shape=list` or target class (`http`/`https`/`package`/`label`) + character count + relaunch;
- `dial`: `hasNumber` + digit count.

The raw ref/text, command, URL/package and number are never formatted. `ToolArgsShapeTest` covers both the useful
fields and the absence of the raw values; the unknown/malformed cases are bounded to `tool=unknown` or
`shape=invalid`.

## P5 — catalogue summary fields

`OpenTool(list=true)` now returns:

```json
{"catalogVia":"launcher|packages","catalogCount":N,"hasPlayer":true|false,"hasSettings":true|false}
```

and logs one count-only line `P3_TOOLCATALOG via=... count=... hasPlayer=... hasSettings=... truncated=...`.
`catalogVia` records which catalogue source answered; `catalogCount` is the pre-cap package count; the two booleans
are derived from package/label shape, not from reading the catalogue body. The app rows/text remain in the tool result
only.

Device readback (production `open(list)` through a debug Activity):

```text
P3_TOOLARG tool=open shape=list
P3_TOOLCATALOG via=launcher count=30 hasPlayer=true hasSettings=true truncated=false
P3_OPENLIST outcome=Done
```

The device count is 30 on this run; it is not hardcoded.
