
### 2.2 听写结果

由探针点输入行麦克风（`P3_A1CLICK_VERDICT … labels=开始语音输入 … clicked=true`），随后经 `DebugWakeAudioPlayer` 播放 `question-zh.wav`（147,200 B，4.61 s，手机扬声器，`streamVolume=150`）：

```text
P4_DICTATION state=started chars=0 reason=user                (23:55:21.728)
P4_WAKE_AUDIO state=playing file=question-zh.wav bytes=147200 chunks=230 sampleRateHz=16000 streamVolume=150
P4_DICTATION state=final chars=16 reason=endpoint             (23:55:26.863)
P3_A1TEXT_VERDICT op=read … target=first_editable … len=16 chars=16 sha=a766e05b…  (23:55:29.543)
```

- **判词：听写转写 Verified（合成 TTS）**。`final chars=16 reason=endpoint`，输入框回读 `len=16`（与 final 一致，SHA `a766e05b7bee5116f4fa63f03c7fb8cf1a7ce1d42d76ca4b42d7272da6e8c8c9`）；本次听写 **没有** `timeout chars=0`。
- **fix1 触发条件实测**：听写期间暂停的 CXR ingress 仍被 transport 持续 offer，实测出现 **两次 `EdithAudio: OFFER:OVERFLOW`**（23:55:23.747、23:55:25.768）——这正是 fix1 要隔离的“dictation 期间 CXR offer outcome”路径。整段窗口 **没有** `INGRESS_OVERFLOW`、`GAP:`、`UNKNOWN_FORMAT` 或任何 dictation fault/revoke 行；听写 loop 的 `P3_FRAME frames=247 bytes=158080 accepted=247 overflow=0 unknownFormat=0 gaps=0`。即 overflow outcome 仍到达诊断，但没有重建/重置共享 framer，final 未被截断。
- **CXR 不重启**：`P3_CXR_AUDIO callbacks=1500→1750→2000→2250→…→4000`（bytes 960,000→2,560,000）贯穿听写前、中、后；捕获窗口内无 `P3_CXR connect`/`stop`/`disconnect`，眼镜端仅 1 次 `Hello accepted` + 1 次 `UI_READY`（听写后无第二次握手）；会话结束回读 `P4_SESSION_READBACK session=Ready error=none`。说明：CXR 链路在捕获窗口开始前已建立，因此“未重连”以“无第二次 connect/Hello + 同一会话 callbacks 连续增长”为据。
- **无自动发送**：窗口内 `P4_TYPED=0`、`P3_TURN start=0`、`P3_CONV said=0`、`P3_WAKE=0`、`P3_PROACTIVE=0`；听写后 UI 会话区仍为「暂无记录」（0 行）。截图 `k40-06-d10-fix1-dictation-final.png`。
