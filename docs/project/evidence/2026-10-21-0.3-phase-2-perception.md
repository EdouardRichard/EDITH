## Final whole-branch fix round (2026-10-21, JVM-only)

The final whole-branch review found 2 Critical + 5 Important. The code fix is commit
**`68b547e5`**; the docs (this file, `CONTRACTS.md`, `DECISIONS.md` D184(h)–(j), `ACCEPTANCE.md`
§2.9, `STATUS.md`) are the accompanying docs commit. **No device turn was rerun and no APK was
rebuilt/installed:** every device row above is still the `d4a749e0`-build reading, and the device-side
verification of C1/C2/I3/I4 is `NotMeasured` (JVM only).

- **C1 — cache served as fresh.** `PerceptionProvider.refresh()` is a real read (observe → new
  `snapshotId` → `beginSnapshot` → `assign` → build/cache, no turn reset); the default keeps old
  providers compiling without refreshing, and `AndroidPerceptionProvider` overrides it. `device.observe`
  calls `refresh()` before projecting `include`/`filter`/`limit`, and the `STALE_REF` answer uses
  `refresh()` (not `afterAction()`), so a manual screen change cannot be served as the old screen.
  JVM: `refreshObservesTheScreenAndOpensANewSnapshotWhileSnapshotStaysCached`,
  `observe with perception refreshes the cached observation before projecting`,
  `act with a stale ref refuses with STALE_REF…`.
- **C2 — perception content persisted via tool results.** `ActionResult.nonPersistent` (plugin-api,
  default `false`) marks perception-bearing results; `DeviceTool.observe`/`status`/`act` (including the
  stale answer) set it. `AgentLoop` keeps the full payload for the in-run model requests but stores a
  safe marker `(perception content not persisted)` with empty images in `AgentRun.transcript`; the
  plugin's `ConversationStore` path stores that redacted form. JVM: `AgentLoopTest` sentinel test and
  `TurnTranscriptRecordTest` production-store test (model sees the sentinel, store/transcript do not).
- **I3 — failed producer reported as `empty`.** `NotificationRead(items, available)`; a throwing
  producer with a live grant is `notifications=unavailable(provider)`, a missing grant stays
  `unavailable(no_access)`. JVM: `NotificationContentSourceTest` read test,
  `AndroidPerceptionProviderTest` coverage-token tests.
- **I4 — summary request had no `P3_CACHE`.** `ModelSummarizer`'s gateway now passes `P3Log::line`, so a
  summary with usage reports `P3_CACHE`; a summary has no assembled frame and therefore no `P3_PROMPT`
  (documented asymmetry). JVM: `ModelSummarizerTest` "a summary request reports its own P3_CACHE line…".
- **I5 — proactive perception.** **Deferred, not implemented.** `runProactive` calls
  `actions().beginTurn()` only; it does not open the perception boundary and emits no `P3_PERCEPTION`.
  Spec §7.5's proactive-turn full snapshot is `NotMeasured` / deferred to Phase 3, and no document
  claims it is met.
- **I6 — P-02 wording.** Criterion changed to: a new snapshot is opened; old refs fail when the node is
  absent or its identity changed; surviving nodes are re-stamped and may resolve. Device TTL/stale
  remains `NotMeasured`.
- **I7 — `P3_PERCEPTION images`.** Narrowed to "images carried by the perception block; Phase 2 blocks
  carry none (0)"; screenshot/tool images are counted by `P3_METRIC images=`, which is where the T6
  `images=2` reading belongs. No per-block count is invented.
- **Minors.** HARD head/tail cuts are code-point safe (`a character cut never splits a surrogate
  pair`); the T4 blind-answer wording is "not fully observable from the harness screenshot (tail
  visible)". Recorded deferred (not reworked): `enabled=false` renders as `null` because
