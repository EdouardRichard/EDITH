## 已能归因的失败

### T2 — 输入前置/状态，不是“模型不会调 shell”

实际截图显示点“开始”后抽屉仍覆盖助手页（`t2-drawer-open.png`）。关闭抽屉、每轮冷启动后，三轮均
`COMPLETED`、亮度 1/mode 0、无关设置 hash 不变。产品已修：开始回调自动收起抽屉。**0.25 的 T2 失败至少有一部分
来自输入前置状态；但不能据此改 0.25 判词。**

### T4 — 应用目录 API

实际截图证明终态确实是 Settings；此前失败根因是 `getInstalledApplications` 在 K40 上只返回 1 个包，改成
`queryIntentActivities` 后目录 30 个。**打开设置成功，但目录汇总字段仍需逐轮读。**

### T8a — 工具定义/模型改写

0.25 没有触发歧义，主要是模型把“文件”改写成具体 app（或没调用 `open`）。在 `open` 的 target 描述加入“类别词
保持原词”后，3/3 干净轮次得到 `APP_AMBIGUOUS` 两候选且前台不变。**这是工具描述/模型路径问题，已可复现修复。**

### T6 — 语料/能力不匹配 + 模型 ref/指令

旧语料的 canvas 页本身可渲染、taps 可工作（`canvas-marker.png`），但页面只存在本地
`/sdcard/Download/.../canvas.html`，`open` 只允许 http(s)，所以不是“页面坏了”。新 HTTP 语义页已由生产
`device` 探针完成顺序点击并出现 `EDITH_SEQUENCE_OK`；真实模型有轮次完成三次点击但未提交/DEADLINE，也有轮次只
点两次。**能力已证明，模型 instruction/ref following 未通过。**

## 还没做的归因

### T1 — 已看到“打开播放器 ≠ 播放”，但未做响应语义审计

截图/日志显示模型打开 QQMusicLite，进入视频/混合页；无 `PLAYING`，artist 不可读。clickable ancestor 兜底修掉了
`NODE_NOT_CLICKABLE`，但没有产生 media key/播放。**还不能区分：模型没选播放控件、播放控件 ref 错、应用没有真正
播放、还是媒体会话未登记。**

### T3 — 缺同轮截图和 provider 细节

0.25 记录为 draft 0 行；当前只看到 `open`/device 路径和 11/8/6 steps 的日志，没有同轮 SMS 界面截图，也没有新
provider 读回。**不能判断是“没写到 provider”“写了但 provider 未刷新”“界面/权限拦截”还是“模型只打开了短信”。**

### T7 — 缺同轮截图，且回合预算先截断

0.25 dry/正式轮有 `shell` 超时和 DEADLINE；当前日志显示 T7-1/T7-3 DEADLINE、T7-2 COMPLETED 但只有 device/load
路径。**没有三副作用的同轮画面；无法区分模型规划失败、工具超时、还是产品回合预算截断。**

### T8c — 缺同轮截图，确认探针生命周期是独立问题

0.25 首次 deny 成立，第二次确认等待导致 120 s 超时；当前没有同轮截图或第二次确认的完整审计。**不能判断模型是
“被拒绝后重试”还是“计划没有取消”；M2 的探针一次性也会影响证据。**
