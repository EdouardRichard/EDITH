## 2. 聚合方法（JUnit XML）

从仓库根递归收集 `*/build/test-results/**/TEST-*.xml`，**排除** `probes/` 与 `third_party/`（与 0.23 P6 口径一致），读取每个 `<testsuite tests/failures/errors/skipped>` 属性求和。聚合命令（PowerShell）：

```powershell
$files = Get-ChildItem -Path . -Recurse -Filter '*.xml' -File | Where-Object {
  $_.FullName -match '\\build\\test-results\\' -and
  $_.FullName -notmatch '\\probes\\' -and $_.FullName -notmatch '\\third_party\\' }
$rows = foreach ($f in $files) {
  try {
    [xml]$x = Get-Content -Raw -LiteralPath $f.FullName
    $s = if ($x.testSuites) { $x.testSuites.testsuite } else { $x.testsuite }
    if ($s -is [array]) { $s = $s[0] }
    [pscustomobject]@{ Name=$s.name; Tests=[int]$s.tests; Fail=[int]$s.failures
      Err=[int]$s.errors; Skip=[int]$s.skipped; File=$f.FullName }
  } catch { "UNPARSABLE: $($f.FullName)" }
}
```

结果：**314 个 XML 文件；313 个可解析 + 1 个已知不可解析**（`phone-app/app` 的 `EngineBundleProvisioningTest`，其 `skipped` 属性里带未转义的本地化文本，XML 解析器在属性处报错）。该文件头部本身可读，按文件头计入：

```text

           failures="0" errors="0" timestamp="2026-10-18T23:17:17.199Z" ...>
```

因此总计 = 313 个可解析 suite（3009 tests / 0 F / 0 E / 1 skip）+ 该 suite（7 tests / 0 F / 0 E / 1 skip）=
**314 suites / 3016 tests / 0 failures / 0 errors / 2 skipped**。
