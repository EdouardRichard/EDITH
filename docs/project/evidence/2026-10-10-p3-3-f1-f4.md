## 1. F1 —— 人时不计入回合预算（D49）

| 项 | 值 |
|---|---|
| 提问（弹窗） | `00:07:11` `P3_CONFIRM_RAISE raised=true` / `P3_CONFIRM_NOTIFY posted=true request=call_scripted_1` |
| 用户点按 | `00:09:02.837` `P3_CONFIRM request=call_scripted_1 outcome=approved source=phone` ⇒ **等待 111 s** |
| 执行 | `00:09:03.377` `P3_TOOL call=set_brightness ok=true detail=ok` |
| 回合结果 | `00:09:03.377` `P3_TURN end turn=1cf83296-… outcome=COMPLETED code=- steps=1` |
| 设备侧复核 | 屏幕亮度 **60 → 180**（目标 180） |

**对照（同一场景、同一设备、同一晚、修复前）**：23:09 答在 75 s ⇒ `P3_TOOL ok=true`（动作照旧执行）但 `P3_TURN end outcome=DEADLINE`。修复后同样"晚答"⇒ **`COMPLETED`**。

**语义**：回合预算只计**机器**时间；`confirmation.request(...)` 是 loop 里唯一花人时的地方，量测其墙钟并顺延 `turnDeadlineNanos`（`try/finally`）。档案 `timeoutMillis` 改为只限**单次模型请求**（`AgentRequest.requestTimeoutNanos`，`0` = 旧行为）。

## 2. F4 —— 连接状态只讲事实

| 时点 | 按钮名（dump 节点文本） | 状态行（dump 节点文本） |
|---|---|---|
| 会话开始、未点连接 | `连接眼镜（CXR）` | **`未连接`** |
| 点连接后 ~2 s | **`重连眼镜`** | **`已连接眼镜`** |

- 置真的唯一来源是 `HostCompositionRoot.linkReady`（`onSceneReady()`，SDK 报出活跃会话时由 transport 恰好投递一次）⇒ 从 `未连接` 翻到 `已连接眼镜` 就是该信号到达的直接见证；旧代码用的 `Capability.Audio` 由 `CxrHostEnvironment` **故意永不宣告**，那条分支在手机上不可达（这也解释了"`重连眼镜` 从不出现"这一既有现象）。
- **全程无"授权"字样**（页面其余含"授权"的节点是 `前台 App 感知授权` / `通知分类感知授权` / `日程标题感知授权` 三行**权限**入口，与连接状态无关）；「已请求连接眼镜，请在 AI App 中确认授权」已删除。
- 中间态 `已请求，等待就绪…` 因就绪在 ~2 s 内到达而未在 dump 中停留（由 `CxrLinkLabelsTest` 的四态断言覆盖；在本轮更早的构建上已真机见过该文案）。
- 授权结果行只在 SDK 真的问过（`onActivityResult` → `onCxrAuthorizationResult`）之后出现，`null` 表示"本进程没被问过"，**不**渲染成"未授权"。

## 4. 边界与未测（如实）

- **不做**：CXR SDK 调用形状、眼镜端、连接**实时心跳/掉线检测**（需 SDK 断连回调，属"照官方 demo"范围）⇒ 状态行表达的是"本进程已建立过会话"，**不是**在线状态（文案与守卫都写明不得说"在线"）。
- **未测**：`requestTimeoutNanos` 的**端到端**效果（loop 侧有单测、插件侧有 helper 单测，但没有一条"模型请求被卡住 30 s"的真机观测）；`P3.3-NM` 既有的 B 真机测量项。
