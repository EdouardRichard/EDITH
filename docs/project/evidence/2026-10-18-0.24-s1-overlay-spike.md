## 0. 装置与边界（先读）

- 手机端 **所有** UI 操作均由 `edith.phone.a11yprobe` 完成；**未使用** `input tap/text/swipe`。眼镜端按键用 `adb shell input keyevent` 注入，作为**按键链路证据**，**不是物理手感证据**。
- 悬浮窗 app-op 由 adb shell `appops set` 授予并读回（spec §10 风险 10 的可脚本性），全程未让用户点授权。
- `SpikeOverlayService` 的 manifest 前台服务类型为 `specialUse`；眼镜 Android 12 上 `startForeground` 接受该类型（`foreground=ok type=manifest(specialUse)`），**没有**触发 Task 9 预留的 fallback。
- 主动点亮使用平台 `SCREEN_BRIGHT_WAKE_LOCK | ACQUIRE_CAUSES_WAKEUP`：厂商 SDK 无主动亮屏 API（官方 FAQ 仅给 `FLAG_KEEP_SCREEN_ON`，且说明指环 `KEY_POWER` 应用层不可拦截），当前产品眼镜端也用同一机制（`2026-10-08-p2-device-closure.md` §3）。
- CXR 音频检查是**文件注入**（既有 `edith.DEBUG_INJECT` → `DebugAudioInjector`），只替换“手机扬声器 → 眼镜麦克风”的声学耦合；KWS 与唤醒投递是生产路径。它不是真实声学耦合，也不是召回率。
- 侧键的真实物理手感、佩戴可读性、功耗 **`NotMeasured`**（S5 走查项）。
