### 2.1 U-2（AI 左 / 用户右 + 角色头像）

`phone-assistant-six.png`、`phone-assistant-thirty.png`、`phone-assistant-cap41.png` 都显示：

- 助手消息为灰色 `surfaceVariant` 气泡，**左对齐**；气泡左侧为**女性面孔**（`Icons.Default.Face4`，盘发，32 dp 圆形）；
- 用户消息为紫色 `primaryContainer` 气泡，**右对齐**；气泡右侧为**人像**（`Icons.Default.Person`，32 dp 圆形）；
- 气泡内只有正文与头像，**不显示时间**，也没有额外文字角色标签；
- 气泡行的合并语义是 `spokenMessage(role, text)`（「助手说：…」/「你说：…」）；头像本身 `contentDescription = null`，避免读屏器重复播报。

JVM 侧由 `AssistantConversationTest` 的 `sideFor` / `roleDescription` / `spokenMessage` 钉住（10/10 通过）。

### 2.2 U-1（固定头/聊天框，只有列表滚动）

两组像素级对比（1080 × 2400，ARGB_8888，整图逐字节；状态栏 0–99 行不计入）：

```text

  headerRows100to760DiffBytes=0
  firstDiffAtOrBelow100=1080

cap40 vs cap41:
  headerRows100to760DiffBytes=0

```

即：**状态栏以下的固定区域（100–760 行）在两组对比中都是 0 差异字节**；第一处内容差异分别为第 1080 / 843 行（消息列表区域）。覆盖顶部 AppBar、标题「对话上下文记录」、唤醒/主动切换、只读说明、聊天框头「唤醒对话」+ 刷新图标。列表从 6 条变为 30 条、从 40 条变为 41 条（封顶后驱逐最旧一条）时，固定区域没有移动。

- 刷新图标：聊天框右上 `Icons.Default.Refresh`，`contentDescription = "刷新对话"`（`AssistantConversationTest` 钉住）；点击只 `revision++` 重读日志，不跳滚动位置（业主口径）。
- **列表滚动的触发方式**：通过 debug-only 种子追加条目，让应用自身的自动跟随路径调用 `animateScrollToItem` 造成列表滚动；**不是人手滑动**。
- **人手滑动路径**：`NotMeasured`。`edith.phone.a11yprobe` 目前没有通用的跨应用滚动意图（A1 的 scroll 场景固定打开 Settings；`A11yClickActivity` 只做点击）。按 D95 未使用 `adb shell input swipe`，也不把自动跟随写成“人手滑动已验证”。

### 2.3 40 条封顶后的跟随（Critical 修复验证）

Reviewer 指出：旧实现用“可见项索引 vs 上一轮 count”判断是否在底部；封顶后 count 不变、新条目尚未布局时会把 `atBottom` 误判为 false，导致跟随在恰好 40 条时停止。第二次复核又指出：长消息只露出下半截时“key 可见”不等于读完；动画被用户滚动取消时，滚动后的书签更新也不会执行。最终修复为 `wasAtBottom(previousLastId, visibleItems, viewportEndOffset, bottomPaddingPx)`：**上一轮最后一条的末尾已进入视口**才算读者在底部；`previousCount`/`previousLastId` 在启动滚动**之前**更新。帧序、封顶驱逐、长消息部分可见、动画取消四种情况都不再依赖“哪一帧先到”。

设备复现与验证：

```text

  -n com.sheen.rokid.phone/.debug.DebugConversationSeed --ei count 40 --ez clear true
# 截图 phone-assistant-cap40.png

adb -s 2696813b shell am broadcast -a edith.DEBUG_CONVERSATION \
  -n com.sheen.rokid.phone/.debug.DebugConversationSeed --ei count 41
# 截图 phone-assistant-cap41.png
```

logcat：

```text
10-17 23:46:07.969  I EdithP3 : P3_CONV_SEED route=WAKE count=40 total=40
10-17 23:46:12.526  I EdithP3 : P3_CONV_SEED route=WAKE count=41 total=40
```

`phone-assistant-cap41.png` 底部可见「唤醒 第 41 轮用户消息」；41 条时 `total=40`（最旧一条被驱逐），页面仍跟随到新条目。JVM 侧新增 `wasAtBottom` 五组断言（空列表、末尾可见、末尾在视口下方、已上滑、未布局）与 `shouldFollowNewEntry(null→first)`。
