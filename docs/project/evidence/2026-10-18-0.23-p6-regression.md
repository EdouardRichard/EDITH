## 2. 一次 PowerShell 5.1 编码假阳性（已更正）

P6 复核发现：最初用 `Get-Content -Raw` 读取 `phone-app/app/build/test-results/testDebugUnitTest/TEST-com.sheen.rokid.phone.EngineBundleProvisioningTest.xml` 时，`[xml]` 在 line 8 报 `org.junit.AssumptionViolatedException is an unexpected token`，当时被误写成“XML 本身无效 / 内嵌控制字符”。实际原因是 **Windows PowerShell 5.1 的 `Get-Content` 把 UTF-8 当作 ANSI 解码**，而该文件的 `<skipped message>` 含有非 ASCII 路径；用 `[System.IO.File]::ReadAllText($f, [System.Text.Encoding]::UTF8)` 读取后，整份文档可以正常解析（`tests=7 skipped=1`），**没有**控制字符。

处理：计数脚本改为显式 UTF-8 整文档解析（不再使用起始标签特判）；所有 312 份 project+third_party XML（以及 325 份含 probes 的 XML）都能解析。计数不变：**301 suites / 2597 tests / 0 failures / 0 errors / 2 skipped**。含 `third_party` 的中间读数为 2645（312 份 - 48 tests），排除后 2597；**没有任何套件被静默丢弃**。
