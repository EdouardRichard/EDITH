## 5. 验收口径与边界

- **U-9 设备半边：Verified (Device)**。忙碌 BACK → STOP → 手机取消并广播 `BUSY=false` → 眼镜回空闲且不退出；空闲 BACK → 退出。
- **物理双击手感**：`NotMeasured`（本证据是 `input keyevent 4` 注入，不是物理侧边触控）。
- **STOP 与旧 APK 混用**：本证据使用两端同一次构建；旧解码器 null 安全失败由 `HintWireCodecTest.anUnknownCommandStaysNull` 钉住，未做旧/新混用设备实验。
- **手机端主动提示的停播/撤屏**：由 `ConversationDisplayCallsTest` 的 accepted 路径 + `cancelOutputTurn` 断言钉住；主机 fake 未投递 `OutputStateEvent(Displayed)`，因此措辞是“已 accepted/可能已在屏”，不是“设备上已显示后撤屏”。本设备证据的忙碌回合是 WAKE 回合，未单独在设备上显示主动提示再打断。
- **STOP 发送失败（D151）**：忙碌+有身份但 `send=false` 时 BACK 退出窗口，`GlassesInteractionTest.aBackWhileBusyWithADeadLink...` 在设备上钉住；成功路径仍不退出。
- **手机“停止”清 busy（D152 相关）**：`host.stop()` 先于 `hintLink.sessionEnded()`，且 `sessionEnded` 在清身份前显式发两路 `BUSY=false`；`CxrHintLinkTest.endingASessionClearsBothBusyLevels...` 钉住。该路径未在设备上做“手机点停止→眼镜回 idle”的单独录像，见边界。
- **CXR 连接**：本证据期间真实连接；若后续复跑时连接不可用，U-9 跨设备半边应记 `NotMeasured`，不得沿用本读数。
- 本证据只记 session/generation、路由、布尔与状态；日志中没有用户正文。
