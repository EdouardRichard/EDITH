## 2. 复审 I-1 —— 晚答之后结果提示仍然上屏（**已修 + 真机 + 单测**）

**缺陷**：turn 的提示有效期由它自己的 deadline 派生（`SmartTurn.hintValidUntil = deadline + grace`）。D49 只把 `AgentLoop` **自己的**预算顺延了，turn 的 deadline 没动 ⇒ 晚答时回合完成、动作执行、结果句组装好后被 `emit` 的 `minOf(now + lifetime, hintValidUntil)` 判为已过期而**丢弃**：**手机动了，眼镜空白**。

**修法（加法式）**：`AgentRun` 新增 `humanWaitNanos`（默认 `0` = 旧行为；loop 每轮 run 归零、在 `confirmation.request` 的 `finally` 里累加实测墙钟），插件在提交结果前 `owned.extendDeadline(owned.deadlineNanos + run.humanWaitNanos)`（`extendDeadline` 会同时把 `hintValidUntil` 推后，且只前进不后退）。

**真机（两次独立回合，注入式提问）**：

## 3. 复审 I-3 —— 只有 transport 认领过的结果才能写成"授权答复"（**已修 + 单测**）

**缺陷**：`MainActivity.onActivityResult` 把**任何** activity result 都交给 `HostCompositionRoot.onCxrAuthorizationResult`，后者无条件把 `RESULT_OK/RESULT_CANCELED/其它` 写成"眼镜授权确认已完成/被取消/结果异常"。**可达性已实证**（`javap` 钉住 `androidx.activity:activity:1.9.2` 的 `ComponentActivity.onActivityResult`：先 `activityResultRegistry.dispatchResult(...)`，**未被注册者消费才**转 `super`）——而 `MainActivity` 自己 override 了这个方法并在里面记状态，所以**本页发起的每个 activity result 都会走到这里**，包括 App 自己 `permissions.launch(...)`（`BLUETOOTH_CONNECT/SCAN`、`POST_NOTIFICATIONS`）的权限框答复。

**修法（诚实缝）**：把"这是不是 SDK 那一问的答复"交给**唯一知道答案的一方**——transport：
`CxrBackend.onAuthorizationResult(...)` 现在返回 `Boolean`，为真**当且仅当** `connect` 武装的那个授权回调仍在（fence 未关、未被消费、`authCallback != null`）；`RokidSessionTransport` / `RokidConnection` / `CxrConnection` 逐层转达；`HostCompositionRoot` 只在 `claimed == true` 时写页面状态，否则**原样经过 transport、页面不动**。**不猜 requestCode**（铁律：SDK 的形状只能照 demo/文档，不能发明）。
- `transport-rokid`：`CxrBackendTest` 新增 2 条——`anActivityResultIsClaimedOnlyWhileAPromptIsPending`（没问过 ⇒ `false`；问过 ⇒ 恰好 `true` 一次，重复 ⇒ `false`）、`anActivityResultAfterRevocationIsNotClaimed`（`cancelAuthorization()` 后 ⇒ `false`）；为此给测试台补上 SDK 自己的 `parseAuthorizationResult` 建模（此前从没有测试走过结果路径）。
- `phone-app`：`CxrLinkWiringTest` 新增 `anActivityResultNoPromptAskedForIsNotAPageFact`（连接在线但**没有**在等授权 ⇒ 结果仍送达 transport、页面**不得**出现授权行）与 `theCompositionOwnedAuthorizationRouteIsAHonestClaimToo`（复审 Minor：第二条注入缝的 `Boolean` 契约此前**没有**任何测试用过非默认值 ⇒ 现钉住"返回 true ⇒ 页面记为 CONFIRMED"），并把原有两条改写为"transport 认领"的形态（`Rig` 现在带一个 `ClaimingConnection`）。RED：`java.lang.AssertionError at CxrLinkWiringTest.kt:101`；**变异**：把组合里的 `if (!claimed) return` 关掉 ⇒ **恰好**这条失败。
- **契约零改动**：`plugin-api` / `core-contracts` 未动；改的是 `phone-app` 内部的 `CxrConnection` 缝与 `agent-runtime` 的 `AgentLoop`/`AgentRun`（**加法式**：新增只读属性 + 带默认值字段）。

**未做（如实）**：I-3 **未做真机复现**。本轮两次设备回合里 `requestStart` 需要的权限**都已授予**（`requested` 为空 ⇒ 权限框根本没弹），所以没有触发该路径，也**没有在设备上观测到症状**；复现步骤已写下（`pm revoke` 一条运行期权限 → 开始会话 → 在权限框上作答 → 页面**不得**出现眼镜授权行），留待后续。
**连带更正**：F4 证据里"授权结果行只在 SDK 真的问过之后出现"这句话，在 I-3 修复前是**不成立**的（任何本页 activity result 都会写进去）——那次真机的**观测值**（两行文案由 dump 读出）不受影响，受影响的是那句**推断**；本轮已由代码机制更正。
