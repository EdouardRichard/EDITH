# 2026-10-20 — 0.26 T6 semantic-page replacement (not yet PASS)

Owner decision: replace the local-canvas T6 with an HTTP semantic strict-order corpus. Specification:
[`2026-10-20-edith-0.26-t6-semantic-sequence.md`](../superpowers/plans/2026-10-20-edith-0.26-t6-semantic-sequence.md).

## Implemented

- Debug-only loopback server `T6PageServer` on `127.0.0.1:8765`; release APK contains no server/page.
- Page: semantic `红`/`绿`/`蓝`/`提交` buttons; only `红→绿→蓝` advances; wrong click resets; submit after completion
  sets `EDITH_SEQUENCE_OK`.
- Device-side HTTP check: `GET / HTTP/1.1` returned `HTTP/1.1 200 OK` and the page content length.
- Production `open` target `http://127.0.0.1:8765/` returned `Done`; `topResumedActivity=com.android.browser/.BrowserActivity`.
  The actual page is `assets/2026-10-20-0.26-t6-semantic/page-opened.png`.
- `uiautomator dump` shows the four controls as `android.widget.Button` with `clickable="true"`.

## Production device sequence probe

A debug Activity finished itself, brought the browser to the front, observed through the **production** `device` tool and
clicked the refs by label:

```text
P3_T6CLICK_TEXT len=15566 hasRed=true hasButton=true
P3_T6CLICK 红=#n86:Done 绿=#n87:Done 蓝=#n88:Done 提交=#n89:Done
```

The page then showed `EDITH_SEQUENCE_OK` (`assets/2026-10-20-0.26-t6-semantic/device-sequence-ok.png`). So the loopback
page, the production `device.observe/act` and the ordered-click state machine all work. This probe is instrumentation, not
the corpus model.

## First real-model run

Injected (with the URL explicitly in the modified corpus question):

```text
P3_TOOLARG tool=open targetClass=http chars=22 ...
P3_TOOLARG tool=device action=observe kind=none filter=all
P3_TOOLARG tool=device action=act kind=tap ... hasRef=true
P3_TOOL  call=device ok=false detail=... NODE_NOT_CLICKABLE ...
P3_TURN end outcome=COMPLETED steps=5
```

The page stayed `sequence=empty` (`assets/2026-10-20-0.26-t6-semantic/model-empty-sequence.png`). This is a
**model ref-selection failure**, not a page/server/local-file failure. The replacement corpus is therefore implemented
but **not passing**; the old T6 remains historical.

A second real-model run used the more explicit question including “观察页面，按红、绿、蓝的顺序各点击一次，然后点击提交”.
The model opened the page, observed, then tried `#n86` and `#n0`; both were refused `NODE_NOT_CLICKABLE`, and the turn
ended `DEADLINE` with the page still `sequence=empty` (`model-ref-failure.png`). The production probe in the same page
proves `#n86` was a clickable red button when the browser was the active window; the model's observation/ref context was
not the same. Next step is therefore **model/tool-context guidance**, not another local-file capability.

## Ref normalization

The model was sending `n86` while the page/probe refs are `#n86`. `device.act` now accepts the bare `n<number>` form
(and leaves other values untouched); a regression test pins `ref:"n1"` → `Ref("#n1")`.

After that fix, a real-model run performed three taps and the page reached `sequence=red,green,blue` — the strict order
was actually satisfied. It then spent its remaining steps on observe/screenshot and ended `DEADLINE` without the
old explicit submit; image: `assets/2026-10-20-0.26-t6-semantic/model-three-ordered-taps.png`.

To remove the extra submit dependency from the [replacement spec](../superpowers/plans/2026-10-20-edith-0.26-t6-semantic-sequence.md),
the page now shows `EDITH_SEQUENCE_OK` automatically on the third ordered click (submit remains optional). A rerun still
failed to complete: the model clicked red and green only and stopped at `sequence=red,green`
(`assets/2026-10-20-0.26-t6-semantic/model-two-taps.png`). The new T6 remains **not passing**; the unresolved part is
model instruction/ref following, not the page or the local-file capability.

## Single next-step page

To remove the three-button selection ambiguity, the page now exposes only one semantic button whose label advances
`第1步：红 → 第2步：绿 → 第3步：蓝 → 已完成`; the third click shows `EDITH_SEQUENCE_OK`.

Round 1 of the real-model diagnostic passed:

```text
P3_TOOLARG tool=open targetClass=http chars=22
P3_TOOLARG tool=device action=observe ...
P3_TOOLARG tool=device action=act kind=tap ...  (x3)
P3_METRIC calls=6 toolCalls=5
P3_TURN end turn=debug-utterance-1 outcome=COMPLETED code=- steps=5
marker present
```

Image: `assets/2026-10-20-0.26-t6-semantic/model-single-next-pass.png`.

Rounds 2 and 3 were not stable: round 2 only called `open` and completed with no clicks; round 3 called `open` and had
no `P3_TURN end` within the observation window. Thus the new T6 is **1/3 model passes**, not a passing corpus. The
production `device` sequence probe remains 4/4 clicks + marker, so the capability is proven; the open issue is model
instruction/ref following across fresh sessions.
